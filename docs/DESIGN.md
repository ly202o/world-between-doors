## 二、视觉语言

### 2.1 色彩

全场景只有三个明度层，没有彩色：

| 层 | 值 | 用途 |
|---|---|---|
| 天 | `#FFFFFF` | 背景、天空 |
| 物体亮面 | 约 `#FAFAFA` | 受光的地面与方块顶面 |
| 物体暗面 | 约 `#CCCCCC` | 背光面、投影 |
| 人 | `#8B8F95` | 中灰白模，哑光；靠投影与分块形体从地面里分出来 |

**没有任何饱和色。** 需要区分层次时，只调明度，不加色相。

### 2.2 立体感从哪来

白色世界里没有颜色对比，形体只能靠两件事建立：

1. **方向光的明暗面差** —— 方块朝向光源的面接近纯白，背光面落到浅灰。
2. **投影** —— 长投影（约 1.5 个身位）是白色场景里最强的形状信息。

因此布光比例很关键：环境光决定投影的浅度，方向光决定面的反差。调反了整个世界会糊成一片白。

### 2.3 地平线

天和地都是白的，分界不能靠颜色差硬做。做法是：

- 天空纯白 `#FFFFFF`
- 雾色比天空**略暗**（`#F1F5F8`）
- 地表随距离渐变成雾色

于是在远处自然浮现一条极淡的分界带。**对比度必须很克制** —— 压过头就变成"灰色山脊"，失去白世界的干净。

### 2.4 形体语言

- 角色：**ALS 原版 AnimMan 网格**（10269 顶点 / 16544 面），哑光灰，无贴图。来自本地 ALS 项目的 `AnimMan.uasset`，用 UE 5.8 命令行导出 FBX 取得（见 `refs/AnimMan.fbx`）。
- **绑定方式**：刚性。FBX 的 Skin Cluster 给出顶点索引与权重，每个顶点归给主导权重的那根骨骼，按 15 个部位分组，每组挂一根 pivot。不是平滑蒙皮，所以关节处有分块接缝。
- 参考素材都存在 `refs/`：`AnimMan.fbx`（当前角色）、`SK_Mannequin.fbx`（UE4 标准）、`SKM_Manny.gltf`（UE5 标准）、`Proxy.fbx`（网络代理）。
- 世界：只有立方体。没有圆柱、没有斜面、没有曲线建筑。
- 一切边缘都是硬边，唯一柔和的是投影和雾。

### 3.35 动作系统：源自 ALS

角色动作不是凭感觉调的，而是照 [ALS-Community](https://github.com/dyanikoglu/ALS-Community) 的 C++ 实现复刻。

**核心是倾斜（Lean）**。ALS 的 `CalculateRelativeAccelerationAmount()` 把加速度按角色朝向反旋转到局部空间，再按 `MaxAcceleration` / `MaxBrakingDeceleration` 归一化到 ±1：

```
RelativeAcceleration = clamp(Acceleration / MaxAcc, -1, 1)   // 在角色局部空间
LeanAmount.FB = InterpTo(当前, RelativeAcceleration.X, dt, 4.0)   // 前后
LeanAmount.LR = InterpTo(当前, RelativeAcceleration.Y, dt, 4.0)   // 左右
```

这两个量驱动身体前后压和左右侧倾，于是起步前压、急停后仰、转弯侧倾——这是 ALS "有重量"的手感来源。

本项目对应实现：`P.leanFB` / `P.leanLR`，用 `(vel - prevVel)/dt` 取加速度，旋转到角色局部后除以 `MAX_ACC = 20` 归一化，再指数平滑。倾斜应用系数前后 0.34 rad、左右 0.26 rad。

**前提条件**：移动必须是恒定加速度。指数趋近产生的加速度是脉冲式的（速度一到位加速度就归零），倾斜来不及积累就衰减了。

### 3.351 原地转身：TurnInPlace（v0.13.2）

站定时目标朝向差出 60° 以上，播放 ALS 的 `TurnIP_L90/R90` 而不是用 lerp 拧身体。这是"有脚的人转身"和"原地滑冰"的区别。

**转角住在 root 骨里**。实测这两个片段：root 骨 yaw 从 0° 线性转到 ±90°（0.6s 到 50%、1.12s 到 99%），而骨盆、脊椎的 yaw 全程为 0——ALS 把转身角打在了骨架最顶层，不是骨盆，也不是 root motion 位移。

因此运行时分成两段：

| 阶段 | `P.face` | root 骨 | 视觉朝向 |
|---|---|---|---|
| 播放中 | 冻结 | 由动画驱动 0°→90° | `P.face + rootYaw` |
| 结算 | `+= rootYaw` | 同帧归零（`hardCut`） | `P.face` |

结算必须**同帧**完成：如果 `P.face` 加了而 root 骨还留着 90°，两者叠加就是 180°；如果保留姿态混合，root 骨会在 0.18s 里从 90° 褪回 0，看起来像"转过去又转回来"。好在转身末帧的姿态和 idle 几乎一样，硬切看不出来。

**只转到"够用"**：素材固定 90°，需求角度却是任意的。`TURN.want = min(|diff|, 90°)`，root 转到这个角度就收（`Math.abs(rootYaw) >= want - 0.03`），不会转过头再被 lerp 拉回来，那种"甩一下"很廉价。

**触发条件**（缺一不可）：站定 `sp < 0.45`、着地、非攀爬、非面板打开、冷却结束、**`faceTarget` 已稳定 0.12s**、残差 > 60°。

**和 lerp 的冲突（踩过的坑）**：站定时的朝向 lerp 是 12/s，视线停稳的那 0.12s 里它已经把角度吃掉约 76%，等转身条件成立时残差早已低于 60°，转身永远不触发。这不是参数问题，是两套机制在抢同一件事。解法是站定且视线未稳时冻结 lerp（`faceFreeze`），走路时不冻结——移动方向优先，该转就转。

**打断**：转身中途推方向键，先把当前 `rootYaw` 结算进 `P.face` 再切到移动动画，朝向不会跳。

### 3.353 头部视线跟随：Head Look（v0.13.4）

ALS 的 Rotation 体系是「下半身管移动方向，上半身和头跟视线」。这套项目里移动方向由 `P.face` 决定，视线由 `camYaw + π` 决定，两者的差就是头该转的角度。

**只动 `neck_01` + `head`，绝不动 spine**。`spine_03` 是手臂的父级——转脊柱，手臂和枪一起转，枪口立刻离开准星。这是硬约束，不是偷懒。

```
目标角 = wrap(camYaw + π − P.face)，clamp ±1.15 rad
颈 45% + 头 55%（合计 = 目标角）
9/s 指数平滑
```

分配比例的理由：只转颈像落枕，只转头像猫头鹰；45/55 让颈椎和颅骨各担一半。

**关闭条件**：攀爬、`mantle` 动画、踉跄（`stumble > 0`）、第一人称（`fpBlend ≥ 0.5`）。第一人称必须关——相机是独立于骨骼的，头转了相机不转，只会把脑袋转进镜头。

**白捡的一个正确行为**：站定时为了让枪露出来，`faceTarget = camYaw + π − 0.5`（侧身 29°）。头部跟随会自动把这 29° 转回来，于是"身体侧着、脸朝前"——正好是真实射击站姿。不需要额外写一行代码。

**顺序**：`driveAnim`（采样动画）→ `updateFootContact`（脚 IK，末尾刷新全矩阵）→ `updateLookPose`（头）。头部在最后，因为它要读最新的父级世界朝向；只刷头子树，不影响武器和脚。

### 3.352 脚部 IK：逐腿两骨解（v0.13.3）

脚贴不贴地是"人站在地上"和"模型飘在地上"的唯一区别。ALS 的素材是平地录的，`supportAt()` 只把整个身体放到中心点的支撑高度——**斜坡、台阶边缘、屋顶，脚一定是错的**。

**实测的病**：18.2° 的坡屋顶上，两脚踝高度相同（都是 4.28），但脚下坡面一个是 4.283、一个是 4.184。也就是左脚陷进去 10cm、右脚悬空 10cm。旧实现只有一层"骨盆补偿"（量到陷地就把骨盆整体抬一点），骨盆只有一个值，补好一只必然压坏另一只。

**结构**：`pelvis → thigh(0.426m) → calf(0.402m) → foot → ball`。目标 = 该脚自己脚下的支撑高度 + 踝高 `0.100m`（平地实测）。

**为什么必须分两层**：

| 落差成因 | 修法 | 原因 |
|---|---|---|
| 两脚一起浮/沉 | 骨盆竖直偏移 | 平地站立时膝角 168~171°，腿几乎伸直，**没有下探余量**；只能整体沉 |
| 两脚不一样高 | 逐腿 IK | 骨盆补不了差异；抬脚只会让腿变弯，**永远有余量** |

所以每帧两遍：第一遍量出 `wantL`/`wantR`，取最小值（限幅 −0.16~+0.08m）给骨盆；第二遍把差额 `want - pelvis` 逐腿做 IK。差额恒 ≥ 0，也就恒可解，不会把腿拉长。

**解算**（平面余弦定理，无迭代求解器）：

1. 整条腿绕髋旋转，使「髋→踝」对准「髋→目标」（`setFromUnitVectors` + 世界旋转左乘）；
2. 绕膝旋转 `Δ = ∠ABC(l) − ∠ABC(d)`，把髋→踝从当前长度收到目标长度。

膝的拐向由**身体正前方**当 pole 向量：屈膝平面 = span(髋→踝, 前方)，法线 = 两者叉积。转向 ±Δ 各算一次踝点，取离目标近的那个——不依赖骨骼局部轴定义，不可能拐反。

**两个数值坑**：

- **腿直时叉积是噪声**。最初的平面法线用 `cross(髋→踝, 髋→膝)`，站立时膝盖离连线不到 1mm，归一化得到随机方向，脚横着飞了 21cm。改用 pole 向量后与腿直不直无关。
- **单次解析解不精确**。原动画的膝盖未必落在「垂直 + 正前」平面里，一次解剩 1.8cm。改成每帧解 3 轮、每轮重新量当前踝位解剩余差额，收敛到毫米级。

**脚掌朝向独立控制**：屈膝会把小腿连脚掌一起转（左腿 167°→122° 时鞋底翻 45°，前脚掌插进屋顶 7.2cm）。位置解完后把脚掌世界朝向强行恢复为「动画原朝向 × 贴坡旋转」，`local = inv(小腿世界朝向) × 目标世界朝向`。脚姿态从此与膝盖弯曲解耦。

**贴坡**：在踝点周围打 `+0.09m` 两个差分取梯度，倾斜到地面法线（鞋底放平在坡上），上限 23°，梯度 > tan31° 当断崖不贴。走动时按 `1 - v/1.3` 衰减，否则是"粘在坡上滑步"的观感。

**改后实测**：平地双踝 0.100/0.101；坡屋顶双踝 0.099/0.099、两脚落差 0.0cm、贴坡角 18.2°（= 坡度）、鞋底穿模 −1.1cm（平地基准 −0.4cm）。

### 3.354 右侧可折叠侧栏（v0.13.5 —— **v0.16.0 已整块移除，见 3.359**）

> 下面这一节保留是为了**记住当时的判断**（为什么用整条侧栏而不是浮动卡片、`translateX(101%)` 为什么要多 1%）。代码已经不在 `world01.html` 里了。

测试清单原来是个独立的 HTML 页，后来要求"能直接显示在游戏右侧栏里"，再后来要求"不是用按钮，而是一个真正的可折叠侧边栏"。

**为什么不是浮动面板**：浮动面板是 `position: fixed` + `top: 224px` 的一块 290px 卡片。两个问题：手机上滚到列表底部就找不到关闭按钮（关闭按钮在最底下）；面板和右侧那排药丸按钮抢同一块地方。整条侧栏把这两件事一次解决——标题、进度、声音、收起全钉在顶部，列表自己在下面滚。

| 项 | 取值 | 理由 |
|---|---|---|
| 收起 | `translateX(101%)` | 多 1% 是为了把 `box-shadow` 也推出屏幕，否则右缘会留一道阴影边 |
| 展开 | `translateX(0)`，0.24s `cubic-bezier(.2,.75,.25,1)` | 用 transform 不用 width：手机上加宽会触发重排 |
| 宽度 | 330px / 手机 88vw | 88vw 是"还能看见左边场景"的上限 |
| 把手 | 右缘 26px 竖标签，`writing-mode: vertical-rl` | 常驻但不占地方；展开时 `opacity: 0` 让开 |
| 开合 | 点标签 / 「收起」 / Esc / F3 | 手机上要有可点的，桌面上要有可敲的 |

**跟设置面板的关系**：两块 UI 抢右侧同一块地方，所以互斥——`showSide(true)` 里先 `showSettings(false)`，反过来也一样。输入拦截统一收口成一个 `panelOpen()`。

**键盘不能吞**：面板打开时**仍然可以 WASD 走路**（和设置面板的既有约定一致），但侧栏里的 `<textarea>` 要能正常打字，所以 `keydown` 开头加了一道：目标元素是 `TEXTAREA / INPUT / SELECT` 就直接返回，连 `m`（显隐鼠标）都不响应。

### 3.355 默认静音（v0.13.5；四状态清单 v0.16.0 已移除）

**默认静音**：打开这个文件不该先响一声，更不该在别人电脑上突然出声。实现上不是把音量调成 0，而是**连 `AudioContext` 都不建**——静音时 `audioUnlock()` 直接 return，浏览器根本不会启动音频管线，手机上还省一份开销。选择存 `world01.sound.v1`，首次进入就把默认值落盘，不留"没写过所以不知道"的中间态。

### 3.356 侧栏是"并行"的，不是模态浮窗（v0.13.6 —— **v0.16.0 侧栏已删，判据保留**）

v0.13.5 把侧栏接进了 `panelOpen()`，等于宣布它是模态的：侧栏一开，开火、换弹、拖视角、滚轮缩放、原地转身全被拦掉。用户的反馈一句就否掉：*"我必须收起侧边栏才能继续用鼠标操作视角。"*

**判据**：一个 UI 该不该拦输入，看它是不是"要你先处理完才能继续"的东西。

| UI | 模态？ | 理由 |
|---|---|---|
| 设置面板（F2） | 是 | 你在调参数，此时拖视角只会误操作 |
| 测试清单侧栏（已删） | **否** | 它是一张边看边勾的表；恰恰要"一边操作一边勾" |

所以 `panelOpen()` 现在只等于 `settingsOpen`。`showSide()` 也不再 `exitPointerLock()`、不重置 `touch/look`——打开侧栏不许打断正在进行的拖拽。

代价：鼠标锁定时光标被捕获，点不到侧栏，得先 Esc。这是"并行"的必然取舍，比"必须收起侧栏才能动"好得多。

### 3.357 圆柱碰撞体与可站斜面（v0.13.6）

**圆柱碰撞**：树干原来是 `0.4×0.4` 的旋转矩形。方盒套圆树干，四个角会多顶出 `0.2·(√2−1) ≈ 8cm`——贴树走会被"看不见的角"磕到，这就是"碰撞太粗糙"。

新增 `addPost(x, y, z, r, h)`，标记 `round: 1`，`c: 1 / s: 0`（局部坐标等于世界坐标，于是能复用矩形分支的推出/摩擦逻辑）。`collideXZ` 里加分支：

```
dr = |P.pos − col|; need = col.hw + rBody
if (dr < need) 法线 = (P.pos − col)/dr，推出去 need
```

验证手法（可复用）：**把角色塞进碰撞体中心 ±0.03，让物理自己推出来**，量 0°/45°/90°/135° 的最终中心距。圆四向一致；方盒对角会多 ~0.06。

**可站斜面**：屋顶那套 `kind:'roof'` 碰撞体已经带斜率（`colHeight = base + rise·(1 − |x−cx|/hw)`），但它只长在 `gable()` 里。v0.13.6 把它抽出来给出生点的试脚土坡用：一个 `ExtrudeGeometry` 三角棱柱 + 一个 `roof` 碰撞体，`base=0 / rise=h`。因为走的是同一条路径，**测土坡等于测真屋顶**，这是它最大的价值——不用每次都爬上房。

实测：`4.6m 宽 / 0.85m 高` → 20.3°；站半坡双踝 0.102 / 0.101（平地基准 0.100），贴坡角 0.354 rad = 坡角。

### 3.36 动画系统：真蒙皮骨骼 + ALS 原版曲线（v0.9.1）

姿态不用 sin 函数摆，也不是部件拼接，而是**真蒙皮骨骼播放 ALS 手 K 动画**。

**为什么必须蒙皮**：v0.8 的做法是按主权重把网格切成 15 块挂到关节上（刚性绑定），骨骼一弯部件之间就露缝——腰胯鼓包、锁骨断层、脚踝脱开。蒙皮（顶点带 4 骨权重）是唯一能让关节连续变形的办法。

**角色数据**（`tools/anim/build_rig.cjs`，从 `refs/AnimMan.fbx` 提取）：

- 10269 顶点 / 16544 三角形，单 `SkinnedMesh`，不切块
- 68 根骨骼（含 clavicle、ball、neck、spine_01~03），绑定矩阵取 Cluster 的 `TransformLink`
- 每顶点最多 4 骨影响，权重归一化，0 个未分配顶点

**动画数据**（`tools/anim/bake_full.cjs`）：

- 每骨每帧**绝对局部旋转**四元数（真骨架的局部坐标系就是 FBX 骨骼坐标系，不需要 delta 共轭）
- 与绑定姿态对比：既不动又同姿态的骨不带走；静止姿势压成单帧；手指骨跳过
- 骨盆只保留上下起伏，水平位移丢弃（位移由游戏移动逻辑负责）
- 规模：25–32 骨 × 8 动画 = 404KB

**运行时结构**：

- 状态机 `idle / walk / run / sprint / 起跳 / 下落 / 落地`；落地是一次性动画，占用 0.32s 后交还状态机（见 3.38）
- 跨动画切换 0.18s 四元数 slerp 混合；未参与当前动画的骨回到绑定姿态
- 播放速率 = 实际速度 / 动画原生步速（walk 1.5 / run 3.5 / sprint 6.0，v0.11.6 校准到 ALS 源码基准 150/350/600 cm/s；填错了就是匀速滑步）
- 冲刺（v0.11.5）：目标速度 4.5 → 6.5；键盘 `Shift` 按住、手机快跑按钮（v0.11.6，触屏设备显示的切换按钮）。v0.11.7 删掉了推满自动冲刺——两个入口并存时按钮形同虚设。进 sprint 动画需要速度先过 4.2 m/s，避免起步阶段在 run/sprint 之间来回跳
- Lean 仍在 `bodyPivot` 上叠加，与动画正交

**方法论差距的说明**：ALS 完整系统还有 BlendSpace 八向混合、动画同步组、脚步 IK、Turn In Place、上下半身分层。当前是"按状态切单动画"，是复刻的第一步；八向（LF/RF/LB/RB）资产已具备，接入只差状态机细分。

### 3.37 音效：ALS 原版录音，内嵌不分包（v0.11.4）

**结论先说**：v0.10 那版是纯 WebAudio 合成（噪声 + 滤波 + 包络），实测听感"像电子音、不写实"，用户明确否决。噪音合成做不出真实混凝土脚步的瞬态颗粒，这是方法上的天花板，不是参数没调好。所以按 `RULES.md` 第 6 条走第二档：取 ALS 项目里的原版录音。

**素材来源与处理**（`tools/sfx/_sfx.js`）：

- ALS 的 `.uasset` 里直接内嵌了原始 WAV（96kHz 单声道），把 RIFF 段切出来即可，不需要引擎
- 处理：去首尾静音 → 降到 16kHz 单声道 16bit → 全组统一增益（保持走/跑的相对轻重）
- 13 个片段共 **111KB base64**，内嵌进 `world01.html`，仍然零外部引用

| 用途 | 录音 |
|---|---|
| 走 | `Concrete_Walk_01~05` |
| 跑 | `Concrete_Run_01~04` |
| 起跳 / 落地 | `Concrete_Step_01~03` + `Concrete_Pivot_02` |

ALS 原版的跳跃和落地也是播脚步 Notify，所以复用 Step 集是符合原版行为的，不是偷懒。

**同步**：用 `createBufferSource` + `AudioBuffer` 在动画事件那一帧直接 `start()`，延迟只剩音频硬件本身的几毫秒。合成版每段噪声都有几十毫秒的起振时间，听感就"慢半拍"——这也是"不同步"的来源。

**播放**：每个动作随机选一个变体，`playbackRate` 在 0.95–1.05 之间微随机，音量按步态递进（走 0.85 / 跑 1.0 / 落地随冲击 0.8–1.1），避免机械重复。

实测（`__audioState()` 的 `peak`，页面内 rAF 连续采样）：跑动峰值 0.92，即录音本身的电平，不做额外压缩。

**解锁路径**（手机不出声几乎都是这一层的问题，不是合成的问题）：

1. **`AudioContext` 只能在手势里创建**——非手势创建的实例，iOS 上 `resume()` 会返回成功但状态永远停在 `suspended`。所以 `audioReady()` / `update()` 兜底一律不新建实例，只 `resume`；发现实例不是手势建的，第一次真手势时关掉重建
2. 手势里真播一次 1 帧空 buffer（iOS 光 resume 不响）
3. `navigator.audioSession.type = 'playback'`（绕开 iOS 侧边静音拨片）
4. `WeixinJSBridgeReady` 后再试一次（微信内置浏览器）+ `visibilitychange` 切回前台时重新 resume
5. 连续两次手势仍不 running → 关掉重建 `AudioContext`
6. 真起不来才在右下角显示提示，并把实际的 `state` 写进去（如 `suspended`），正常时这块 DOM 不显示

**备用播放链路（v0.11.3）**：有些 webview 直接拦掉 WebAudio 的输出，`state` 永远是 `suspended`，`resume()` 也没用。这时把同一批录音交给 `<audio>` 元素播（data URI），第一次手势里静音播一次解锁元素。两条链路音源相同，听感一致。

**脚步时机**：不靠计时器拍脑袋，烘焙动画时用 FK 算 `foot_l`/`foot_r` 每帧世界 Y，取局部极小值（阈值 = 最小值 + 8% 幅度、间隔 <0.16s 合并、首尾跨循环去重）作为触地事件，写进动画数据的 `steps` 数组。运行时按动画时间轴跨事件点触发，与播放速率、循环回绕都解耦。

**注意**：ALS 动画里的 `Mask_FootstepSound` 曲线是空的（实际用 Animation Notify 派发），所以不要指望从曲线拿事件。

### 3.358 武器系统整体移除（v0.14.0）

**决定**：不做武器了，已有的那套手枪系统整块删除。不是"暂时关掉"，代码里不留半截。

**为什么是删而不是改**：v0.12.0 做过一版、v0.13.0 整体重做、v0.13.1 又调了"只剩一把枪 / 持枪姿势 / 枪声"。三轮都停在"手感调不顺"上——问题不在参数，在这个世界该不该有枪。用户判断：方向不对。那么继续调就是往里加沉没成本。

**删除顺序**（照着做才不会留悬空引用）：

1. 界面元素 → 2. 输入监听 → 3. 模型与材质 → 4. 挂点姿态常量 → 5. 射击逻辑 → 6. 特效池 → 7. 音效 → 8. 主循环调用 → 9. `__world` 诊断接口 → 10. **碰撞豁免表**

第 10 步最容易漏：`fillCollisionGaps()` 的 `COL_EXEMPT_ROOTS` 里有一项是 `heldPistol`，删了模型不删这行，自检会在 `undefined` 上取属性直接崩。反过来，删完之后豁免数从 30 掉到 2，这个数字本身就是"28 个枪零件确实离场"的证据 —— **比人眼数 mesh 可靠**。

**一处不能连带删的**：`P.faceTarget = camYaw + π − 0.5` 那段的注释是「持枪站定：身体跟着瞄准方向转」，看着全是枪，但它同时是 v0.13.2 原地转身（TurnInPlace）的唯一触发点——不接管 `faceTarget`，站定甩视角时 `diff` 恒为 0，90° 转身动画永远不会播。删完测试里 4 条转向断言全挂才发现。

所以现在留的是去掉 0.5rad 的版本：**身体正对视线**，而不是"为了露出右肩和枪"斜 29°。判据一句话：**注释说它为什么被写出来，不代表它只负责那一件事。**

**留下的**：三块靶板 + 支架当纯场景物件（有碰撞、无命中判定）。它们是有体积的世界物件，删了那片空地就真空了。

**代价**：第一人称现在是"纯眼睛"——ALS 素材里没有"空手"的第一人称手臂，所以画面里没有手。要补第一人称手臂得另找素材，和 8 方向步态是同一笔素材债。

### 3.39 单手武器：一把枪，三种视角（v0.13.1 —— **v0.14.0 已整体移除，见 3.358**）

**硬约束**：全场只有一把枪。第一人称不是第二套模型，而是同一个 `heldPistol`（挂在 `hand_r` 上）在另一组手臂角度下的样子。

| 视角 | 相机 | 手臂姿势 | 身体 |
|---|---|---|---|
| 自由 / 第三人称 | 轨道机位（肩点球面） | `HOLD`：手在骨盆右前方，枪口朝前 | 可见 |
| 第一人称 | 移到头前 | `HOLD_AIM`：手抬到眼睛前下方 | 隐藏（`skinMesh` 关） |

**姿势是解出来的，不是调出来的**。`applyHoldPose()` 在动画写完之后对 `upperarm_r` / `lowerarm_r` / `hand_r` 右乘一个局部旋转（`quaternion.multiply`），相当于"在无持枪动画的素材上硬摆一个持枪姿势"。角度用坐标下降求：目标 = 手骨相对骨盆的 xyz（世界系，注意 `face = π` 时右 = +x、前 = -z），软约束 = 手肘横向 > 0.17m，评价 = `__world.repose()` 之后读世界坐标算残差。

- `HOLD`（第三人称）：目标 `(+0.30, +0.22, -0.26)`，残差 9cm，肘 0.30m。手位偏外是刻意的——从正后方看，手在胸前会被躯干整个挡住。
- `HOLD_AIM`（第一人称）：目标 `(+0.17, +0.55, -0.36)`，残差 7.6cm。枪最后落在离眼 0.46m、NDC (0.56, -0.59) 的位置，即画面右下角。
- 两组之间按 `fpBlend` 线性插值（同一组骨骼的欧拉角，插值不会穿帮），所以视角切换时手臂是连续抬起来的。

**枪口朝向要单独校**：`GUN_HAND_Q` 是相对手的常量局部变换，手转多少枪就转多少。改手臂角度后必须重新对一次枪口方向（枪的局部 -z 与角色前方的点积），否则枪会横着指。同一个求解器里把 `(1 - dot)` 加进代价，一次解完位置和朝向。

**判断"看不看得见"用 NDC，不要猜**：把枪的世界坐标 `project(camera)`，`|x|,|y| ≤ 1` 才在画面里；再看它是不是落在躯干轮廓内（会被挡）。第一版"第三人称枪不可见"就是这么定位的——NDC x≈0.16 在画面里，但正好压在躯干上。

**侧身站姿**：站定且持枪时 `P.faceTarget = camYaw + π - 0.5`（29°）。两个作用：真实的射击站姿；把枪从躯干轮廓里转出来。判定要排除第一人称（`fpBlend < 0.5`），否则第一人称下身体被拧 29°，手臂连带枪一起飞出画面。

**枪声**：ALS 是移动系统，没有武器音源，所以合成。三层叠加：

| 层 | 做法 | 参数 |
|---|---|---|
| 低频冲击 | 正弦扫频 | 148→46Hz，170ms，gain 0.60 |
| 噪声爆裂 | 带通噪声 | 2100Hz Q0.7，95ms，gain 0.80 |
| 尾音 | 低通噪声 | 1500→380Hz，280ms，gain 0.20 |

每发从 0.6s 噪声 buffer 的随机位置起播（`start(t, rand())`），连射不会听成一模一样的复读。机械声（干击 / 退匣 / 上匣）是 45–75ms 的带通噪声 + Q2.2。

**ALS 追加音效（v0.13.1）**：`Concrete_Pivot_01–04`（转身步，跑动中急转 >120° 触发，冷却 0.42s）、`UI/Click`（按钮点击，捕获阶段统一拦）、`Wind05 + Birds01` 混成 9.3s 环境循环（11kHz，首尾 0.7s 交叉淡化防接缝）。

### 3.38 跳跃：三段式，空中不踏步（v0.11.0）

**问题**：v0.10 的空中全程播放 `ALS_N_JumpLoop`，而那是个**跑动起跳**的循环——脚前后行程 63–70cm、脚抬到 65cm。角色在空中没有对应位移，脚就在原地划，观感就是"滑步"。

**做法**（对齐 ALS 的三段结构）：

| 阶段 | 动画 | 说明 |
|---|---|---|
| 起跳（上升段 vy>0.2） | `JumpWalk_LF/RF`，快跑时 `JumpRun_LF/RF`（v0.11.5） | 按起跳瞬间速度选：>4.8 m/s 用跑跳；左右脚每次交替 |
| 下落（vy≤0.2） | `FallLoop` / `FallLoop_Fast` | 脚行程只有 7cm，**几乎不动**，滑步感消失 |
| 落地（跑跳，水平速度 >1.8） | **不播落地片段** | 腿还在跑，硬塞"脚钉住"的姿势必然滑；只留压扁 + 音效 |
| 落地（原地/慢速，≤1.8） | `Land_Light` / `Land_Heavy` | 脚真踩住了，完整播，占 0.55s |

**关键取舍**：

- 不用 JumpLoop 了。它只在"角色真的以起跳速度前冲"时才成立，我们的空中不锁速度，用它必然划
- 起跳片段只烘焙前 22 帧（0.7s），上升段实际只用前 ~0.35s，裁掉后半省 43% 体积
- 空中 `ACC` 降到 30%，水平惯性保留——起跳后不会突然刹停，跳出去的距离和动画的腿部动作对得上
- 落地不再锁满 1.2s 整段，否则落地后继续前进会变成"脚不动但人在滑"
- 跑跳落地干脆不播落地片段：脚钉住的动画和位移天生对不上，这是"没有下半身分层"时的取舍。真要两全，得做 ALS 那样的上下半身分层（腿走跑步循环、上身播落地压缩），还没做
- **起跳 → 下落用 0.30s 混合**（其他切换仍是 0.18s）：`JumpRun_*` 的反侧手会摆到头顶以上 33cm，切得太快像被拽下来

**仍存在的差距**：ALS 有 JumpApex 段和起跳的 root motion（位移由动画驱动）。FBX 里没有 pelvis 水平位移曲线，所以这里只能靠物理速度，脚与地面的严格吸附做不到。

### 3.4 相机模型

绕角色的球面轨道，三个量：

```
camYaw    水平角，0 表示位于角色正后方
camPitch  俯角，夹在 0.06–1.00 弧度（3°–57°）
camDist   距离，横屏 8.6 / 竖屏 9.9
```

相机位置（枢轴在肩点，居中不偏移）：

```
pivot  = follow + (0, 1.42, 0)
pos    = pivot + ( sin(yaw)·cos(pitch),
                   sin(pitch),
                   cos(yaw)·cos(pitch) ) × dist
lookAt = pivot
```

`follow` 是对角色位置的平滑跟随（lerp 系数 4.2），转视角本身不平滑（要跟手），只有位置跟随平滑。

**移动方向必须相机相对**：`forward = (−sin(yaw), −cos(yaw))`、`right = (cos(yaw), −sin(yaw))`。这一步漏掉的话，转完视角按前进还往老方向跑。

#### 3.41 透视三档取景：第一 / 第三 / 自由（v0.11.21 → v0.11.29；第 4 档等距见 3.41.2）

`viewMode` 0/1/2/3 = 第一人称 / 第三人称 / 自由视角 / **等距（v0.15.0；v0.17.0 起是默认档**，`isoSnap()` 在首次 `resize()` 后把仰角 / 方位 / 机距一次性落位，不走每帧缓动，进场没有开场旋转）。前三档是同一台透视相机，只是位置来源不同，所以能直接按权重混合：

```
wF = fpBlend          第一人称权重
w3 = 1 − wF           轨道权重（第三人称 · 自由视角，和恒为 1）
pos    = tp·w3 + eye·wF
lookAt = tpT·w3 + fpT·wF
```

| 档位 | 位置 | 注视点 | 拖动 | 缩放 |
|---|---|---|---|---|
| 第三 | 肩点枢轴 + `dir(camYaw, camPitch) × camDist` | 肩点 | 水平 + 俯仰 | 无 |
| 第一 | `P.pos + (0,1.62,0)` | 视线方向 12 m 外 | 水平 + `fpPitch` | 无 |
| 自由 | 同第三，俯仰/距离换成 `freePitch`/`freeDist` | 肩点 | 水平 + 俯仰（±1.45） | 滚轮 / 双指 1.5–60 m |
| 等距 | 同第三，俯角焊死 35.264°、方位两档（固定=不转 / 自由=Q/E 15° + 拖动连续）、机距由取景高度反算 | 肩点 | 固定/自由（见下） | 滚轮 / 双指改覆盖米数 6–90 m（**换正交相机**，见 3.41.2） |

- **为什么按权重相加而不是状态机**：状态机在"从轨道切第一人称"时会先回到某个中间状态（两个量分别在动），权重相加天然经过中间高度，镜头是一条连续曲线。
- **第一人称**：独立 `fpPitch`（±1.15 rad），不动 `camPitch`；身体朝向 `camYaw + π`，否则侧着走；`fpBlend > 0.45` 隐藏自身网格（0.7 时相机已经在体内）。
- **枢轴在肩点 1.42 m**：挂胸口会让滚轮拉到最近时镜头停在腹部（用户报过「相机在肚子这里」）；挂眼睛那是第一人称的事。机位不再额外抬高，枢轴就是基准。
- **自由视角（v0.11.23 加，v0.11.29 由「全视」改名）**：复用第三人称的球面轨道，只把 `orbitPitch` / `orbitDist` 换成 `freePitch` / `freeDist`。
  - **默认落点是旧俯视全景**（v0.11.33）：俯角 `0.66`（约 38°）、机距横屏 `23` / 竖屏 `20`——就是 v0.11.29 删掉的 `TOP_PITCH` / `TOP_DIST`。进这一档的目的是"先看见全貌，再自己转"，从第三人称原样接过来只会让人以为它只是"能转的第三人称"。
  - **不硬切**：0.55 s 内从当前取景滑到落点（`freeIntro`），任何用户输入（转俯仰 / 滚轮 / 捏合）立刻清 0 取消，不跟人抢操作。
  - 滚轮 `Math.exp(deltaY × 0.0011)`；双指按"起始指距 × 起始距离 / 当前指距"**直接设值**，不累乘（累乘会飘）。
  - **俯仰方向和第三人称一致**（v0.11.31）：`freePitch += dy`，下拖 = 镜头抬高低头看。曾经写成 `-=`，两档手感相反。
  - **捏合按区域判定**（v0.11.30 → v0.11.31）：
    - 只有"看到两根手指"就捏合，会把"左手摇杆 + 右手拖动"当成缩放，两个操作一起废掉；
    - 但反过来"有摇杆就不许捏合"，又让"边走边缩放"做不了；
    - 最终规则：**捏合 = 右半屏凑够两根手指**。左半屏永远归摇杆，不参与判定；捏合用显式 `pinch.a/b` 记两根手指，`pointermove` 只拦截这两根，摇杆手指照常驱动走路。三种组合可以同时存在：走 + 转 + 缩。
    - 捏合抬起一根后，右半屏剩下的那根接着当转视角用（`look.dragging = true`，避免抬手被判成轻点跳跃）。
  - 最近 1.5 m（最短臂长挡住，不把"拉到底"做成第一人称：眼睛朝向与轨道朝向是两套控制模型，混起来最近处会突然换手感）。
  - 能翻到地平线以下，但不能钻到地下：按当前机距反算最低俯角 `asin((0.35 − follow.y − 1.42) / dist)`，机距越大允许越低，拉近了自动抬起来；再加 `camera.y < 0.35` 兜底。
  - **45° 视角锁定**（v0.11.35 加 / v0.11.37 补全）：僵毁那类等距生存游戏的取景。**俯角焊死 `π/4`、水平角焊死**，缩放照常；这就是固定的斜 45° 俯视取景。
    - 僵毁经典相机其实是**固定俯角 + 只能 90° 步进转**，官方没公布精确角度，社区按 45° 左右理解；B42 换了可调相机，默认还更低。这里借"整个镜头不跟着角色转"这一条。
    - **水平锁在哪**：`lockYaw = camYaw`，即**按下按钮那一刻的朝向**，不跳镜头。想换方向先解锁转好再锁。这是 v0.11.37 补的——v0.11.35 只锁了俯角，水平还能转，不叫"固定视角"。
    - `turnBy` 在 `freeMode && freeLock` 时忽略 `dx` 和 `dy`；键盘 `Q`/`E` 也禁掉，否则从键盘还能转。第一/第三人称不受影响。
    - 收敛用**每帧 easing** `k = min(1, dt×6)`：`freePitch += (LOCK_PITCH − freePitch)×k`、`camYaw += dyaw×k`，其中 `dyaw` 先归一到 `±π`（跨 `±2π` 边界不归一就会绕远路整圈转回来）。不复用 `freeIntro`：那个过渡会被缩放取消，取消后角度永远卡在半路。
    - 锁定时 `toggleView` 的落点取 `LOCK_PITCH`；锁定是偏好，跨视角保留，切出去转一圈再回来会平滑收敛回 `lockYaw`。
    - 桌面没有按钮，用 `L` 键（`T` 是主题切换）。
  - **遮挡不拉近，改半透明**（v0.11.32）：这一档的机距是用户自己滚出来的，被塔一挡就拽到 0.9 m、松手再缓缓退回，等于镜头跟人抢控制权。所以自由视角里 `camBlockGoal` 恒等于 `effDist`，命中的物体材质换成 `ghostMat`（`opacity 0.26`、`depthWrite = false`），走开还原。第三人称仍走"拉近到 0.9 m"那套——它的机距是程序给的，压一下不心疼。
- **遮挡处理的两种策略**（按档位分，不要混）：

  | 档位 | 相机怎么办 | 挡在中间的东西 |
  |---|---|---|
  | 第三 | 沿视线拉近（最短 0.9 m），离开缓慢恢复 | 不动 |
  | 自由 | **不动** | 换 `ghostMat` 半透明，离开还原 |
  | 第一 | 不处理 | 不处理 |

  两套名单 `keep` / `occluded` 在 100 ms 的射线回调里交替维护：先还原已出名单的，再给新名单上材质，顺序反了会闪一下。
- **删掉的东西**（别翻案）：
  - **正交投影（v0.11.33 加 / v0.11.39 删 / v0.15.0 作为独立档重新加回）**：v0.11.33 那版是"把整个渲染换成正交"，v0.11.39 用户判定不需要、整套移除（`orthoCam` / `activeCam` / `orthoMode` / `#projBtn` / `O` 键）。**v0.15.0 按用户明确要求加回来**，但形态完全不同，见 3.41.2：
    | | v0.11.33（已删） | v0.15.0 |
    |---|---|---|
    | 地位 | 替换整个渲染，全场景只有正交 | 第 4 档，其余三档仍是透视 |
    | 相机 | 单台，需整套改造 | 第二台 `orthoCam`，每帧跟随透视相机 |
    | 机位 | 摆在 90 m 外拍全景 | 跟随角色，枢轴在肩点 |
    | 取景 | 视野只覆盖约 18 m，**房子被顶出画面** | 按"纵向覆盖 28 m"定，房子完整 |
    | 接缝 | 硬切 | 半高 = 机距×tan(FOV/2)，枢轴平面等大，不跳 |
    当初那条否决理由（房子跑出画面上边）是真的，所以这次专门量了：24 m 时房子顶部仍被顶出去，28 m 完整，30 m 更宽但人更小。默认取 28。
  - **俯视（v0.11.29 删）**：整套透视俯视移除（`topMode` / `topBlend` / `TOP_PITCH` / `TOP_DIST` / 权重 `wT`）。它的半透明遮罩思路留下来了，在 v0.11.32 挪给了自由视角。
  - **越肩（v0.11.27 加 / v0.11.29 删）**：横向偏移在手机上把横向空间让给了空白区域，用户判定不适合，先不做。`PIVOT_H` 抬到肩点这件事保留。

#### 3.41.1.1 设置面板样式（v0.20.0 补）

**事故**：`#settingsPanel` 从建面板那天起就没有一条 CSS。`<section>` 在文档流里排布，被 100% 高的画布顶到视口外，加上 `body{overflow:hidden}`——按 F2 确实在切 `hidden`，但人永远看不见，表现为「F2 没反应」。拖了至少十几个版本才被用户发现。**教训：新 UI 元素必须有「看得见」的验收（屏幕矩形落在视口内且尺寸像样），「hidden 属性切了」不算数。**

样式要点：右上角 272px 卡片（`--panel-solid`）、z-index 400、矮屏（≤560px 高）改贴底；内容超长时页脚（状态文字 + 恢复默认/关闭）用 `position:sticky` 吸底，滚到哪「关闭」都在手边；页脚用**不透明**的 `--bg`，半透明面板色会把身后的滑条透出来。

#### 3.41.1.2 省电：后台暂停与前台待机（v0.20.0）

两层：切后台 → `visibilitychange` 停整个循环（本来就有）；前台待机 → 30s 无输入 + 角色静止 + 无动作播放 + 面板没开 → 主循环空转（不物理不渲染，rAF 链保留），任何输入立刻恢复。
待机判定在 loop 顶部做，时间基准 `last`/`acc` 每帧照常推进，恢复不会卡一大跳。
设计取舍：不做「降帧渲染」（12fps 之类）——直接停渲染更省，反正画面是静止的；音效/环境音照跑，那是「环境还在」。诊断口 `__world.power`（idle/hidden/sinceInput），`setIdleMs(ms)` 供测试缩阈值，`frameCount` 验证渲染帧真的停了。

#### 3.41.1 桌面鼠标：指针锁定（v0.11.41）

用户要求 RPG 式：不要按住左键拖，而是鼠标消失、移动即转视角。

- 点画面调 `canvas.requestPointerLock()`；`pointerlockchange` 维护 `plLocked`；锁定态 `pointermove` 直接读 `movementX / movementY` 交给 `turnBy`，不再依赖 `mouse.down`。
- 未锁定仍保留按住拖动的路径作为兜底——iframe 或浏览器策略拒绝锁定时不至于完全不能转。
- `pointerlockerror` 把 `plLocked` 置回 false；`requestPointerLock()` 返回 Promise 时挂 `.catch()`，避免未处理拒绝污染控制台。
- 手机端不受影响：整条路径由 `pointerType === 'mouse'` 守着。

#### 3.41.2 等距视角：正交相机（v0.15.0）

第 4 档。前 3 档都是"透视相机绕角色转"，这一档换的是**投影本身**。

**为什么必须是正交**：透视的平行线永远收敛——FOV 调到 10°、5° 都只是"看起来像"。等距是画法几何里一件确定的事，三条同时成立才算：

| 条件 | 值 |
|---|---|
| 投影 | 正交（平行投影），`OrthographicCamera` |
| 仰角 | `atan(1/√2)` = **35.264°**（不是 45°；45° 是"像"，不是"是"） |
| 方位 | **45° + k·90°**，四个机位 |

**不换相机，加一台。** `camera`（透视）继续负责前三档，新增 `orthoCam`，每帧 `position.copy` + `quaternion.copy`，`activeCam` 决定 `renderer.render` 用哪台。

**接缝（这套做法的全部技术要点）**：

```
正交视锥半高 halfH = effDist × tan(FOV_BASE / 2)
正交视锥半宽 halfW = halfH × ASPECT
```

于是两台相机在**枢轴平面**上等大 —— 位置相同、朝向相同、过枢轴那一点的世界尺寸相同。

- 切投影那一刻不跳（枢轴处连续），实测差 0.0002（浮点）
- "远处不变小"从第一帧就成立，不需要过渡动画
- 机距动画 + 视锥绑定机距 = 进等距时是连续缩放，不是硬切
- 反过来，这条一旦不成立就说明投影和机位脱节，所以测试里专门断言 `|halfH − expectHalfH| < 0.02`

**取景用纵向覆盖米数，不用机距，也不用"窄边"**：

- 第一版按"画面窄边覆盖多少米"算 → 竖屏窄边是宽，纵向直接撑到 34.6 m，人是小点、上下全是空地
- 视野和机距通过 `FOV` 绑定，所以"要多大画面"能直接换成"相机站多远"，不用手调常数

| 握法 | 纵向覆盖 | 角色占屏高 | 备注 |
|---|---|---|---|
| 横屏 | 28 m | ≈6.3% | 房子完整（24 m 时顶部被顶出画面） |
| 竖屏 | 28 m | ≈6.3% | 横向只有 12.9 m，是竖屏的固有代价 |

`ISO_VIEW_H_MIN 6` ~ `MAX 90`，滚轮 / 双指改的就是这个米数。正交没有 FOV，这是唯一的缩放手段。

**方位两级档（v0.18.0）**：状态量 `isoYawIdx` 是 **15° 细档**序号（0..23），方位 = 45° + n×15°；每帧逼近的目标由它反算。
- `Q` / `E` 轻按 = ±1 细格（15°）；`Shift`+`Q`/`E` = ±6 格（90°）；拖动累计 80px（`ISO_DRAG_STEP`）= ±6 格。拖动只走粗档——「整个世界转直角」的手感留给拖动，微调交给键盘，两级分工不混淆。
- **为什么用户要了细档还保留 90° 粗档**：45°+k·90° 是唯一「三条轴等长」的方位，细档角度地砖会被拉长（60° 时两轴比 0.775，实测与理论值一致）。`iso.exact` 诊断口直接告诉你现在是否停在方正方位上。
- **仍然不做连续旋转**：拖动松手永远落在档位上，不会停在 37° 这种无意义的角度。
- v0.15.0 原方案（只有 90° 一档）是用户 2026-11-15 上午否掉自由旋转后维持的；同日 further 要求"多档切换"，经选项确认落为两级档方案。
- **v0.19.0 拖动加自由旋转**：同日用户拍板「可以多档切换，包括自由旋转」。落点——拖动默认**自由**（`camYaw` 为主、`isoYawIdx` 每帧跟着它走，松手停在哪是哪）；`G` 键 / 等距下的「自由/吸附」按钮（与 `#lockBtn` 互斥共用 +56px 槽位）切回吸附跳格。**档位键不受开关影响**。
- **两条实现规则**（都是踩出来的）：① 自由拖动时每帧**不得**向档位收敛，否则拖一下就弹回格子；② ~~档位阈值吃物理像素~~（v0.21.0 随跳格机制一起删，规则①仍有效）。
- **v0.21.0 固定 = 完全不能旋转**（同日第五次演化，用户拍板「固定就是不能旋转，保留固定和自由」）：固定模式下拖动**一分不动**、Q/E 也不动，机位焊死真等距方位；跳格机制（`isoDragX` / `ISO_DRAG_STEP` / `rawDx` 物理像素累计）整块删除。`G` / 按钮切「自由」后拖动连续转 + Q/E 15°/90° 档位生效。**切回固定时吸附到最近真等距方位（45°+k·90°，不是 15° 格）**——「固定」的含义就是焊死在方块方正的四个方位上；`V` 切进等距时也按当前模式吸附。驱动量翻转照旧：固定时 idx→`camYaw`，自由时 `camYaw`→idx，`setIso`/`setYaw` 必须知道当前谁是驱动量。
- **诊断口的教训**：`setIso` 在自由模式下光改 `isoYawIdx` 会被每帧同步覆盖（和 v0.17.0 的 `setYaw` 同类坑），必须直接摆 `camYaw`。规则：**改「驱动量」的诊断口要知道当前谁是驱动量**——吸附模式驱动量是序号，自由模式驱动量是 `camYaw`。

**俯角焊死**：`turnBy` 在 `isoMode` 里忽略 `dy`，`camPitch` 每帧向 `ISO_PITCH` 收敛（`k = min(1, dt×6.5)`，与 45° 锁定同一套做法）。用每帧 easing 而不是一次性过渡：中途被打断（切视角、转屏、缩放）也总能回到位。

**遮挡沿用自由视角那套**（换 `ghostMat` 半透明，不拉近）：等距里机距只决定画面大小，被屋顶一拽就整块缩水。判定条件从 `freeMode && wF < 0.05` 扩到 `(freeMode || isoMode) && wF < 0.05`。

**进场的机距从 `effDistNow` 起步，不是 `camDist`**：自由视角实际在 23，`camDist` 是 8.6，照后者起步镜头会先钻进去再退出来（0.5 s 的"抽一下"）。过渡帧截图才发现的。

**雾没有特殊处理**：MEMORY 里 v0.11.33 记过"正交下雾退化成均匀白纱，必须 `scene.fog = null`"——那是**全景正交（机距 90 m）**的结论：整场景到相机几乎等距，雾量一致。跟随式等距机距只有 31 m，场景纵向跨度 20 m 左右，雾量 5%~30%，仍有层次。白色主题实测没有糊成一片，所以不动雾。这条结论**只对跟随式成立**，改回全景正交就要重新处理。

#### 3.42 地面网格：着色器画，不用 GridHelper（v0.11.21）

`GridHelper` 被否掉过——远处线挤进同一个像素就是摩尔纹横条。现在用 `onBeforeCompile` 往标准材质里注入：

```
vec2 g = worldXZ / scale;            // 1 m 细线 / 5 m 粗线
vec2 d = abs(fract(g - 0.5) - 0.5) / fwidth(g);
line = 1 - min(min(d.x, d.y), 1);    // 线宽固定 ≈ 1 像素
k = (1 - smoothstep(0.12, 0.55, pxSize)) × (1 - smoothstep(26, 78, dist));
```

- `fwidth` 让线宽恒定 1 像素，所以不管多远都不会"变密"。
- 再按"一个像素覆盖多少米"衰减：掠射角时一个像素能覆盖好几米，线必然糊成一片，直接让 `k → 0`。
- 世界坐标取样，所以地面跟着角色平移时网格是静止的。
- 强度只有 0.07 / 0.10，混向 `vec3(0.55,0.60,0.66)`——只提供尺度感，不抢主体。

#### 3.43 碰撞：2.5D（圆柱 vs 竖直棱柱）（v0.11.22）

世界里所有实体都是竖直棱柱，所以不需要 3D 刚体，也不需要物理引擎：

```
水平：把角色位置转到盒子局部坐标 → 圆(r=0.36) vs 矩形(hw,hd)：
      最近点 → 若距离 < r，沿法线推出；再把速度在法线上的分量清零（贴墙滑）
垂直：脚下支撑高度 = max(0, 所有"覆盖脚下 XZ 且顶面 ≤ 脚下+0.35"的盒子的顶面)
```

| 判定 | 规则 |
|---|---|
| 挡不挡 | `col.top - feet <= stepAllow` 就不挡（地面时 0.35，空中 0.08） |
| 站在哪 | 支撑高度；落地判定改成 `pos.y <= support` |
| 走出边缘 | `pos.y - support > 0.4` → `onGround = false` |
| 粗筛 | 每盒预算 `reach = 半对角线 + r + 0.6`，超出直接跳过 |

- **为什么空中把 stepAllow 收到 0.08**：站在地上允许"走进矮块再被抬起来"（这就是自动台阶）；空中也允许的话，跳到方块侧面时会先钻进体积里再被抬上去，视觉上穿模。
- **为什么站立判定放宽 0.28m**：脚踩在边缘上、或站在两个盒子接缝处时，严格判定会让支撑高度在两格之间跳变 → 人上下抖。
- **贴墙摩擦（v0.11.26）**：法向清零、切向保留 = 标准贴墙滑，但方块是随机旋转的，"撞正"几乎不发生，于是按着前进会被一路蹭到方块边缘再绕过去。现在补一层摩擦：
  ```
  press = −(目标速度 · 墙法线)        // 有多想往墙里钻
  切向速度每秒衰减 WALL_FRIC × press  // WALL_FRIC = 3.5
  ```
  - **必须是目标速度**，不能是当前速度的法向投影：上一帧法向已被清零，这里只剩一帧重新加速的量（≈ a·dt），按它算摩擦等于没有。
  - 只在 `onGround` 生效；空中蹭墙不减速，免得跳跃贴墙时突然刹车。
  - 效果曲线：0–30° 顶住（0→1.31 m 后基本不动），45° 以上照常滑行（≈ 满速）。
  - **拐角没处理**：最近点从面变角点时法线跟着转，人还会被抹过拐角。摩擦已经把"正面被送到边缘"的概率压得很低，暂时不动。
- **代价**：83 个盒子 × 2 次遍历 × 120Hz，粗筛之后实际每次只有个位数盒子参与，手机满帧无变化。

出生点正前方 2.7m 摆了三级 0.30m 台阶（每级 0.55m 深、2.6m 宽），顶上一个 0.90m 平台。参数是照着碰撞阈值挑的：

#### 3.45 出生点小屋：僵毁式一层的郊区住宅（v0.11.34）

- **小构件必须合批**（v0.11.36，踩过坑）：第一版给每根栅栏柱、每条横板、每扇窗都 `new THREE.Mesh()` 且全开 `castShadow`，**每帧 draw call 从 39 涨到 190**——每个独立 Mesh 主画面一次、2048² 阴影贴图再一次，手机上走路明显掉帧。

  | 版本 | 每帧 draw call |
  |---|---|
  | 无房子（v0.11.33） | 39 |
  | 房子逐个建（v0.11.34/35） | 190 |
  | 合批后（v0.11.36） | 62 |

  规则：**只有遮挡射线要按对象换材质 / 挂 `userData.trim` 的才配单独存在**（两片墙、两片屋顶、四块树冠、门窗面片）；其余统一进 `InstancedMesh(unitBox, propMat)`，用 `Object3D` 摆位置/缩放/倾斜后 `setMatrixAt`。车库卷帘门的四条横槽单独合成一个小 `InstancedMesh`，作为一个 `trim` 整体隐藏。贴墙薄面片关 `castShadow`；碰撞体只传 `{position, rotation}` 字面量，别为它造不渲染的 Mesh。

#### 3.51 手机按钮：药丸，不是圆（v0.11.33）

原来右上角是 58 px 的圆、右下角 66 px 的圆，里面只放两个字（快跑 / 第三），相当于用一个正方形的面积装 24 px 的文本。屏幕上常驻三块白斑，在白世界里尤其抢眼。

| 项 | 值 | 理由 |

| 高 | 34 px | 单行字够用；再矮就成了链接，手指点不准 |
| 左右内边距 | 13 px | 两字 + 26 = 51 px 宽，比 58 的圆还窄 |
| 圆角 | 999 | 全圆角，和世界里的方块形成对照（世界是硬的，UI 是软的） |
| 字号 / 字重 | 12 / 600 | 和底部提示的 11.5 拉开层级 |
| 底色 | `rgba(255,255,255,.88)` + 极淡投影 | 纯白背景上必须有边界，但不能有硬边 |

- **45° 按钮只在自由视角出现**：其他两档没有这个概念；主题按钮则任何视角都在（切主题和视角无关）。
- 右上三枚依次是 视角(+14) / 45°(+56) / 主题(+98)；删掉正交后 45° 顶了原正交的位置。
- **快跑下移到提示文字上方**：药丸变矮之后原来 74 px 的位置正好压在底部三行提示上。

#### 3.52 操作说明：桌面按 `H`，触屏自动淡出（v0.11.38）

同一段说明，两端的行为不一样，因为输入方式不一样：

| | 桌面 | 触屏 |
|---|---|---|
| 初始 | 收起（`opacity 0`） | 摊开（`opacity 1`） |
| 关闭方式 | 按 `H` 再收起 | 9 s 后自动淡出 |
| 常驻提示 | 右上角 22×22 的 `H` 徽标 | 无（没键盘） |
| 过渡 | 0.18 s（手动切换要利落） | 1 s |

- **`hideTip()` 在桌面直接返回**：`V`/`O`/`L`、点画面、滚轮、切按钮都会调它；不短路的话，说明会一按任意键就消失，或者自己弹出来。桌面只由 `setTip()` 管。
- `#tip` 的 CSS 默认 `opacity: 0`（不是靠 JS 在首帧关掉），避免桌面加载瞬间闪一下说明；触屏分支初始化时置 1。
- 徽标 `pointer-events: none`，不抢右半屏的鼠标拖动；展开时点亮（`.on`）作为状态反馈。
- **判端用 `TOUCH_UI`**（`matchMedia('(pointer: coarse)')`），和那四枚按钮同一个来源，不会出现「按钮是触屏、说明是桌面」的错配。


#### 3.53 两套主题：深色（默认）/ 白色（v0.11.39）

白色世界是立项命题，所以深色不是"把白色抹掉"，而是并列的另一档，`T` 键 / 主题按钮随时切回。

| | 白 | 深色 |
|---|---|---|
| 天空 / 雾 | `#ffffff` / `#f1f5f8` | `#0d1116` / `#18212b` |
| 地面 / 积木 | `#ffffff` / `#f4f7fa` | `#1c242e` / `#424e5c` |
| 角色 | `#8f93a8` | `#d2dce7` |
| hemi + sun | 1.45 + 1.84 | **0.62 + 0.80** |

- **深色档光强必须降**：物理光照下白世界靠 3.0 量级把材质打到近白，深色材质沿用会被洗成浅灰。这是深浅两档唯一的非颜色差异。
- **CSS 全走变量**（`--bg / --panel / --ink / --shadow / --on-bg`），切换只改 `<html data-theme>`；`theme-color` meta 跟着换（移动端状态栏）。
- **房子专用材质在 `house()` 内部**，注册到 `HOUSE_MATS` 才能被 `applyTheme()` 访问；地面网格线的颜色做成 shader uniform `uGridColor`，切主题只改 Color 对象、不重编译。
- `ghostMat` 是 `propMat.clone()`，两档透明度分别 0.26 / 0.30；还原遮罩用 `userData.baseMat`，所以切主题后被遮物体也不会掉色。


#### 3.54 攀爬：ALS Mantle + 代码位移（v0.11.40，v0.12.6 起改由根骨位移驱动，见 3.59）

素材直接在 ALS 工程里找，不自己摆姿势：`Actions/ALS_N_Mantle_1m_RH`，烘焙成 `__ANIMS.mantle`（1.5333 s / 47 帧 / 32 骨）。

- **触发**：`doJump()` 先 `tryClimb()`，命中就不进起跳缓冲。键盘空格和手机轻点都走 `doJump()`，两端共用一条判定，没新增按键。
- **判定**：沿 `P.face` 探 0.30–1.20 m，找 `top − feet ∈ [0.45, 1.25]` 且 `hw/hd ≥ 0.30` 的碰撞体。下界避开"自动迈台阶"，上界是 1m 撑上动作的合理上限，最小顶面尺寸把栅栏这类薄片排除（站不住）。
- **落点**：沿朝向继续走，取最后一个仍在顶面的位置，再回退 10 cm。**不能用安全边距当判据**——命中点本身就在盒子边缘，一加边距就永远「站不住」，这是这版踩的坑。
- **位移**：ALS 动画只带骨骼旋转，没有 root motion，位置由 `advanceClimb()` 插值。**必须分两段**（v0.11.41 修）：一条直线从起点插到顶面，45° 的斜线会穿过棱柱侧面，看着就是人从方块里钻过去。

  | 段 | 占比 | 轨迹 |
  |---|---|---|
  | ① 撑起 | 前 52% | 起点 → 外层表面外 `PLAYER_R`（`hitS − PLAYER_R`）、顶面 +0.06 |
  | ② 翻上 | 后 48% | 该点 → 顶面落点 |

  第一段上升时身体一直在盒子外侧，第二段开始时已经高于顶面，水平推进不会穿。
- **物理冻结**：`update()` 的物理整段包进 `if (climb) advanceClimb(dt); else { … }`。否则重力会把上升中的角色拽回地面、`collideXZ` 会把他从盒子里推出去。朝向/倾斜/动画状态机等公共部分留在 `if` 外照常跑；相关的 `sp / prevVX / prevVZ / sprint / tx / tz` 在开头先给默认值。
- **动画交接**：`setAnim('mantle', 1, true)` 用现成的 `ANIM.oneShot`，播放期间状态机不抢；`driveAnim` 只对 walk/run/sprint 触发脚步音，mantle 不会误播。


#### 3.55 碰撞体积可视化（v0.11.41）

调试工具，用来核对「看到的模型」和「真正挡人的形状」。`C` 键 / 手机第四枚按钮切换。

- 数据源就是 `colliders` 本身（没有第二套碰撞数据），把每个棱柱按 `hw / hd / top / yaw` 重建成 8 个角点、12 条边。
- 全部合并进一个 `BufferGeometry` + `LineSegments`：96 个碰撞体 → 2304 顶点、**1 次 draw call**，不增加逐帧开销。
- `depthTest: false` + `renderOrder 990`：被墙挡住的碰撞盒也看得到。玩家胶囊（r 0.36 / 高 1.86）每帧跟随 `P.pos`，是判断攀爬穿模最直接的参照。
- 只在需要时构建（首次开启才建），关掉只切 `visible`。

#### 3.56 网格 ↔ 碰撞覆盖式登记（v0.12.4）

用户要求"所有网格体的碰撞都加上，不要漏"。做法不是给每个 Mesh 手写一个碰撞体，而是**覆盖式登记 + 自检**：

1. `fillCollisionGaps()` 在场景全部建好后跑一次，遍历每个网格（`InstancedMesh` 逐个实例取矩阵）；
2. 用几何包围盒的 **8 个角点**逐点查"是否已被某个碰撞体包住"（容差 0.16m，够贴面片/窗门用）；
3. 没包住的按世界包围盒补一个 AABB 近似体，按尺寸/材质自动归类：
   - `pebble`：≤0.5m 高、≤0.7m 见方 —— 碎屑，**可被子弹打中，但不挡人不颠人**
   - `flat`：顶面 ≤0.12m —— 车道这类薄板，等同地面
   - `leaf`：树冠材质 —— 在头顶上方，参与射线，不做移动阻挡（否则会挡住树下通行）
   - `auto`：其余真正的实体，正常阻挡
4. 补完再跑一遍**只统计不修改**的 `collisionAudit(false)` 复核，`missing` 必须为 0；数字直接进 F2 面板（网格 + 实例 = 合计 / 已覆盖 / 豁免 / 遗漏）。

豁免只有四处，且都写进 `COL_EXEMPT_ROOTS` 带理由：地面平面（支撑由 `supportAt` 的 0 高度给）、角色骨骼蒙皮（移动用稳定圆柱）、手持枪模、第一人称枪模；碰撞/骨骼线框自身也标了 `colExempt`。

**为什么不逐个摆碰撞体**：96 个构件时是"位置对不上"，430 个实例时是"逐帧遍历和 draw call 一起崩"。覆盖式登记让"看得见 = 有碰撞"变成可自动验证的约束，而不是靠人肉清单。

**已知近似**：`auto/pebble/flat/leaf` 是 AABB，旋转过的散石会略微偏大一圈；树冠只做射线命中，不做移动阻挡。

#### 3.57 攀爬高度分档：1m / 2m 两段 ALS 素材（v0.12.6 修订）

| 顶面高度 | 用哪段 | 时长 | 触发 | 说明 |
|---|---|---|---|---|
| 0.40–1.30m | `mantle`（ALS_N_Mantle_1m_RH） | 1.06s（速率 1.45x） | 跑撞自动 / 空格 | 矮墙、台阶平台、栅栏翻越 |
| 1.30–2.35m | `mantle2`（ALS_N_Mantle_2m） | 1.55s（速率 1.55x，剪到 2.40s） | **只能空格** | 车库墙、高积木 |
| >2.35m | 不起攀 | — | 三层楼/主屋 3m 墙，够不到就是够不到 |

- **位移不再自己插值**（v0.12.6 改）：以前按 48% / 30% / 22% 三段 smoothstep，和动画的腿部节奏对不上，脚在墙面/地面上被拖。现在由烘焙出来的**根骨位移曲线**驱动（见 3.59）。
- `samplePose` 里 `mantle` 和 `mantle2` 都按单次动作处理（末帧停住，不插值回首帧），否则攀爬收尾会滑步。
- 翻栏（`vault`）例外：落点是另一侧地面，竖直不用根骨净上升量，改成 `peakY + sin(π·进度)` 的过顶弧线。
- **高墙只手动**（v0.12.7）：`tryClimb(autoOnly)` 里 `autoOnly` 为真时遇到 tier2 直接返回 false。自动路径是跑撞预接近与空中小跳；`doJump` 走的是手动路径，并且会清掉撞墙踉跄的 `stumble`，「站到墙根按不动」是手感问题。
- **可攀的墙不弹回**：撞墙踉跄会把人推离 0.35m，退了就够不到沿。顶面在 0.40–2.35m 的墙只停住不走踉跄分支。

#### 3.58 主角碰撞：体宽半径 + 骨骼胶囊（v0.12.5）

用户提"用模型本身做碰撞"。分两层落地，因为**UE / ALS 的移动碰撞本身也是一个胶囊**：

1. **移动**：仍是一根胶囊，但半径 `rBody` 由骨骼实测体宽推出（骨盆/脊柱/大腿/上臂离中轴最远点 + 5cm，夹 0.24–0.40，按 `dt*5` 平滑）。贴墙间隙从 0.36m 收到 ~0.25m，不会因为摆臂抖动——单一胶囊 + 缓变半径是稳定性的前提。
2. **命中/接触**：13 段骨骼胶囊（躯干、头、双臂、双腿、双脚）每帧取端点，3 个采样点测"埋进阻挡体多深"（要求采样点在碰撞体顶面以下，站在台上不算接触）。结果进 F2 面板，碰撞模式下被埋进去的那段标红。

**为什么不直接拿蒙皮当碰撞体**：蒙皮是几万三角形，逐三角求交的代价和抖动都不现实；多体动力学解算会让摆臂把角色顶离墙面。所以取"胶囊代表身体段"这一步近似，和 UE 的做法同源。

#### 3.59 攀爬位移 = 动画根骨位移（v0.12.6）

**问题**：用户报"爬高墙有滑步"。量化后发现是两层原因叠在一起：

1. `bake_full.cjs` 原来只烘骨骼旋转 + 骨盆竖直 `bob`，**根骨平移的水平分量被丢掉**，位移由代码另算。动画的水平行程在 0.33–1.0s（clip 共 2.7s）就结束了，代码却均匀走满 1.95s —— 后 0.86s 里"动画已经站住、身体还在往前挪"，脚被拖。
2. 跑撞自动抓沿的探针 0.56m 太远，起手点离墙 0.45m，落点又在墙面里 0.44m，需要的水平距离 0.81m 而动画只有 0.65m，位移被拉长 1.25 倍，脚在墙面上被拖 25%。

**做法**：

- 烘焙新增 `root` 数组：根骨（`root` 优先，退回 `pelvis`）相对首帧的位移，按 Three 分量存 `[侧, 上, 前]`。实测 `mantle` Δ=[0, 1, 0.65]、`mantle2` Δ=[0, 2, 0.65]，竖直正好等于素材设计高度。
- `advanceClimb()` 每帧按**动画时间**取根骨位移 → 位置。播放速率只压缩时间轴、不改曲线形状，所以任何速度下身体和脚都同相位。
- 需要更短的水平距离就整体压比例（`sH < 1`，只能这样）；更长的话不拉整条曲线，多出来的量 `residual` 放到 40%–90% 的尾段（翻上去站起时）慢慢补，那会儿脚本来就抬着。
- 探针 0.56 → **0.34m**（≈体半径 + 5cm），让起手点贴住墙；诊断字段 `__world.climbScale` 给出 `{h, v, sH, res}`，`sH` 应恒为 1.00。
- 回退路径：素材没有 `root` 数据时仍走原来的三段插值，不会崩。
- **骨盆三分量**（v0.12.7）：只应用竖直 `bob` 是穿模的根因 —— 撑上动作里骨盆相对根骨还要后收 0.27m，丢了水平分量身体就贴在墙面上、甚至陷进去。`pv` 烘 x/y/z 三分量后写回骨盆骨骼。
- **几何对齐参数**：抓沿距离上限 0.50m（原 0.90，太远起攀会把位移拉长到 1.9 倍）、起手点保底离墙面 `CLIMB_START_GAP` 0.36m、落点进深 `CLIMB_LAND_IN` 0.34m。三者配合让 `sH` 稳定在 1.00。实测骨骼埋进墙体最深 5.5cm（沿口抓握），改前是 13cm。

#### 3.6 渲染预算：手机先砍"画多少像素"（v0.13.0）

用户报"手机好卡"。可复现的第一步是**排除主线程**：CDP 在 4 倍 CPU 降频下跑 390×844、DPR 3，仍然是 120 FPS、P95 9.4 ms、0 个长帧。也就是说卡在 GPU / 显存，不在 JS。

于是把像素成本拆开看：

| 项 | 改前 | 改后（手机） | 倍数 |
|---|---|---|---|
| MSAA | 开（默认 4x） | 关 | ~4× 采样 |
| 像素比 | `min(dpr, 2)` → 780×1688 | `min(dpr, 1.5)` → 585×1266 | 0.56× 像素 |
| 阴影图 | 2048² + PCFSoft | 1024² + 硬 PCF | 4× 采样 |

三项是乘起来的。桌面维持原样（2 倍像素比、MSAA、2048 PCFSoft），只有移动端降。

**移动端判定**：先看 UA（`Android|iPhone|iPad|iPod|Mobile|HarmonyOS|OpenHarmony|MIUI`），命中即手机；iPadOS 13+ 默认伪装成 Mac，退回"触点数 >1 + `(pointer: coarse)` + 短边 ≤820"。早一版写的是"有触摸 + 短边小"，会把小窗口的桌面浏览器也判成手机——真机上是对的，桌面上是错的，所以改成 UA 优先。

**自适应分辨率**（`adaptResolution`）：真机 GPU 会随温度/占用变慢，静态配置不够。

| 参数 | 值 | 理由 |
|---|---|---|
| 采样窗口 | 24 帧 | 太短会被单帧尖刺带偏，太长反应迟钝 |
| 降档阈值 | 平均 > 23.5 ms（<43 FPS） | 60 FPS 目标下留出余量 |
| 升档阈值 | 平均 < 17.8 ms（>56 FPS） | 和降档拉开滞回，避免边界抖动 |
| 步长 | 0.08（很慢 0.16） | 8% 的像素变化肉眼几乎看不出 |
| 下限 | 0.62 | 再低画面就明显糊，宁可掉帧 |
| 冷却 | 0.9 s | 一次调整后不再连调 |
| 暖机 | 1.5 s | 开局几帧在编译着色器，拿它们当依据会一进场就砍到底 |
| 降档记忆 | 12 s 内不回爬 | 防止"降→快→升→又慢"的两档来回闪 |

只影响渲染像素，物理和动画仍固定 120 Hz 步进，所以手感不随画质变化。

#### 3.61 手枪：手感由"曲线"和"反馈层"构成（v0.13.0）

用户原话是"手枪相关的你参考成熟产品做啊，做的啥啊"。原来的实现是 3 个盒子 + 一个锥形闪光、开火只做 `cooldown + 闪一下 + 一条射线`。参考主流 FPS 的手枪，把它拆成四层：

| 层 | 内容 | 为什么必须有 |
|---|---|---|
| 模型 | 18 个部件：滑套 / 抛壳口 / 防滑纹 / 照门 + 准星 / 膛口 + 枪口孔 / 套筒座 / 导轨 / 分解杆 / 扳机护圈 / 扳机 / 握把 / 握把纹 / 弹匣 + 底板 | 轮廓和细节决定"这是把枪"还是"一个盒子" |
| 材质 | 中灰钢滑套 + 深色聚合物握把，两段 | 白色世界里全黑枪身会糊成剪影 |
| 动态 | 欠阻尼弹簧后坐力（位移 / 俯仰 / 横摆）+ 滑套 28 mm 后座循环 + 换弹四段 + 空仓干击 | 手感来自"开一枪之后枪怎么回来"，不是静态造型 |
| 反馈 | 散布锥（准星四段线张合）+ 抛壳 + 曳光 + 弹孔 + 烟 + 火光 | 单发要能看出"打中了什么、偏了多少" |

**后坐力用弹簧而不是指数衰减**：`wRecV += (-wRec*210 - wRecV*17)*dt`，开火时灌一个初速度（0.95）。指数衰减只往回收，看起来像掉帧；欠阻尼弹簧会过冲一点再收住，那一下"顿"才是枪有劲的感觉。第一人称的枪身后移 5 cm、抬头约 13°，第三人称只转 3.2 rad 比例量（枪小、动作要克制）。

**散布与准星同源**：`bloom = 0.0032 + 移动 + 空中 + 连发累积`，准星间距 `gap = 3 + min(26, bloom*620)` px，实际弹道也在同半径的锥内取随机方向。两者共用一个数，玩家看到的和打出来的才一致。

**特效全部池化预建**（抛壳 8 / 曳光 4 / 弹孔 20 / 烟 6）：开火瞬间 `new` 一个带新材质的 mesh，手机上会触发临时分配 + 首次编译着色器，表现为"每开一枪卡一下"。

**三条硬约束**（踩过）：

1. **不能用叠加混合**。这个世界底色是白的，`AdditiveBlending` 在白底上等于没画——第一版枪口火光、曳光、烟全是叠加，截图里完全看不见。全部改普通混合 + 饱和色。
2. **长条面片拼不出星形火光**。透视下 0.088 m 的细长面片会拉成横贯半屏的丝带。火光 = 一片正对镜头的方片 + 一个前向锥体。
3. **靶子不能既走解析体又走 mesh 射线**。靶子自己也在 `colliders` 里，射线先撞到它的解析盒，`hits[0].distance < nearest` 因浮点误差判负 → "打中靶子"退化成"打中场景"。按 `kind === 'target'` 排除。

## 四、关键取舍与理由

| 决策 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 相机朝向 | 固定轨道，玩家手动转 | 自动跟随角色背后 | 自动跟随在手机上会晕，且剥夺了观察世界的自由 |
| 视野 | 三档：第一 / 第三 / 自由 | 只做第三人称；四档（含俯视） | 第一人称是沉浸工具，自由视角是观察工具，成本都只是插值一段位置；俯视在 v0.11.29 删掉——自由视角拉到高处就能替代它的观察用途 |
| 越肩偏移 | 不做（v0.11.29 删） | 横向偏移 + 枢轴抬肩 | 手机上横向空间本来就不够，偏移等于把一半屏幕让给空白；枢轴抬到肩点这半件事保留 |
| 移动方式 | 相机相对方向 | 角色相对（坦克式） | 现代第三人称的默认预期 |
| 地面网格 | 着色器画弱网格 | `GridHelper` / 网格贴图 | GridHelper 远处是摩尔纹横条；着色器按像素覆盖率衰减就没这问题 |
| 参照物 | 散石 + 方块群 | 网格、地面纹理 | 有体积感、有投影，且不形成规律线条 |
| 角色材质 | 哑光灰白模 `#8B8F95` | 深色剪影 | 用户指定参考 UE Mannequin；代价是角色不再是最强对比点，可读性交给投影 |
| 几何精度 | 低（Segments 14–28） | 高精度 | 手机上省 GPU，剪影风格下看不出差别 |
| 阴影 | 真实方向光投影 | 假圆片接触阴影 | 长投影是白色场景的主要形状信息，假影做不到 |

## 五、已知限制

1. 角色侧面剪影仍偏"柱状"：虽已有膝肘关节，但胸腔与骨盆没有前后错落，侧看轮廓变化有限。
2. 竖屏地平线很淡，白世界固有代价。
3. 方块有碰撞，但散石没有（可以踩过去）；世界没有边界。
4. 阴影只在角色周围 ±26m 内有效，更远的方块无投影（被雾遮住，不易察觉）。
