## 一、世界设定

第一天，只有三样东西：

1. **一片白地** —— 没有尽头，没有地形起伏。
2. **一片白天空** —— 没有太阳、没有云、没有地平线上的山。
3. **一个人** —— 深色，站着，会走会跳。

除此之外散落着一些白色的方块，它们没有功能，只是让这片空白有了尺度。

设计意图：世界越空，人的存在感越强。观众第一眼应该看到那个黑色的小人，而不是"一个游戏场景"。

## 二、视觉语言

### 2.1 色彩

全场景只有三个明度层，没有彩色：

| 层 | 值 | 用途 |
|---|---|---|
| 天 | `#FFFFFF` | 背景、天空 |
| 物体亮面 | 约 `#FAFAFA` | 受光的地面与方块顶面 |
| 物体暗面 | 约 `#CCCCCC` | 背光面、投影 |
| 人 | `#8B8F95` | 中灰白模，哑光；靠投影与分块形体从地面里分出来 |

**没有任何饱和色。** 需要区分层次时，只调明度，不加色相。

### 2.2 立体感从哪来

白色世界里没有颜色对比，形体只能靠两件事建立：

1. **方向光的明暗面差** —— 方块朝向光源的面接近纯白，背光面落到浅灰。
2. **投影** —— 长投影（约 1.5 个身位）是白色场景里最强的形状信息。

因此布光比例很关键：环境光决定投影的浅度，方向光决定面的反差。调反了整个世界会糊成一片白。

### 2.3 地平线

天和地都是白的，分界不能靠颜色差硬做。做法是：

- 天空纯白 `#FFFFFF`
- 雾色比天空**略暗**（`#F1F5F8`）
- 地表随距离渐变成雾色

于是在远处自然浮现一条极淡的分界带。**对比度必须很克制** —— 压过头就变成"灰色山脊"，失去白世界的干净。

### 2.4 形体语言

- 角色：**ALS 原版 AnimMan 网格**（10269 顶点 / 16544 面），哑光灰，无贴图。来自本地 ALS 项目的 `AnimMan.uasset`，用 UE 5.8 命令行导出 FBX 取得（见 `refs/AnimMan.fbx`）。
- **绑定方式**：刚性。FBX 的 Skin Cluster 给出顶点索引与权重，每个顶点归给主导权重的那根骨骼，按 15 个部位分组，每组挂一根 pivot。不是平滑蒙皮，所以关节处有分块接缝。
- 参考素材都存在 `refs/`：`AnimMan.fbx`（当前角色）、`SK_Mannequin.fbx`（UE4 标准）、`SKM_Manny.gltf`（UE5 标准）、`Proxy.fbx`（网络代理）。
- 世界：只有立方体。没有圆柱、没有斜面、没有曲线建筑。
- 一切边缘都是硬边，唯一柔和的是投影和雾。

### 3.2 场景构成

| 对象 | 数量 | 几何 | 说明 |
|---|---|---|---|
| 地面 | 1 | `PlaneGeometry(300)` | 旋转 −90°，接收阴影 |
| 大积木 | 72 | `BoxGeometry` | 半径 11–87m 环形散布，部分高 2.5–5.3m |
| 小散石 | 240 | `InstancedMesh` 同一个 Box | 半径 1.6–43m，单个 draw call |
| 远处高塔 | 11 | `BoxGeometry` | 42–88m，高 6–15m，不投影只接收 |
| 角色 | 1 | 24 个基础几何体 | 头+鼻+颈+胸廓/腹/骨盆+双三角肌，四根两节肢体各带关节球 |

分布用**确定性伪随机**（`hash(i, salt)` = `sin` 哈希），不存数据、每次刷新世界相同、可以靠调 salt 重排。

### 3.3 光照

```
HemisphereLight  白色天光 + 微冷地面色，强度 1.45   → 决定"阴影有多浅"
DirectionalLight 白色，强度 1.84，位置角色偏移 (10, 10.5, 9) → 决定"面有多分明"
```

- 方向光**跟随角色**（`sun.position = 角色位置 + 固定偏移`），保证投影贴图始终覆盖角色周围 ±26m。
- 阴影贴图 2048²，`PCFSoftShadowMap`，`normalBias 0.018`。

**踩过的坑**：改完 `shadow.camera.left/right/top/bottom` 必须手动调 `updateProjectionMatrix()`，否则仍是默认的 ±5 范围，除角色脚下外全场无投影。

**关于强度**：Three.js r155 之后是物理光照，`MeshStandardMaterial` 的漫反射带 `1/π`。要让白色地面接近纯白，各光源强度之和要到 3.0 量级；按老经验给 0.8 会整片发灰。

### 3.35 动作系统：源自 ALS

角色动作不是凭感觉调的，而是照 [ALS-Community](https://github.com/dyanikoglu/ALS-Community) 的 C++ 实现复刻。

**核心是倾斜（Lean）**。ALS 的 `CalculateRelativeAccelerationAmount()` 把加速度按角色朝向反旋转到局部空间，再按 `MaxAcceleration` / `MaxBrakingDeceleration` 归一化到 ±1：

```
RelativeAcceleration = clamp(Acceleration / MaxAcc, -1, 1)   // 在角色局部空间
LeanAmount.FB = InterpTo(当前, RelativeAcceleration.X, dt, 4.0)   // 前后
LeanAmount.LR = InterpTo(当前, RelativeAcceleration.Y, dt, 4.0)   // 左右
```

这两个量驱动身体前后压和左右侧倾，于是起步前压、急停后仰、转弯侧倾——这是 ALS "有重量"的手感来源。

本项目对应实现：`P.leanFB` / `P.leanLR`，用 `(vel - prevVel)/dt` 取加速度，旋转到角色局部后除以 `MAX_ACC = 20` 归一化，再指数平滑。倾斜应用系数前后 0.34 rad、左右 0.26 rad。

**前提条件**：移动必须是恒定加速度。指数趋近产生的加速度是脉冲式的（速度一到位加速度就归零），倾斜来不及积累就衰减了。

### 3.36 动画系统：真蒙皮骨骼 + ALS 原版曲线（v0.9.1）

姿态不用 sin 函数摆，也不是部件拼接，而是**真蒙皮骨骼播放 ALS 手 K 动画**。

**为什么必须蒙皮**：v0.8 的做法是按主权重把网格切成 15 块挂到关节上（刚性绑定），骨骼一弯部件之间就露缝——腰胯鼓包、锁骨断层、脚踝脱开。蒙皮（顶点带 4 骨权重）是唯一能让关节连续变形的办法。

**角色数据**（`tools/anim/build_rig.cjs`，从 `refs/AnimMan.fbx` 提取）：

- 10269 顶点 / 16544 三角形，单 `SkinnedMesh`，不切块
- 68 根骨骼（含 clavicle、ball、neck、spine_01~03），绑定矩阵取 Cluster 的 `TransformLink`
- 每顶点最多 4 骨影响，权重归一化，0 个未分配顶点

**动画数据**（`tools/anim/bake_full.cjs`）：

- 每骨每帧**绝对局部旋转**四元数（真骨架的局部坐标系就是 FBX 骨骼坐标系，不需要 delta 共轭）
- 与绑定姿态对比：既不动又同姿态的骨不带走；静止姿势压成单帧；手指骨跳过
- 骨盆只保留上下起伏，水平位移丢弃（位移由游戏移动逻辑负责）
- 规模：25–32 骨 × 8 动画 = 404KB

**运行时结构**：

- 状态机 `idle / walk / run / sprint / 起跳 / 下落 / 落地`；落地是一次性动画，占用 0.32s 后交还状态机（见 3.38）
- 跨动画切换 0.18s 四元数 slerp 混合；未参与当前动画的骨回到绑定姿态
- 播放速率 = 实际速度 / 动画原生步速（walk 1.5 / run 3.5 / sprint 6.0，v0.11.6 校准到 ALS 源码基准 150/350/600 cm/s；填错了就是匀速滑步）
- 冲刺（v0.11.5）：目标速度 4.5 → 6.5；键盘 `Shift` 按住、手机快跑按钮（v0.11.6，触屏设备显示的切换按钮）。v0.11.7 删掉了推满自动冲刺——两个入口并存时按钮形同虚设。进 sprint 动画需要速度先过 4.2 m/s，避免起步阶段在 run/sprint 之间来回跳
- Lean 仍在 `bodyPivot` 上叠加，与动画正交

**方法论差距的说明**：ALS 完整系统还有 BlendSpace 八向混合、动画同步组、脚步 IK、Turn In Place、上下半身分层。当前是"按状态切单动画"，是复刻的第一步；八向（LF/RF/LB/RB）资产已具备，接入只差状态机细分。

### 3.37 音效：ALS 原版录音，内嵌不分包（v0.11.4）

**结论先说**：v0.10 那版是纯 WebAudio 合成（噪声 + 滤波 + 包络），实测听感"像电子音、不写实"，用户明确否决。噪音合成做不出真实混凝土脚步的瞬态颗粒，这是方法上的天花板，不是参数没调好。所以按 `RULES.md` 第 6 条走第二档：取 ALS 项目里的原版录音。

**素材来源与处理**（`tools/sfx/_sfx.js`）：

- ALS 的 `.uasset` 里直接内嵌了原始 WAV（96kHz 单声道），把 RIFF 段切出来即可，不需要引擎
- 处理：去首尾静音 → 降到 16kHz 单声道 16bit → 全组统一增益（保持走/跑的相对轻重）
- 13 个片段共 **111KB base64**，内嵌进 `world01.html`，仍然零外部引用

| 用途 | 录音 |
|---|---|
| 走 | `Concrete_Walk_01~05` |
| 跑 | `Concrete_Run_01~04` |
| 起跳 / 落地 | `Concrete_Step_01~03` + `Concrete_Pivot_02` |

ALS 原版的跳跃和落地也是播脚步 Notify，所以复用 Step 集是符合原版行为的，不是偷懒。

**同步**：用 `createBufferSource` + `AudioBuffer` 在动画事件那一帧直接 `start()`，延迟只剩音频硬件本身的几毫秒。合成版每段噪声都有几十毫秒的起振时间，听感就"慢半拍"——这也是"不同步"的来源。

**播放**：每个动作随机选一个变体，`playbackRate` 在 0.95–1.05 之间微随机，音量按步态递进（走 0.85 / 跑 1.0 / 落地随冲击 0.8–1.1），避免机械重复。

实测（`__audioState()` 的 `peak`，页面内 rAF 连续采样）：跑动峰值 0.92，即录音本身的电平，不做额外压缩。

**解锁路径**（手机不出声几乎都是这一层的问题，不是合成的问题）：

1. **`AudioContext` 只能在手势里创建**——非手势创建的实例，iOS 上 `resume()` 会返回成功但状态永远停在 `suspended`。所以 `audioReady()` / `update()` 兜底一律不新建实例，只 `resume`；发现实例不是手势建的，第一次真手势时关掉重建
2. 手势里真播一次 1 帧空 buffer（iOS 光 resume 不响）
3. `navigator.audioSession.type = 'playback'`（绕开 iOS 侧边静音拨片）
4. `WeixinJSBridgeReady` 后再试一次（微信内置浏览器）+ `visibilitychange` 切回前台时重新 resume
5. 连续两次手势仍不 running → 关掉重建 `AudioContext`
6. 真起不来才在右下角显示提示，并把实际的 `state` 写进去（如 `suspended`），正常时这块 DOM 不显示

**备用播放链路（v0.11.3）**：有些 webview 直接拦掉 WebAudio 的输出，`state` 永远是 `suspended`，`resume()` 也没用。这时把同一批录音交给 `<audio>` 元素播（data URI），第一次手势里静音播一次解锁元素。两条链路音源相同，听感一致。

**脚步时机**：不靠计时器拍脑袋，烘焙动画时用 FK 算 `foot_l`/`foot_r` 每帧世界 Y，取局部极小值（阈值 = 最小值 + 8% 幅度、间隔 <0.16s 合并、首尾跨循环去重）作为触地事件，写进动画数据的 `steps` 数组。运行时按动画时间轴跨事件点触发，与播放速率、循环回绕都解耦。

**注意**：ALS 动画里的 `Mask_FootstepSound` 曲线是空的（实际用 Animation Notify 派发），所以不要指望从曲线拿事件。

### 3.38 跳跃：三段式，空中不踏步（v0.11.0）

**问题**：v0.10 的空中全程播放 `ALS_N_JumpLoop`，而那是个**跑动起跳**的循环——脚前后行程 63–70cm、脚抬到 65cm。角色在空中没有对应位移，脚就在原地划，观感就是"滑步"。

**做法**（对齐 ALS 的三段结构）：

| 阶段 | 动画 | 说明 |
|---|---|---|
| 起跳（上升段 vy>0.2） | `JumpWalk_LF/RF`，快跑时 `JumpRun_LF/RF`（v0.11.5） | 按起跳瞬间速度选：>4.8 m/s 用跑跳；左右脚每次交替 |
| 下落（vy≤0.2） | `FallLoop` / `FallLoop_Fast` | 脚行程只有 7cm，**几乎不动**，滑步感消失 |
| 落地（跑跳，水平速度 >1.8） | **不播落地片段** | 腿还在跑，硬塞"脚钉住"的姿势必然滑；只留压扁 + 音效 |
| 落地（原地/慢速，≤1.8） | `Land_Light` / `Land_Heavy` | 脚真踩住了，完整播，占 0.55s |

**关键取舍**：

- 不用 JumpLoop 了。它只在"角色真的以起跳速度前冲"时才成立，我们的空中不锁速度，用它必然划
- 起跳片段只烘焙前 22 帧（0.7s），上升段实际只用前 ~0.35s，裁掉后半省 43% 体积
- 空中 `ACC` 降到 30%，水平惯性保留——起跳后不会突然刹停，跳出去的距离和动画的腿部动作对得上
- 落地不再锁满 1.2s 整段，否则落地后继续前进会变成"脚不动但人在滑"
- 跑跳落地干脆不播落地片段：脚钉住的动画和位移天生对不上，这是"没有下半身分层"时的取舍。真要两全，得做 ALS 那样的上下半身分层（腿走跑步循环、上身播落地压缩），还没做
- **起跳 → 下落用 0.30s 混合**（其他切换仍是 0.18s）：`JumpRun_*` 的反侧手会摆到头顶以上 33cm，切得太快像被拽下来

**仍存在的差距**：ALS 有 JumpApex 段和起跳的 root motion（位移由动画驱动）。FBX 里没有 pelvis 水平位移曲线，所以这里只能靠物理速度，脚与地面的严格吸附做不到。

### 3.4 相机模型

绕角色的球面轨道，三个量：

```
camYaw    水平角，0 表示位于角色正后方
camPitch  俯角，夹在 0.06–1.00 弧度（3°–57°）
camDist   距离，横屏 8.6 / 竖屏 9.9
```

相机位置（枢轴在肩点，居中不偏移）：

```
pivot  = follow + (0, 1.42, 0)
pos    = pivot + ( sin(yaw)·cos(pitch),
                   sin(pitch),
                   cos(yaw)·cos(pitch) ) × dist
lookAt = pivot
```

`follow` 是对角色位置的平滑跟随（lerp 系数 4.2），转视角本身不平滑（要跟手），只有位置跟随平滑。

**移动方向必须相机相对**：`forward = (−sin(yaw), −cos(yaw))`、`right = (cos(yaw), −sin(yaw))`。这一步漏掉的话，转完视角按前进还往老方向跑。

#### 3.41 三种取景：第一 / 第三 / 自由（v0.11.21 → v0.11.29）

`viewMode` 0/1/2 = 第一人称 / 第三人称 / 自由视角（**默认，v0.11.34 起**）。都是同一台透视相机，只是位置来源不同，所以能直接按权重混合：

```
wF = fpBlend          第一人称权重
w3 = 1 − wF           轨道权重（第三人称 · 自由视角，和恒为 1）
pos    = tp·w3 + eye·wF
lookAt = tpT·w3 + fpT·wF
```

| 档位 | 位置 | 注视点 | 拖动 | 缩放 |
|---|---|---|---|---|
| 第三 | 肩点枢轴 + `dir(camYaw, camPitch) × camDist` | 肩点 | 水平 + 俯仰 | 无 |
| 第一 | `P.pos + (0,1.62,0)` | 视线方向 12 m 外 | 水平 + `fpPitch` | 无 |
| 自由 | 同第三，俯仰/距离换成 `freePitch`/`freeDist` | 肩点 | 水平 + 俯仰（±1.45） | 滚轮 / 双指 1.5–60 m |

- **为什么按权重相加而不是状态机**：状态机在"从轨道切第一人称"时会先回到某个中间状态（两个量分别在动），权重相加天然经过中间高度，镜头是一条连续曲线。
- **第一人称**：独立 `fpPitch`（±1.15 rad），不动 `camPitch`；身体朝向 `camYaw + π`，否则侧着走；`fpBlend > 0.45` 隐藏自身网格（0.7 时相机已经在体内）。
- **枢轴在肩点 1.42 m**：挂胸口会让滚轮拉到最近时镜头停在腹部（用户报过「相机在肚子这里」）；挂眼睛那是第一人称的事。机位不再额外抬高，枢轴就是基准。
- **自由视角（v0.11.23 加，v0.11.29 由「全视」改名）**：复用第三人称的球面轨道，只把 `orbitPitch` / `orbitDist` 换成 `freePitch` / `freeDist`。
  - **默认落点是旧俯视全景**（v0.11.33）：俯角 `0.66`（约 38°）、机距横屏 `23` / 竖屏 `20`——就是 v0.11.29 删掉的 `TOP_PITCH` / `TOP_DIST`。进这一档的目的是"先看见全貌，再自己转"，从第三人称原样接过来只会让人以为它只是"能转的第三人称"。
  - **不硬切**：0.55 s 内从当前取景滑到落点（`freeIntro`），任何用户输入（转俯仰 / 滚轮 / 捏合）立刻清 0 取消，不跟人抢操作。
  - 滚轮 `Math.exp(deltaY × 0.0011)`；双指按"起始指距 × 起始距离 / 当前指距"**直接设值**，不累乘（累乘会飘）。
  - **俯仰方向和第三人称一致**（v0.11.31）：`freePitch += dy`，下拖 = 镜头抬高低头看。曾经写成 `-=`，两档手感相反。
  - **捏合按区域判定**（v0.11.30 → v0.11.31）：
    - 只有"看到两根手指"就捏合，会把"左手摇杆 + 右手拖动"当成缩放，两个操作一起废掉；
    - 但反过来"有摇杆就不许捏合"，又让"边走边缩放"做不了；
    - 最终规则：**捏合 = 右半屏凑够两根手指**。左半屏永远归摇杆，不参与判定；捏合用显式 `pinch.a/b` 记两根手指，`pointermove` 只拦截这两根，摇杆手指照常驱动走路。三种组合可以同时存在：走 + 转 + 缩。
    - 捏合抬起一根后，右半屏剩下的那根接着当转视角用（`look.dragging = true`，避免抬手被判成轻点跳跃）。
  - 最近 1.5 m（最短臂长挡住，不把"拉到底"做成第一人称：眼睛朝向与轨道朝向是两套控制模型，混起来最近处会突然换手感）。
  - 能翻到地平线以下，但不能钻到地下：按当前机距反算最低俯角 `asin((0.35 − follow.y − 1.42) / dist)`，机距越大允许越低，拉近了自动抬起来；再加 `camera.y < 0.35` 兜底。
  - **45° 视角锁定**（v0.11.35 加 / v0.11.37 补全）：僵毁那类等距生存游戏的取景。**俯角焊死 `π/4`、水平角焊死**，缩放照常；这就是固定的斜 45° 俯视取景。
    - 僵毁经典相机其实是**固定俯角 + 只能 90° 步进转**，官方没公布精确角度，社区按 45° 左右理解；B42 换了可调相机，默认还更低。这里借"整个镜头不跟着角色转"这一条。
    - **水平锁在哪**：`lockYaw = camYaw`，即**按下按钮那一刻的朝向**，不跳镜头。想换方向先解锁转好再锁。这是 v0.11.37 补的——v0.11.35 只锁了俯角，水平还能转，不叫"固定视角"。
    - `turnBy` 在 `freeMode && freeLock` 时忽略 `dx` 和 `dy`；键盘 `Q`/`E` 也禁掉，否则从键盘还能转。第一/第三人称不受影响。
    - 收敛用**每帧 easing** `k = min(1, dt×6)`：`freePitch += (LOCK_PITCH − freePitch)×k`、`camYaw += dyaw×k`，其中 `dyaw` 先归一到 `±π`（跨 `±2π` 边界不归一就会绕远路整圈转回来）。不复用 `freeIntro`：那个过渡会被缩放取消，取消后角度永远卡在半路。
    - 锁定时 `toggleView` 的落点取 `LOCK_PITCH`；锁定是偏好，跨视角保留，切出去转一圈再回来会平滑收敛回 `lockYaw`。
    - 桌面没有按钮，用 `L` 键（`T` 是主题切换）。
  - **遮挡不拉近，改半透明**（v0.11.32）：这一档的机距是用户自己滚出来的，被塔一挡就拽到 0.9 m、松手再缓缓退回，等于镜头跟人抢控制权。所以自由视角里 `camBlockGoal` 恒等于 `effDist`，命中的物体材质换成 `ghostMat`（`opacity 0.26`、`depthWrite = false`），走开还原。第三人称仍走"拉近到 0.9 m"那套——它的机距是程序给的，压一下不心疼。
- **遮挡处理的两种策略**（按档位分，不要混）：

  | 档位 | 相机怎么办 | 挡在中间的东西 |
  |---|---|---|
  | 第三 | 沿视线拉近（最短 0.9 m），离开缓慢恢复 | 不动 |
  | 自由 | **不动** | 换 `ghostMat` 半透明，离开还原 |
  | 第一 | 不处理 | 不处理 |

  两套名单 `keep` / `occluded` 在 100 ms 的射线回调里交替维护：先还原已出名单的，再给新名单上材质，顺序反了会闪一下。
- **删掉的东西**（别翻案）：
  - **正交投影（v0.11.33 加 / v0.11.39 删）**：`orthoCam` / `activeCam` / `orthoMode` / `#projBtn` / `O` 键整套移除，渲染回到单台透视相机。用户判定不需要；而且正交没有透视收缩，机距 20 m 时视野只覆盖约 18 m，出生点的房子会跑出画面上边，和这个世界的取景逻辑合不来。
  - **俯视（v0.11.29 删）**：整套透视俯视移除（`topMode` / `topBlend` / `TOP_PITCH` / `TOP_DIST` / 权重 `wT`）。它的半透明遮罩思路留下来了，在 v0.11.32 挪给了自由视角。
  - **越肩（v0.11.27 加 / v0.11.29 删）**：横向偏移在手机上把横向空间让给了空白区域，用户判定不适合，先不做。`PIVOT_H` 抬到肩点这件事保留。

#### 3.41.1 桌面鼠标：指针锁定（v0.11.41）

用户要求 RPG 式：不要按住左键拖，而是鼠标消失、移动即转视角。

- 点画面调 `canvas.requestPointerLock()`；`pointerlockchange` 维护 `plLocked`；锁定态 `pointermove` 直接读 `movementX / movementY` 交给 `turnBy`，不再依赖 `mouse.down`。
- 未锁定仍保留按住拖动的路径作为兜底——iframe 或浏览器策略拒绝锁定时不至于完全不能转。
- `pointerlockerror` 把 `plLocked` 置回 false；`requestPointerLock()` 返回 Promise 时挂 `.catch()`，避免未处理拒绝污染控制台。
- 手机端不受影响：整条路径由 `pointerType === 'mouse'` 守着。

#### 3.42 地面网格：着色器画，不用 GridHelper（v0.11.21）

`GridHelper` 被否掉过——远处线挤进同一个像素就是摩尔纹横条。现在用 `onBeforeCompile` 往标准材质里注入：

```
vec2 g = worldXZ / scale;            // 1 m 细线 / 5 m 粗线
vec2 d = abs(fract(g - 0.5) - 0.5) / fwidth(g);
line = 1 - min(min(d.x, d.y), 1);    // 线宽固定 ≈ 1 像素
k = (1 - smoothstep(0.12, 0.55, pxSize)) × (1 - smoothstep(26, 78, dist));
```

- `fwidth` 让线宽恒定 1 像素，所以不管多远都不会"变密"。
- 再按"一个像素覆盖多少米"衰减：掠射角时一个像素能覆盖好几米，线必然糊成一片，直接让 `k → 0`。
- 世界坐标取样，所以地面跟着角色平移时网格是静止的。
- 强度只有 0.07 / 0.10，混向 `vec3(0.55,0.60,0.66)`——只提供尺度感，不抢主体。

#### 3.43 碰撞：2.5D（圆柱 vs 竖直棱柱）（v0.11.22）

世界里所有实体都是竖直棱柱，所以不需要 3D 刚体，也不需要物理引擎：

```
水平：把角色位置转到盒子局部坐标 → 圆(r=0.36) vs 矩形(hw,hd)：
      最近点 → 若距离 < r，沿法线推出；再把速度在法线上的分量清零（贴墙滑）
垂直：脚下支撑高度 = max(0, 所有"覆盖脚下 XZ 且顶面 ≤ 脚下+0.35"的盒子的顶面)
```

| 判定 | 规则 |
|---|---|
| 挡不挡 | `col.top - feet <= stepAllow` 就不挡（地面时 0.35，空中 0.08） |
| 站在哪 | 支撑高度；落地判定改成 `pos.y <= support` |
| 走出边缘 | `pos.y - support > 0.4` → `onGround = false` |
| 粗筛 | 每盒预算 `reach = 半对角线 + r + 0.6`，超出直接跳过 |

- **为什么空中把 stepAllow 收到 0.08**：站在地上允许"走进矮块再被抬起来"（这就是自动台阶）；空中也允许的话，跳到方块侧面时会先钻进体积里再被抬上去，视觉上穿模。
- **为什么站立判定放宽 0.28m**：脚踩在边缘上、或站在两个盒子接缝处时，严格判定会让支撑高度在两格之间跳变 → 人上下抖。
- **贴墙摩擦（v0.11.26）**：法向清零、切向保留 = 标准贴墙滑，但方块是随机旋转的，"撞正"几乎不发生，于是按着前进会被一路蹭到方块边缘再绕过去。现在补一层摩擦：
  ```
  press = −(目标速度 · 墙法线)        // 有多想往墙里钻
  切向速度每秒衰减 WALL_FRIC × press  // WALL_FRIC = 3.5
  ```
  - **必须是目标速度**，不能是当前速度的法向投影：上一帧法向已被清零，这里只剩一帧重新加速的量（≈ a·dt），按它算摩擦等于没有。
  - 只在 `onGround` 生效；空中蹭墙不减速，免得跳跃贴墙时突然刹车。
  - 效果曲线：0–30° 顶住（0→1.31 m 后基本不动），45° 以上照常滑行（≈ 满速）。
  - **拐角没处理**：最近点从面变角点时法线跟着转，人还会被抹过拐角。摩擦已经把"正面被送到边缘"的概率压得很低，暂时不动。
- **代价**：83 个盒子 × 2 次遍历 × 120Hz，粗筛之后实际每次只有个位数盒子参与，手机满帧无变化。

#### 3.44 出生点台阶：测试道具，不是景观（v0.11.24）

出生点正前方 2.7m 摆了三级 0.30m 台阶（每级 0.55m 深、2.6m 宽），顶上一个 0.90m 平台。参数是照着碰撞阈值挑的：

| 参数 | 值 | 目的 |
|---|---|---|
| 每级高 | 0.30 m | < `STEP_UP`(0.35) → 能自动迈上去 |
| 平台高 | 0.90 m | > `STEP_DOWN`(0.40) → 走出边缘真掉下去，不是踩下去 |
| 与出生点距离 | 2.7 m | 一眼看见，直走 0.6 秒就上第一级 |

- **只登记碰撞体，不进 `blockers`**：台阶才 0.9m，如果参与相机防穿模，站在台上镜头会被顶到脸上。
- **试过绕 20° 摆**（想让踏步侧面更好看），实测正对镜头时整组变成一块白板还挡住正前方，改回 0°。
- 这是临时测试道具，测完手感就该撤掉——它不属于这个世界。

#### 3.45 出生点小屋：僵毁式一层的郊区住宅（v0.11.34）

世界从「一堆白方块」到「有人住过」只差一栋房子。参照《僵尸毁灭工程》郊区住宅的原型：一层、坡屋顶、贴着主屋的车库翼、门廊、车道、栅栏小院。全部是 `BoxGeometry` + 一个 `ExtrudeGeometry`（山墙屋顶），没有一块贴图。

坐标系：出生点原点，台阶朝 −z（北）。房子的院子在出生点正前方 `z ∈ [-24, -9]`，`x ∈ [-9, 7]`，南墙（`z=-9`）朝出生点。

| 部件 | 尺寸 | 位置 | 备注 |
|---|---|---|---|
| 主屋 | 8 × 6 × 3 m | 中心 (−3, −19.5) | 山墙屋顶 +1.45，挑檐 0.4 |
| 车库翼 | 3.7 × 5.5 × 2.7 m | 中心 (2.85, −19.25) | 贴主屋东墙；山墙屋顶 +0.8，脊线同向 |
| 门廊 | 2.6 × 1.6，台高 0.3 | 前门正前 | 0.3 < `STEP_UP`，直接走上去；雨棚单坡 −0.07 rad |
| 车道 | 2.5 × 10.5 | 从车库门穿出院墙到 z=−6 | 0.06 厚 `stoneMat` 板，无碰撞 |
| 栅栏 | 0.95 高，柱距 ~1.7 | 院子四边 | 南墙留两个口：车道 1.6–4.1、院门 −3.2–−2.0 |
| 树 | 干 0.3×2.0 + 两层冠 | 前院两棵 | 冠用 `IcosahedronGeometry(…,0)` 压扁，正球像雪球 |

**几个不能省的细节**：

- **屋面必须比墙暗一点点**（`roofMat 0xe7eef5` vs `propMat 0xf4f7fa`）。纯白世界里屋顶和墙同色时，从高处俯视整个屋顶糊成一块，看不出坡面。
- **门窗是贴在墙面上的深色面片，不在 `blockers` 里**。代价是自由视角把它们变半透明时，这些面片会剩下几块深灰方片飘在空中——所以给墙体挂了 `userData.trim` 列表，遮罩时一起 `visible = false`。
- **烟囱从屋面穿出 0.7 m**，位置在 x 方向偏脊 2.3 m、z 方向偏中心 1.8 m，正好在坡面中段。
- **散石和积木要避开院子和车道**（`inYard` / `inDrive`）。随机撒点不看边界的话，房子里会长出积木、车道上会长出石头。
- **屋顶进 `blockers` 但不要碰撞体**：3 m 墙 + 坡屋顶，跳不上去（跳跃上限 1.07 m），登记碰撞只是浪费逐帧粗筛。
- **小构件必须合批**（v0.11.36，踩过坑）：第一版给每根栅栏柱、每条横板、每扇窗都 `new THREE.Mesh()` 且全开 `castShadow`，**每帧 draw call 从 39 涨到 190**——每个独立 Mesh 主画面一次、2048² 阴影贴图再一次，手机上走路明显掉帧。

  | 版本 | 每帧 draw call |
  |---|---|
  | 无房子（v0.11.33） | 39 |
  | 房子逐个建（v0.11.34/35） | 190 |
  | 合批后（v0.11.36） | 62 |

  规则：**只有遮挡射线要按对象换材质 / 挂 `userData.trim` 的才配单独存在**（两片墙、两片屋顶、四块树冠、门窗面片）；其余统一进 `InstancedMesh(unitBox, propMat)`，用 `Object3D` 摆位置/缩放/倾斜后 `setMatrixAt`。车库卷帘门的四条横槽单独合成一个小 `InstancedMesh`，作为一个 `trim` 整体隐藏。贴墙薄面片关 `castShadow`；碰撞体只传 `{position, rotation}` 字面量，别为它造不渲染的 Mesh。

#### 3.51 手机按钮：药丸，不是圆（v0.11.33）

原来右上角是 58 px 的圆、右下角 66 px 的圆，里面只放两个字（快跑 / 第三），相当于用一个正方形的面积装 24 px 的文本。屏幕上常驻三块白斑，在白世界里尤其抢眼。

改成统一的 `.pill`：

| 项 | 值 | 理由 |
|---|---|---|
| 高 | 34 px | 单行字够用；再矮就成了链接，手指点不准 |
| 左右内边距 | 13 px | 两字 + 26 = 51 px 宽，比 58 的圆还窄 |
| 圆角 | 999 | 全圆角，和世界里的方块形成对照（世界是硬的，UI 是软的） |
| 字号 / 字重 | 12 / 600 | 和底部提示的 11.5 拉开层级 |
| 底色 | `rgba(255,255,255,.88)` + 极淡投影 | 纯白背景上必须有边界，但不能有硬边 |

- **只点亮真正的开关**：快跑（开/关）、45° 锁定（开/关）、主题（深色=点亮）用 `.on`；视角按钮是循环，**不点亮**，靠文字本身（第一 / 第三 / 自由）表达状态——否则它看起来像个永远开着的开关。
- **45° 按钮只在自由视角出现**：其他两档没有这个概念；主题按钮则任何视角都在（切主题和视角无关）。
- 右上三枚依次是 视角(+14) / 45°(+56) / 主题(+98)；删掉正交后 45° 顶了原正交的位置。
- **快跑下移到提示文字上方**：药丸变矮之后原来 74 px 的位置正好压在底部三行提示上。

#### 3.52 操作说明：桌面按 `H`，触屏自动淡出（v0.11.38）

同一段说明，两端的行为不一样，因为输入方式不一样：

| | 桌面 | 触屏 |
|---|---|---|
| 初始 | 收起（`opacity 0`） | 摊开（`opacity 1`） |
| 关闭方式 | 按 `H` 再收起 | 9 s 后自动淡出 |
| 常驻提示 | 右上角 22×22 的 `H` 徽标 | 无（没键盘） |
| 过渡 | 0.18 s（手动切换要利落） | 1 s |

- **`hideTip()` 在桌面直接返回**：`V`/`O`/`L`、点画面、滚轮、切按钮都会调它；不短路的话，说明会一按任意键就消失，或者自己弹出来。桌面只由 `setTip()` 管。
- `#tip` 的 CSS 默认 `opacity: 0`（不是靠 JS 在首帧关掉），避免桌面加载瞬间闪一下说明；触屏分支初始化时置 1。
- 徽标 `pointer-events: none`，不抢右半屏的鼠标拖动；展开时点亮（`.on`）作为状态反馈。
- **判端用 `TOUCH_UI`**（`matchMedia('(pointer: coarse)')`），和那四枚按钮同一个来源，不会出现「按钮是触屏、说明是桌面」的错配。


#### 3.53 两套主题：深色（默认）/ 白色（v0.11.39）

白色世界是立项命题，所以深色不是"把白色抹掉"，而是并列的另一档，`T` 键 / 主题按钮随时切回。

| | 白 | 深色 |
|---|---|---|
| 天空 / 雾 | `#ffffff` / `#f1f5f8` | `#0d1116` / `#18212b` |
| 地面 / 积木 | `#ffffff` / `#f4f7fa` | `#1c242e` / `#424e5c` |
| 角色 | `#8f93a8` | `#d2dce7` |
| hemi + sun | 1.45 + 1.84 | **0.62 + 0.80** |

- **深色档光强必须降**：物理光照下白世界靠 3.0 量级把材质打到近白，深色材质沿用会被洗成浅灰。这是深浅两档唯一的非颜色差异。
- **CSS 全走变量**（`--bg / --panel / --ink / --shadow / --on-bg`），切换只改 `<html data-theme>`；`theme-color` meta 跟着换（移动端状态栏）。
- **房子专用材质在 `house()` 内部**，注册到 `HOUSE_MATS` 才能被 `applyTheme()` 访问；地面网格线的颜色做成 shader uniform `uGridColor`，切主题只改 Color 对象、不重编译。
- `ghostMat` 是 `propMat.clone()`，两档透明度分别 0.26 / 0.30；还原遮罩用 `userData.baseMat`，所以切主题后被遮物体也不会掉色。


#### 3.54 攀爬：ALS Mantle + 代码位移（v0.11.40）

素材直接在 ALS 工程里找，不自己摆姿势：`Actions/ALS_N_Mantle_1m_RH`，烘焙成 `__ANIMS.mantle`（1.5333 s / 47 帧 / 32 骨）。

- **触发**：`doJump()` 先 `tryClimb()`，命中就不进起跳缓冲。键盘空格和手机轻点都走 `doJump()`，两端共用一条判定，没新增按键。
- **判定**：沿 `P.face` 探 0.30–1.20 m，找 `top − feet ∈ [0.45, 1.25]` 且 `hw/hd ≥ 0.30` 的碰撞体。下界避开"自动迈台阶"，上界是 1m 撑上动作的合理上限，最小顶面尺寸把栅栏这类薄片排除（站不住）。
- **落点**：沿朝向继续走，取最后一个仍在顶面的位置，再回退 10 cm。**不能用安全边距当判据**——命中点本身就在盒子边缘，一加边距就永远「站不住」，这是这版踩的坑。
- **位移**：ALS 动画只带骨骼旋转，没有 root motion，位置由 `advanceClimb()` 插值。**必须分两段**（v0.11.41 修）：一条直线从起点插到顶面，45° 的斜线会穿过棱柱侧面，看着就是人从方块里钻过去。

  | 段 | 占比 | 轨迹 |
  |---|---|---|
  | ① 撑起 | 前 52% | 起点 → 外层表面外 `PLAYER_R`（`hitS − PLAYER_R`）、顶面 +0.06 |
  | ② 翻上 | 后 48% | 该点 → 顶面落点 |

  第一段上升时身体一直在盒子外侧，第二段开始时已经高于顶面，水平推进不会穿。
- **物理冻结**：`update()` 的物理整段包进 `if (climb) advanceClimb(dt); else { … }`。否则重力会把上升中的角色拽回地面、`collideXZ` 会把他从盒子里推出去。朝向/倾斜/动画状态机等公共部分留在 `if` 外照常跑；相关的 `sp / prevVX / prevVZ / sprint / tx / tz` 在开头先给默认值。
- **动画交接**：`setAnim('mantle', 1, true)` 用现成的 `ANIM.oneShot`，播放期间状态机不抢；`driveAnim` 只对 walk/run/sprint 触发脚步音，mantle 不会误播。


#### 3.55 碰撞体积可视化（v0.11.41）

调试工具，用来核对「看到的模型」和「真正挡人的形状」。`C` 键 / 手机第四枚按钮切换。

- 数据源就是 `colliders` 本身（没有第二套碰撞数据），把每个棱柱按 `hw / hd / top / yaw` 重建成 8 个角点、12 条边。
- 全部合并进一个 `BufferGeometry` + `LineSegments`：96 个碰撞体 → 2304 顶点、**1 次 draw call**，不增加逐帧开销。
- `depthTest: false` + `renderOrder 990`：被墙挡住的碰撞盒也看得到。玩家胶囊（r 0.36 / 高 1.86）每帧跟随 `P.pos`，是判断攀爬穿模最直接的参照。
- 只在需要时构建（首次开启才建），关掉只切 `visible`。

## 四、关键取舍与理由

| 决策 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 相机朝向 | 固定轨道，玩家手动转 | 自动跟随角色背后 | 自动跟随在手机上会晕，且剥夺了观察世界的自由 |
| 视野 | 三档：第一 / 第三 / 自由 | 只做第三人称；四档（含俯视） | 第一人称是沉浸工具，自由视角是观察工具，成本都只是插值一段位置；俯视在 v0.11.29 删掉——自由视角拉到高处就能替代它的观察用途 |
| 越肩偏移 | 不做（v0.11.29 删） | 横向偏移 + 枢轴抬肩 | 手机上横向空间本来就不够，偏移等于把一半屏幕让给空白；枢轴抬到肩点这半件事保留 |
| 移动方式 | 相机相对方向 | 角色相对（坦克式） | 现代第三人称的默认预期 |
| 地面网格 | 着色器画弱网格 | `GridHelper` / 网格贴图 | GridHelper 远处是摩尔纹横条；着色器按像素覆盖率衰减就没这问题 |
| 参照物 | 散石 + 方块群 | 网格、地面纹理 | 有体积感、有投影，且不形成规律线条 |
| 角色材质 | 哑光灰白模 `#8B8F95` | 深色剪影 | 用户指定参考 UE Mannequin；代价是角色不再是最强对比点，可读性交给投影 |
| 几何精度 | 低（Segments 14–28） | 高精度 | 手机上省 GPU，剪影风格下看不出差别 |
| 阴影 | 真实方向光投影 | 假圆片接触阴影 | 长投影是白色场景的主要形状信息，假影做不到 |

## 五、已知限制

1. 角色侧面剪影仍偏"柱状"：虽已有膝肘关节，但胸腔与骨盆没有前后错落，侧看轮廓变化有限。
2. 竖屏地平线很淡，白世界固有代价。
3. 方块有碰撞，但散石没有（可以踩过去）；世界没有边界。
4. 阴影只在角色周围 ±26m 内有效，更远的方块无投影（被雾遮住，不易察觉）。
