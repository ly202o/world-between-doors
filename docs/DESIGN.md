## 一、世界设定

第一天，只有三样东西：

1. **一片白地** —— 没有尽头，没有地形起伏。
2. **一片白天空** —— 没有太阳、没有云、没有地平线上的山。
3. **一个人** —— 深色，站着，会走会跳。

除此之外散落着一些白色的方块，它们没有功能，只是让这片空白有了尺度。

设计意图：世界越空，人的存在感越强。观众第一眼应该看到那个黑色的小人，而不是"一个游戏场景"。

## 二、视觉语言

### 2.1 色彩

全场景只有三个明度层，没有彩色：

| 层 | 值 | 用途 |
|---|---|---|
| 天 | `#FFFFFF` | 背景、天空 |
| 物体亮面 | 约 `#FAFAFA` | 受光的地面与方块顶面 |
| 物体暗面 | 约 `#CCCCCC` | 背光面、投影 |
| 人 | `#8B8F95` | 中灰白模，哑光；靠投影与分块形体从地面里分出来 |

**没有任何饱和色。** 需要区分层次时，只调明度，不加色相。

### 2.2 立体感从哪来

白色世界里没有颜色对比，形体只能靠两件事建立：

1. **方向光的明暗面差** —— 方块朝向光源的面接近纯白，背光面落到浅灰。
2. **投影** —— 长投影（约 1.5 个身位）是白色场景里最强的形状信息。

因此布光比例很关键：环境光决定投影的浅度，方向光决定面的反差。调反了整个世界会糊成一片白。

### 2.3 地平线

天和地都是白的，分界不能靠颜色差硬做。做法是：

- 天空纯白 `#FFFFFF`
- 雾色比天空**略暗**（`#F1F5F8`）
- 地表随距离渐变成雾色

于是在远处自然浮现一条极淡的分界带。**对比度必须很克制** —— 压过头就变成"灰色山脊"，失去白世界的干净。

### 2.4 形体语言

- 角色：**ALS 原版 AnimMan 网格**（10269 顶点 / 16544 面），哑光灰，无贴图。来自本地 ALS 项目的 `AnimMan.uasset`，用 UE 5.8 命令行导出 FBX 取得（见 `refs/AnimMan.fbx`）。
- **绑定方式**：刚性。FBX 的 Skin Cluster 给出顶点索引与权重，每个顶点归给主导权重的那根骨骼，按 15 个部位分组，每组挂一根 pivot。不是平滑蒙皮，所以关节处有分块接缝。
- 参考素材都存在 `refs/`：`AnimMan.fbx`（当前角色）、`SK_Mannequin.fbx`（UE4 标准）、`SKM_Manny.gltf`（UE5 标准）、`Proxy.fbx`（网络代理）。
- 世界：只有立方体。没有圆柱、没有斜面、没有曲线建筑。
- 一切边缘都是硬边，唯一柔和的是投影和雾。

## 三、技术架构

### 3.1 交付形态

单个 `index.html`，约 690KB，其中 670KB 是内联的 Three.js（r160 UMD 构建）。

```
<!DOCTYPE html>
  <style>   极简：全屏 canvas + 两行提示文字 + 错误提示层
  <script>  Three.js 库（内联，!function(...) 包裹）
  <script>  游戏本体（IIFE，约 500 行）
```

为什么内联：见 `RULES.md` R1。手机上把文件传来传去时，任何"旁边还有个目录"的设计都会失效。

### 3.2 场景构成

| 对象 | 数量 | 几何 | 说明 |
|---|---|---|---|
| 地面 | 1 | `PlaneGeometry(300)` | 旋转 −90°，接收阴影 |
| 大积木 | 72 | `BoxGeometry` | 半径 11–87m 环形散布，部分高 2.5–5.3m |
| 小散石 | 240 | `InstancedMesh` 同一个 Box | 半径 1.6–43m，单个 draw call |
| 远处高塔 | 11 | `BoxGeometry` | 42–88m，高 6–15m，不投影只接收 |
| 角色 | 1 | 24 个基础几何体 | 头+鼻+颈+胸廓/腹/骨盆+双三角肌，四根两节肢体各带关节球 |

分布用**确定性伪随机**（`hash(i, salt)` = `sin` 哈希），不存数据、每次刷新世界相同、可以靠调 salt 重排。

### 3.3 光照

```
HemisphereLight  白色天光 + 微冷地面色，强度 1.45   → 决定"阴影有多浅"
DirectionalLight 白色，强度 1.84，位置角色偏移 (10, 10.5, 9) → 决定"面有多分明"
```

- 方向光**跟随角色**（`sun.position = 角色位置 + 固定偏移`），保证投影贴图始终覆盖角色周围 ±26m。
- 阴影贴图 2048²，`PCFSoftShadowMap`，`normalBias 0.018`。

**踩过的坑**：改完 `shadow.camera.left/right/top/bottom` 必须手动调 `updateProjectionMatrix()`，否则仍是默认的 ±5 范围，除角色脚下外全场无投影。

**关于强度**：Three.js r155 之后是物理光照，`MeshStandardMaterial` 的漫反射带 `1/π`。要让白色地面接近纯白，各光源强度之和要到 3.0 量级；按老经验给 0.8 会整片发灰。

### 3.35 动作系统：源自 ALS

角色动作不是凭感觉调的，而是照 [ALS-Community](https://github.com/dyanikoglu/ALS-Community) 的 C++ 实现复刻。

**核心是倾斜（Lean）**。ALS 的 `CalculateRelativeAccelerationAmount()` 把加速度按角色朝向反旋转到局部空间，再按 `MaxAcceleration` / `MaxBrakingDeceleration` 归一化到 ±1：

```
RelativeAcceleration = clamp(Acceleration / MaxAcc, -1, 1)   // 在角色局部空间
LeanAmount.FB = InterpTo(当前, RelativeAcceleration.X, dt, 4.0)   // 前后
LeanAmount.LR = InterpTo(当前, RelativeAcceleration.Y, dt, 4.0)   // 左右
```

这两个量驱动身体前后压和左右侧倾，于是起步前压、急停后仰、转弯侧倾——这是 ALS "有重量"的手感来源。

本项目对应实现：`P.leanFB` / `P.leanLR`，用 `(vel - prevVel)/dt` 取加速度，旋转到角色局部后除以 `MAX_ACC = 20` 归一化，再指数平滑。倾斜应用系数前后 0.34 rad、左右 0.26 rad。

**前提条件**：移动必须是恒定加速度。指数趋近产生的加速度是脉冲式的（速度一到位加速度就归零），倾斜来不及积累就衰减了。

### 3.36 动画系统：真蒙皮骨骼 + ALS 原版曲线（v0.9.1）

姿态不用 sin 函数摆，也不是部件拼接，而是**真蒙皮骨骼播放 ALS 手 K 动画**。

**为什么必须蒙皮**：v0.8 的做法是按主权重把网格切成 15 块挂到关节上（刚性绑定），骨骼一弯部件之间就露缝——腰胯鼓包、锁骨断层、脚踝脱开。蒙皮（顶点带 4 骨权重）是唯一能让关节连续变形的办法。

**角色数据**（`tools/anim/build_rig.cjs`，从 `refs/AnimMan.fbx` 提取）：

- 10269 顶点 / 16544 三角形，单 `SkinnedMesh`，不切块
- 68 根骨骼（含 clavicle、ball、neck、spine_01~03），绑定矩阵取 Cluster 的 `TransformLink`
- 每顶点最多 4 骨影响，权重归一化，0 个未分配顶点

**动画数据**（`tools/anim/bake_full.cjs`）：

- 每骨每帧**绝对局部旋转**四元数（真骨架的局部坐标系就是 FBX 骨骼坐标系，不需要 delta 共轭）
- 与绑定姿态对比：既不动又同姿态的骨不带走；静止姿势压成单帧；手指骨跳过
- 骨盆只保留上下起伏，水平位移丢弃（位移由游戏移动逻辑负责）
- 规模：25–32 骨 × 8 动画 = 404KB

**运行时结构**：

- 状态机 `idle / walk / run / jump / fall / land`；land 是一次性动画（播完才交还状态机）
- 跨动画切换 0.18s 四元数 slerp 混合；未参与当前动画的骨回到绑定姿态
- 播放速率 = 实际速度 / 动画原生步速（walk 1.7 / run 3.75 / sprint 6.5，待手感校准）
- Lean 仍在 `bodyPivot` 上叠加，与动画正交

**方法论差距的说明**：ALS 完整系统还有 BlendSpace 八向混合、动画同步组、脚步 IK、Turn In Place、上下半身分层。当前是"按状态切单动画"，是复刻的第一步；八向（LF/RF/LB/RB）资产已具备，接入只差状态机细分。

### 3.4 相机模型

绕角色的球面轨道，三个量：

```
camYaw    水平角，0 表示位于角色正后方
camPitch  俯角，夹在 0.06–1.00 弧度（3°–57°）
camDist   距离，横屏 8.6 / 竖屏 9.9
```

相机位置：

```
pos = follow + ( sin(yaw)·cos(pitch),
                 sin(pitch),
                 cos(yaw)·cos(pitch) ) × dist
lookAt = follow + (0, 1.05, 0)
```

`follow` 是对角色位置的平滑跟随（lerp 系数 4.2），转视角本身不平滑（要跟手），只有位置跟随平滑。

**移动方向必须相机相对**：`forward = (−sin(yaw), −cos(yaw))`、`right = (cos(yaw), −sin(yaw))`。这一步漏掉的话，转完视角按前进还往老方向跑。

### 3.5 视口适配

| | 横屏 | 竖屏 |
|---|---|---|
| fov | 48 | 60 |
| 相机距离 | 8.6 | 9.9 |
| 初始俯角 | 0.30 | 0.34 |
| 地平线位置 | 画面约 17% | 约 20% |

竖屏水平视野天生窄（同等纵向 fov 下只有 30° 左右），只能靠"加大 fov + 拉远"补偿，代价是边缘轻微透视变形。

## 四、关键取舍与理由

| 决策 | 选择 | 放弃的方案 | 理由 |
|---|---|---|---|
| 相机朝向 | 固定轨道，玩家手动转 | 自动跟随角色背后 | 自动跟随在手机上会晕，且剥夺了观察世界的自由 |
| 移动方式 | 相机相对方向 | 角色相对（坦克式） | 现代第三人称的默认预期 |
| 地面网格 | 不做 | `GridHelper` 网格 | 远处产生严重摩尔纹横条，破坏白世界的干净 |
| 参照物 | 散石 + 方块群 | 网格、地面纹理 | 有体积感、有投影，且不形成规律线条 |
| 角色材质 | 哑光灰白模 `#8B8F95` | 深色剪影 | 用户指定参考 UE Mannequin；代价是角色不再是最强对比点，可读性交给投影 |
| 几何精度 | 低（Segments 14–28） | 高精度 | 手机上省 GPU，剪影风格下看不出差别 |
| 阴影 | 真实方向光投影 | 假圆片接触阴影 | 长投影是白色场景的主要形状信息，假影做不到 |

## 五、已知限制

1. 角色侧面剪影仍偏"柱状"：虽已有膝肘关节，但胸腔与骨盆没有前后错落，侧看轮廓变化有限。
2. 竖屏地平线很淡，白世界固有代价。
3. 没有碰撞体：方块可以穿过，世界没有边界。
4. 阴影只在角色周围 ±26m 内有效，更远的方块无投影（被雾遮住，不易察觉）。
