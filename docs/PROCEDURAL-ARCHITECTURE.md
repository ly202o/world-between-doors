# 程序化建筑制作规范：从 land 学到什么

用户要求（2026-11-19）：删除的是卡顿场景，仍须学会这种风格的场景与建筑制作，不能退回几个盒子拼房子的做法。

这份规范以本项目保留的 land 源码为依据；它用于后续建筑任务的制作和验收；独立建筑生成器尚未开发。

## 1. 先理解源代码的职责

| 文件 / 入口 | 实际职责 | 今后制作时必须保留的关系 |
|---|---|---|
| vendor/land/src/objects/buildings.js: houseParams | 固定种子解析风格、朝向、长宽、楼层、屋顶坡度、烟囱、塔、翼楼 | 所有构件从同一份参数计划派生，不能各自随手随机 |
| 同文件: houseFootprints | 主体及附属体量的占地 | 宅基地、道路避让与实际模型必须一致 |
| 同文件: planBlocks | 主屋、翼楼、老虎窗、塔的空间组成 | L/T/十字形是明确的体量关系，屋顶和门窗随体量走 |
| 同文件: buildBlock | 墙面坐标、遮挡关系、门窗、墙体和构件 | 被另一体量挡住的位置不再开窗、加角石或放装饰 |
| 同文件: roofOf | 双坡/四坡屋顶，檐口、椽头、瓦层、屋脊 | 屋顶尺寸从墙体和坡度计算，不是随意盖个三角锥 |
| vendor/land/src/objects/mesh-builder.js、poly/ | 网格、倒角、切分、法线与变形 | 正确的闭合、朝向和边缘光要由几何保证 |
| vendor/land/src/objects/village.js | 道路、宅基地、削坡、广场、田地、房门到街道的关系 | 先决定人怎么到达建筑，再补装饰 |
| vendor/land/src/render/props.js、texgen.js | 材质卡、米制 UV、材质图集、风和 LOD | 不能只复制顶点，再用一个默认材质声称效果已经迁移 |
| vendor/land/test/village.test.js、poly.test.js | 几何有效、不同 LOD 边界一致、闭合和法线方向 | 美术结果与结构检查同时验收 |

## 2. 结构优先，按这个顺序做

1. **用途与尺度**：先用我们的角色校准门高、层高、台阶、过道和屋檐。说明房屋是住宅、旅馆、工坊还是纯外观。
2. **平面与占地**：画出主屋、翼楼、入口、前院与道路连接；明确正面和地面 y=0；预留角色净空。先出灰模四面图。
3. **体量计划**：统一生成主屋/翼楼/塔/老虎窗关系，计算相交和隐藏区域。主屋与附楼必须有连接方式，不能只是互相穿插的盒子。
4. **墙体与洞口**：门窗的高度、轴线和楼层一致。近景门窗真正开洞，带墙厚、窗台、洞侧壁、过梁；不要用黑色平面代替窗洞。
5. **地基与地形**：地基对接实际地面；坡地削台和挡土部分要合理，门外台阶要落在道路上，不能悬空或埋地。
6. **屋顶系统**：由墙顶、进深、坡角推导屋脊和檐口；补檐下厚度、椽头、屋脊瓦。翼楼连接处处理交线与天沟，不能让屋顶不明原因穿墙。
7. **附属物**：烟囱、雨棚、廊架、平台、栏杆、灯、招牌都有挂接点和支撑关系，避开门窗与人的动线。
8. **材质与做旧**：先控制大色块，再做墙脚、雨痕、旧瓦、苔藓。做旧与受雨、潮湿、接地位置对应，不在所有面随机撒脏点。
9. **碰撞与交互**：使用我们自己的角色控制器。门洞必须可通行，门扇与铰链、墙体、台阶、楼板、屋面分别登记真实范围；不能用统一高度的障碍圆柱称为完整建筑碰撞。
10. **优化和实机**：合批/实例化，共享材质。近景瓦片可有厚度，中景改纹理，远景保留剪影、屋顶、烟囱、主要配色；LOD 不能换成另一栋房子。

## 3. land 的具体可复用经验

- houseParams 的普通房屋默认长边约 7.4–10m、短边约 5.4–6.8m，陶瓦坡角约 38–46°；这是该风格的样例，不是所有建筑的统一数值。
- 一层房屋仍有高于门窗的墙体和屋顶空间，避免屋檐直接压到门头。楼层数、窗位置与墙高必须同源。
- 不是每栋房屋都加塔。塔和复杂体量用于地标，其余建筑保持有节奏的变化。
- 石灰灰泥墙、石基、浅木窗框、褪色百叶窗、陶瓦屋顶有明确材质分工。窗玻璃在日光下映天空，不能一律纯黑。
- 瓦的参差、墙的轻微弯曲、屋脊的下垂是受限的小变化，不能破坏连接、碰撞和支撑。
- 独立随机流控制细节：删掉远景瓦片不能连带改变门位置、烟囱高度或房屋颜色。
- 植被与杂物服务生活逻辑：墙根草、窗下花箱、门边水桶、柴棚和晾衣绳要让开人走的地方。
- 外观完整不等于室内完整。若允许进入，还要单独设计室内地板、楼板、楼梯、门扇、层间通路和室内碰撞。

## 4. 下次建筑交付的硬检查

- 四面、斜俯视和角色眼高截图；能说明主体与附属部分的关系。
- 门窗开洞正常、没有墙挡门、台阶能到达、檐口与屋顶不悬空、没有重复隐藏面闪烁。
- 用真实按键走到门前、开门、进入、出门；能上台阶；不穿墙、不被隐形碰撞卡住。
- 近/中/远三个距离的轮廓与配色一致；移动镜头没有明显 LOD 变形跳变。
- 材质、法线、正反面、阴影层、阴影刷新和角色脚下接地均验证；不能只检查 castShadow=true。
- 发布前记录文件/资源大小、生成或读取耗时、draw call 与几何量；手机必须单独检查，不能用 PC 正常替代。
- 先做好一栋经验证的建筑，再扩展成村落。没有通过以上检查，不报告“完整建筑已做好”。
