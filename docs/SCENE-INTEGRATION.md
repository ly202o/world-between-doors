# SCENE-INTEGRATION.md · 场景接入规则

> **给造场景的一方（人或另一个 AI）与接入方（world01）的共同契约。**
> 2026-11-16 立。起因：v0.23.0 接入黄昏街角便利店时，场景方交付的是"能看的独立 diorama"，接入方没有接口，只能一点点剥建模代码，事后修了一串坑（相机与主循环要拆、ES6 要转 ES5、底座穿地、灯挂错层级、天空球不跟相机）。
> 这份文档把那些坑提前变成规矩。**改这份文档需要用户拍板。**

---

## 0. 一句话分工

**场景方造"一段能独立观看的建筑模型"；接入方把它变成"世界里的一个关卡"。**

两边各管各的，中间只有一个接口：**场景方交付的那个函数**。

---

## 1. 场景方交付什么

### 1.1 交付形态

| 项 | 要求 |
|---|---|
| 文件 | 单文件 `.html`，可双击打开即看（这是"独立 diorama"的定义） |
| 依赖 | 开发期允许 `importmap` 引 three r160 + OrbitControls；**接入时全部搬进 world01，运行期零外链** |
| 图片 | **禁止**。一切视觉由几何体 + 光照生成 |
| 建模范围 | **只建模型**。相机、OrbitControls、装配动画、主循环、输入、UI 一概不要 |
| 入口 | 一个函数，签名固定：`buildXxxLevel(worldScene)`，返回一个对象 |

### 1.2 接口形状（硬规定）

```js
function buildIslandLevel(worldScene) {
  var root = new THREE.Group();
  root.name = 'islandPlate';
  worldScene.add(root);              /* 所有几何体挂进 root，不要直接挂 scene */

  /* ...建模... */

  return {
    host  : root,                    /* 接入方会整体平移/旋转它 → 世界坐标 */
    lights: { hemi: null, sun: null, fill: null, bounce: null },
    sky   : null,                    /* 可选：跟随相机的背景球，见 §3.4 */
    store : { x0:0, x1:0, z0:0, z1:0 },  /* 可选：场景包围盒，接入方用来切光照 */
    doors : []                       /* 预留：本关内部的门扇 */
  };
}
```

**接入方只认这个形状。** 返回的 `host` 必须能整体变换（接入方会把它转到世界坐标、可能绕 Y 转 90°）。

### 1.3 坐标约定（最容易出事的一条）

| 约定 | 值 | 为什么 |
|---|---|---|
| 地面高度 | **y = 0 就是可站立的地面** | 接入方直接把 root 放到世界坐标 y=0，接上世界的无限地面 |
| 原点 | **x = 0, z = 0 是关卡中心** | 接入方按中心平移；不要在边缘留原点 |
| 朝向 | **+Z 是关卡的"正面"**（门在 +Z 方向能看到主体） | 接入方按需绕 Y 旋转 90°，前提是正面朝 +Z |
| 尺寸 | 直径 **≤ 32m** | 等距默认取景 **20m**（v0.27.1 起，滚轮可到 90m）；太大一屏装不下 |
| 净空 | **原点前后 10m 内不要放不可见碰撞体** | 那是接门的位置 |

### 1.4 底座 / 台座：**不许自带**

模型自带的底板、顶沿、装饰基座一律**删掉**。

> v0.23.0 的教训：便利店模型自带 21.3×0.22 底板 + 20.5×1.08 主体 + 两层顶沿，顶沿在 y = −0.025 ~ −0.16，搬进世界后从世界地面戳出来一圈亮边，像浮岛。

规则：**场景内任何几何体的最低点不得低于 y = −0.05**，除非它明确是"悬空/浮空"部分（并在该部分单独命名）。

### 1.5 灯光

- 关卡自有灯**挂在 `root` 里**，方向光的 `target` 放在**关卡中心上方**，阴影相机要能覆盖整关（否则影子盖不到场景）。
- 不依赖全局太阳：接入方会把世界的主太阳压暗、把关卡的灯升起来。
- 返回值里必须给出 `lights` 的引用，接入方按区域混合强度。

### 1.6 天空

可选。若有天空：

- 必须是**跟随相机的背景球**（半径 ≥ 200、`BackSide`、`depthWrite: false`）；
- **不参与碰撞**（接入方会把 `userData.colExempt` 标上）；
- 在等距 35° 俯角下基本看不见 → 门口看店内不能依赖它。

### 1.7 材质与色板

- 统一用 **toon 平面着色**（`MeshToonMaterial` + 4×1 `DataTexture` 渐变贴图，`NearestFilter`），与 world01 现有关卡一致。
- 色板集中在一个 `PAL` 常量表里，不要散落十六进制。
- 渐变贴图**每个场景各自建一份**（不能共用同一个 `DataTexture` 实例再改，否则材质互相污染）。

### 1.8 语法

- 项目代码约定是 **纯 ES5**（`var` / `function`，无箭头、无 `let/const`、无模板串）。
- 场景方**可以用 ES6 写**（方便），但接入方会降级；降级的前提是：**不要用 class、装饰器、顶层 await、动态 import**。
- 验收：接入后 `const` / `let` / 箭头函数出现次数必须为 **0**。

## 2. 接入方做什么（world01 侧）

按顺序，每步都有对应的坑：

| # | 步骤 | 坑 |
|---|---|---|
| 1 | 抽出**建模段**（"只建模型"那一段） | 相机 / OrbitControls / 装配动画 / 主循环 **一概不搬**；v0.23.0 源文件是 43~2166 行 |
| 2 | 去掉装配动画 | diorama 常带"从地基下升起"的动画；搬进游戏后关卡一开始就该在那儿 |
| 3 | **ES5 降级** | 一次性 `tsc` 降级即可，不要引入构建依赖；降级后 `const/let/箭头 = 0` |
| 4 | **删底座**，校平高度 | 车行道类平面抬到 +0.005 防 z-fighting；草地/人行道按 0.22 量级 |
| 5 | 挂成独立 world | `splitWorlds()` 分组 + 碰撞体带 **world 标签**（`field` / `spawn` / `konbini` → 新增自己的一档） |
| 6 | 碰撞体 | `fillCollisionGaps()` 必须在所有关卡建好之后跑；天空/门扇进 `colExempt` |
| 7 | 光照与雾 | `applyWorldLighting(w)` 按当前 world 切。**v0.27.0 起改成「每个世界一套光」，不再按玩家位置混算天光** → 新关卡只要注册自己的灯组即可 |
| 8 | 天空穹顶 | 跟随相机、跟随可见性淡入淡出 |
| 9 | 门 | 接门位要在场景**正面**且有净空；门本身是 world01 的 `makeGate()` 复用。**v0.27.0 起：世界锚在门上**——目标关卡整体平移到门的位置，跨门时人/镜头不动，只切世界层 |
| 10 | **同步测试断言** | 碰撞体总数变了，`w01_v140` / `w01_v160` 的硬编码数要跟着改（这是最常忘的一步） |

## 3. 边界行为约定

### 3.1 悬空场景（无无限地面）

浮空岛这类场景**脚下没有地面**，走到边缘会掉下去。约定：

- 场景方**不负责**边界行为，但必须在 `1.3` 的净空规则里让边缘可预判；
- 接入方负责坠落处理：**掉出范围 → 淡出 → 回到本关入口**（用户 2026-11-16 拍板）；
- 坠落判定用"y < 阈值"而不是"离开边界多边形" —— 玩家在边缘徘徊时不容易被误判。

### 3.2 有地面的场景

无限地面照旧，不需要额外处理。

## 4. 交付前的自检清单

场景方交稿前自己跑一遍：

- [ ] 双击 `.html` 能打开，画面正常，**没有任何图片素材**
- [ ] 旋转/缩放到任何角度都不穿帮（没有"只在某个角度看对"的面）
- [ ] 相机最低点（从下往上看过）没有奇怪的悬空板
- [ ] 最低几何体不低于 y = −0.05（除明确的浮空部分）
- [ ] 正面（+Z）方向有可辨识的主体，不是一堵墙或一段背板
- [ ] 灯光的影子落在自己身上，不是全黑
- [ ] 建模段里**没有** `requestAnimationFrame` 主循环 / 相机控制 / 键盘鼠标事件

接入方搬完再跑：

- [ ] `const` / `let` / 箭头函数 = 0
- [ ] 每个 `<script>` 块 `node --check` 通过
- [ ] 孤立目录 `file://` 打开：零外部请求、零控制台异常
- [ ] 回归测试全绿（碰撞体数变化的要同步改断言）
- [ ] 手机档（2.5 倍渲染 + 自适应）帧数达标
