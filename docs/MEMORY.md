## 2026-11-16 · v0.26.0 重叠层：门是接缝，不是传送

用户原话：*"我要镜头都不跳的。是不是应该是两个关卡重叠？像任意门一样，进去就是显示另一个关卡，出来就又切换回来？……也就是说世界是重叠的？像多维度空间？"*，随后拍板：*"就像ue中的流放关卡，对吧，做吧"*。

- **做法**：三个世界（spawn / field / konbini）在同一个坐标系里叠着；门是两层之间的接缝。跨门槛只改 `curWorld`，玩家的 `P.pos`、朝向、`camYaw` 都不动，镜头自然不跳。
- **门的坐标必须两边对齐**：出生世界的门与目标关卡的门同位置同朝向（便利店 (-15.5, 24.5, ry −90°)、旧场 (2, −4, ry 180°)）；门后画面用**同一台相机**渲染另一层，透视和视差才对。
- **碰撞要分世界**：所有碰撞体带 `world` 标签（`BUILD_WORLD` 在构建各层时切），`collideXZ` / `supportAt` 只认当前世界。不做这件事，隐藏关卡的屋顶会**隐形支撑**玩家，脚 IK 和侧走判定全乱（v140 / look 两套就是这么红的）。
- **门挡板（blocker）也要带 world**：它不在网格里，`worldOfMesh` 找不到父链，得在 `makeStandaloneDoor` 里显式 `blk.world = d.world`。
- **到达门自动打开**：否则镜头贴着门板/落点被挡；开门后 blocker 移开，人不会被挤出去。
- **测试要不要动**：布局变了，测试落点要跟着挪——look 的侧走点从 (0,0) 挪到 (30,30)（旧场/门附近的隐形几何会误触发 mantle），v140/v160 的碰撞体 676→678。这不是放水，是测试在验证"空地侧走"这一条，场地换了它得站到新空地上。

## 2026-11-16 · v0.25.0 真门：把"传送门"从贴图改成透视正确的一扇缝

用户原话：*"你现在这个是贴图，并不是里面看起来是场景……没有传送，没有贴图，就是真的走进去"*

- 坑 1：RT 重建后 `ShaderMaterial` 的 uniform 还指着旧纹理，画面会黑——`rt.setSize` 后要重新赋 `uMap`。
- 坑 2：便利店侧回程门原本关着，正好挡在门洞后面，RT 里整扇门是黑的；渲染目的地世界时先把"目的地回程门组"藏起来，再恢复。
- 坑 3：门扇向外开会挡住走过去的路，也不符合"推门进去"；改成向内开 -1.75 rad。
- 坑 4：回程门原来在街角（-12.4, 22），人到不了店门口；挪到店门口台阶上（-21.6, 19.0，朝西），穿过去就是店招。

## 2026-11-15 · v0.23.3 手机掉帧与门口阴影闪动

用户原话：*"但是掉帧卡顿哦"* ／ *"屏幕好像还有闪动"*

- 掉帧：3x 对中端机太重。改成 2.5x 上限 + 开局 0.8 + 更早的自适应（阈值 50fps、下限 0.55）；手机档把关卡的 fill/bounce 两盏装饰补光关掉、关卡太阳阴影 2048 减到 1024。
- 闪动：真凶不是分辨率，是 world/关卡两套太阳的 castShadow 在 b=0.55 单点二值切换——玩家在区域边界来回走，b 在阈值附近摆动，地面阴影就一开一关。改成 0.9/0.2 滞回，切换点都落在对方只剩 10%/20% 光强的时候。
- 教训：凡是"按某个标量阈值切资源/开关"的行为，只要那个标量会被玩家走动来回跨，就必须带滞回，否则一定闪。

## 2026-11-15 · v0.23.2 手机清晰度

用户原话：*"手机像素太低了"*

- 根因不是"分辨率设置错"，是手机档 DPR 上限 1.5：390pt 宽的手机画布只有 491px，浏览器把它放大到 1170px 的屏幕上，等于每 2.4 个屏幕像素用 1 个画布像素插出来。
- 改法只动一个默认值：DPR_CAP 手机档 1.5 → 3。自适应分辨率 renderScale 的逻辑没动，GPU 扛不住时仍会往下收，下限 0.62（等效 1.86 倍，仍比旧上限 1.5 清晰）。
- 手机档 antialias 一直是 false（性能考虑），在 3 倍像素下锯齿不明显，这次没动。
- 验证方式：CDP 模拟 390×844、DPR 3 的手机，读 canvas.width / clientWidth 的比例——旧版 1.26，新版 3.00。

## 2026-11-15 · v0.15.0 第 4 档视角：等距（正交）

用户原话：*"我只是要一个等距视角的视角模式。"* —— 上一轮我把"这种等距视角做一个看看"理解成"做一个新的等距场景"，另起了一个 `iso01/iso.html`（小岛风景 demo）。跑偏了，已承认。**这条要记：他说的是"视角模式"，那就是在 world01 里加一档，不是新开项目。**

- **正交，不是窄 FOV。** 透视的平行线永远收敛；等距 = `OrthographicCamera` + 仰角 `atan(1/√2)` = 35.264° + 方位 45°+k·90°。三条缺一条就只是"看起来像"。
- **不换相机，加一台。** 透视 `camera` 管前三档，新 `orthoCam` 每帧复制位置和朝向，`activeCam` 决定 renderer 用哪台。
- **接缝的钥匙**：`halfH = effDist × tan(FOV/2)`，两台相机在枢轴平面等大 → 切投影不跳（实测差 0.0002），且"远处不变小"从第一帧就成立，不需要过渡动画。
- **取景用"纵向覆盖多少米"，不要用"窄边"**：按窄边算，竖屏纵向撑到 34.6m，人成小点。最终横竖屏都用 28m（≈6.3% 屏高）。
- **28m 是量出来的，不是拍的**：v0.11.39 删正交的理由之一就是"房子跑出画面上边"，24m 时房子顶部仍被顶出去，30m 完整，28m 压住边。**历史否决理由要当成需求来验，不能当成耳旁风，也不能当成圣旨。**
- **方位两级档（v0.18.0）**：Q/E 轻按 15° 细档微调，Shift+Q/E 与拖动（80px）走 90° 粗档；俯角焊死，滚轮改覆盖米数（6–90m）。自由旋转被用户否了（2026-11-15），纯 90° 一档也被否了——落点是两级档：细档换构图自由，粗档保住「转世界直角」的手感，四个方正方位仍在。

## 2026-11-14 · v0.13.3 脚部两骨 IK

- **上一版记的"坡屋顶一脚悬空一脚陷入"已修**。旧实现的"骨盆补偿"物理上就不成立：骨盆只有一个值，两脚必须一起动。斜坡上两脚差 9.9cm，补好一只必然压坏另一只。
- **解法分两层，这个分工是核心**：
  - 两脚**一起**浮/沉 → 骨盆竖直偏移。因为平地站立时膝角 168~171°，腿已接近伸直，**没有下探余量**，只能整体沉。
  - 两脚**不一样高** → 逐腿两骨 IK。抬脚只会让腿变弯，永远有余量。
  - 所以每帧两遍：先量 `wantL/wantR`，取最小值（限幅 −0.16~+0.08）给骨盆；剩余差额逐腿解。**剩余量恒 ≥ 0 → 恒可解**，不会把腿拉长。
- **骨架数据**：`pelvis → thigh(0.426) → calf(0.402) → foot → ball`；平地站立踝高 **0.100m**（两脚实测）；前脚掌（ball）在平地约 −0.004m（动画本身带 4mm 入地）。

- **坑 2**：单次解析解剩 1.8cm 残差，因为原动画的膝盖不在「垂直+正前」平面里。解法是每帧解 3 轮，每轮重新量当前踝位、解剩余差额。

- **枪口朝向**：`GUN_HAND_Q` 是相对手的常量局部变换，手转多少枪就转多少。改手臂姿势必须重新对一次枪口方向（点积目标 = 角色前方），否则枪会横着指。
- **枪声是合成的**（ALS 没有武器音源）：低频正弦冲击 + 带通噪声爆裂 + 低通尾音，三层。机械声（干击/退匣/上匣）是 45~75ms 的带通噪声 + Q2.2。实测峰值枪声 0.68 / 脚步 0.56，比例合适。
- **ALS 音效抽取**：`.uasset` 里内嵌的是完整 RIFF/WAV（`RIFF` + `WAVE` + `fmt ` + `data`），直接按块切出来就能用；`Concrete_*` 96kHz 单声道、背景 44.1kHz 立体声。抽出后按 16k（音效）/ 11k（背景）重采样、掐首尾静音、归一化。背景循环要**首尾交叉淡化**（`seam()`），不然循环点能听见。
- **坑 4**：`decodeSfx()` 在 AudioContext 重建后会再跑一遍，`SFX_BUF[g].push()` 直接让采样集翻倍（walk 5→10）。入口处 `SFX_BUF = {}`。`AMB_SRC` 同理要跟着重置。
- **测试**：CDP 里 `KeyboardEvent` 用 `window.dispatchEvent(new KeyboardEvent('keydown',{key:'v'}))` 才稳，`Input.dispatchKeyEvent` 的 `key` 有时不落到 `e.key`。`Runtime.evaluate` 里写 `{a:1}` 会被当代码块，要包成 `({a:1})`。

## 2026-11-14 · v0.13.0 手机性能 + 手枪重做

- **手机"卡"的定位**：不是 JS。CDP 4 倍 CPU 降频下仍 120FPS 就已经说明问题在 GPU。真机上的成本是叠起来的——MSAA + 3x 像素比 + 2048 PCFSoft 阴影，fill rate 直接被放大好几倍。方向是「少画像素」，不是「少算逻辑」。
- **手机档**：`IS_MOBILE` 先认 UA（Android/iPhone/iPad/鸿蒙/MIUI），iPadOS 伪装 Mac 时用「触点数>1 + 粗指针 + 短边≤820」兜底。**别用「有触摸 + 短边小」**——小窗口的桌面浏览器会被误判。手机：关 MSAA、像素比封顶 1.5、阴影 1024 硬 PCF。
- **自适应分辨率** `adaptResolution()`：24 帧一采样，慢于 43FPS 降 0.08（很慢降 0.16），快于 56FPS 攒 4 次升 0.08，下限 0.62，调整后锁 0.9s，开局 1.5s 暖机，降过的档位 12s 内不回爬（防两帧一抖）。
- **手枪**：18 个部件、两段材质（中灰滑套 + 深色握把）；后坐力是欠阻尼弹簧（灌初速度，过冲再收）；滑套 28mm 后座循环；散布 = 基础+移动+空中+连射累积，射线锥内 `sqrt(random)` 取极坐标；准星四段线随散布张合（金色命中 / 红色空仓）；抛壳 / 曳光 / 弹孔 / 烟 / 火光全部池化预建。
- **踩坑 1（关键）**：`AdditiveBlending` 在白色世界上等于没画。枪口火光、曳光、烟原本都是叠加，截图里完全看不见。这个世界所有"发光"特效一律用普通混合 + 饱和色。
- **踩坑 2**：长条面片拼星形火光，在透视下会拉成横贯半屏的丝带。火光用「正对镜头的方片 + 前向锥体」。
- **踩坑 3**：靶子自己也是 `colliders` 里的一项，射线先撞它自己的解析盒，浮点误差让 `hits[0].distance < nearest` 判负 → "打中靶子"退化成"打中场景"。射线遍历碰撞体时按 `kind === 'target'` 排除。
- **踩坑 4**：诊断脚本里 `FX.tracers.forEach(t => t.life = 9)` 会把**池里没用过的那几个**也点亮——它们在原点、1 米见方，投影出来是一块巨大的橙色楔形，看起来像曳光画错了。改参数只改 `m.visible` 为真的那几个。
- **测试环境**：`D:/temp/run_with_edge.sh` 在**同一个 shell** 里起无头 Edge 和 node 脚本，跑完再 kill。后台任务结束时子进程会被带走，分离启动的浏览器撑不过一条命令。软渲染（swiftshader）下 20~40 FPS 是正常的，别拿它判断真机帧率，它的用途是当压力源验证自适应会不会降档。

## 2026-11-14 · v0.12.6 攀爬滑步根治（根骨位移）

- 用户报「爬高墙有滑步」，**原因不在时长调参，而是位移和动画不是同一条曲线**：
  - 烘焙把根骨平移的水平分量丢了（只留竖直 `bob`），位移由代码三段插值另算；
  - `mantle2` 的原生根骨在 0.33–1.0s 就走完，代码摊到 1.95s → 末尾 0.86s 动画站住身体还在挪 0.9m；
  - 跑撞探针 0.56m 导致起手点离墙 0.45m，所需水平 0.81m 而动画只有 0.65m → 拉长 1.25 倍，脚在墙面被拖。
- 现在烘焙带 `root`（根骨相对首帧位移，`[侧,上,前]`），`advanceClimb()` 按动画时间取位移；速率只压时间轴。多余的水平距离走 `residual`，摊到 40%–90% 尾段。
- 探针 0.56 → 0.34m（≈体半径+5cm）。诊断：`__world.climbScale` = `{h,v,sH,res}`，`sH` 必须 1.00；`__world.feet` 给脚骨世界坐标用于量滑步。
- **教训**：以后凡是"动作看着打滑"，先查烘焙有没有把 root motion 丢掉，而不是去调时长/分段比例——时长只改快慢，曲线形状才决定脚是否被拖。
- 三档实测：1m 墙 `mantle` 1.06s → y=1；2m 墙 `mantle2` 2.08s → y=2；2.6m 拒绝。翻栏 x 从 −9.58 跨到 −8.4，峰值抬 0.72+，落地 y=0。

**为什么动画用素材不用代码（用户 2026-11-13 问"动画曲线能不能做成代码"后的结论）**：

1. **试过，被否了**。v0.4 的角色就是纯代码步态（sin 公式摆腿摆臂），用户看到 ALS 后直接说"不像"，这才换的素材。有实测结论，不是猜的。
2. **差距是方法论不是参数**。代码公式各关节相位固定；ALS 的动作里脊柱扭转、骨盆起伏、手臂惯性跟随是几十根骨头**不同步**协调出来的，几个 sin/cos 表达不了。
3. **补齐的代价不成比例**。要用代码做出重量感，得上完整程序化动画方案：脚部 IK 让脚贴地、质心偏移、动量守恒——工作量大、"好看"没有保证，风险是折腾一圈回到火柴感。
4. **折中已经存在**。lean 倾斜、待机呼吸、起跳压扁都是纯代码叠在素材动画上的（ALS 自己也是"基础动画 + 代码层"）。所以"世界由代码长出来"的命题没有破，只是基础动效借了素材的力。
5. 体积代价可控：动画数据 577KB，在 2.07MB 单文件里占 28%。

## 六、踩过的坑（按严重程度）

### 1. 手机打开纯白，桌面正常
- **现象**：一片白，没有任何报错提示。
- **根因**：`<script src="vendor/three.min.js">`，只把 html 传到手机，依赖目录没跟过去。
- **修法**：Three.js 整段内联。
- **教训**：给用户的页面必须**真的**只有一个文件。验证方式是"新建空目录只拷这一个 html 再跑"。

### 2. 内联之后还是纯白
- **根因**：`three.min.js` 首行是 `console.warn(...),`，靠逗号表达式让后面的立即执行函数处在表达式上下文。删掉首行后，`function(t,e){...}` 落到语句开头，被解析成**无名函数声明** → SyntaxError。
- **修法**：`*/` 后补一个 `!`。
- **教训**：校验要**每个 `<script>` 块单独** `node --check`，别只查最后一块。

### 3. 白色世界的光怎么调都不对
- **现象**：要么整片发灰，要么全过曝成纯白，天地无分界。
- **根因**：Three.js r155+ 是物理光照，`MeshStandardMaterial` 漫反射带 `1/π`，强度给 0.8 会发灰，要 3.0 量级地面才接近白。
- **修法**：hemi 1.45 / sun 1.84；地平线靠**雾色比天暗一点点**（`#F1F5F8` vs `#FFFFFF`）浮出来，不能靠地面比天暗硬做。

### 4. 只有角色脚下有影子，方块全无
- **根因**：改了 `shadow.camera.left/right/top/bottom` 但没调 `updateProjectionMatrix()`，仍是默认 ±5。
- **修法**：手动调用一次。

### 5. 角色侧面像一根柱子
- **根因**：胶囊拼接、无膝无肘、头陷进躯干里（头球底面低于躯干胶囊顶面 → 看着没脖子）。
- **修法**：躯干缩短（不是把头顶上去）、加颈、膝盖肘部分节 + 关节球、加鼻凸。
- **衍生坑**：背面视角两腿重叠成一条 → 髋间距加到 ±0.125；跳跃手臂向前抬像抱东西 → `rotation.x` 正值才是向后甩。

### 6. 转完视角按 W 还往老方向走
- **根因**：移动方向没改成相机相对。
- **修法**：`forward = (−sin yaw, −cos yaw)`、`right = (cos yaw, −sin yaw)`。

### 7. 动画接入后角色躺平（FBX 曲线四个连环坑）
> 补充（v0.9.1）：即便曲线全对，**刚性绑定**也会在关节处露缝。真蒙皮才是正解，别在切块方案上打补丁。
- **坑 1**：`Properties70` 的 `P` 节点格式是 `[名字, 类型, 标签, 标志, 值×3]`，值要从**末尾**取，从 `props[3]` 取会拿到标志位（字符串 → NaN）。
- **坑 2**：FBX 属性名带空格（`Lcl Rotation`），比对前要 `replace(/\s+/g,'')`。
- **坑 3**：`ALS_N_Pose.fbx` 这类资产**不写绑定姿态**，rest 必须从 `ALS_N_Walk_F.fbx` 统一取。
- **坑 4**：FBX `eEulerXYZ` = `Rz·Ry·Rx`（X 先施加）。写成 `Rx·Ry·Rz` 在 gimbal 附近（pelvis 的 Y≈−90°）会算出 40° 假旋转 → 整个人躺倒。
- **另一个必踩的公式坑**：局部旋转增量不能直接套。我们的骨骼组挂在「rest 世界朝向」里，增量要用**父骨 rest 世界旋转共轭**：
  `Q(bone) = W_rest(parent) · (R_anim_local · R_rest_local⁻¹) · W_rest(parent)⁻¹`，
  再转 Three 坐标 `q' = m ⊗ q ⊗ m⁻¹`（m = Rx(−90°)）。
- **验证手法**：把每个动画 pelvis/thigh 的增量角打出来，走路 pelvis 应在 10° 内、thigh 在 30° 上下。数字离谱就是上面某个坑。

### 8. 落地动画一帧就被覆盖
- **根因**：状态机每帧都调 `setAnim`，一次性动画被立刻换回 idle。
- **修法**：`if (!ANIM.oneShot) setAnim(...)`，让落地动画播完再交还状态机。
- **v0.11.0 修正**：反过来也不行——落地锁满整段 1.2s，玩家继续前进就变成「脚不动人在滑」。改成 `P.landLock = 0.32` 计时器，到点强制清 `oneShot`。

### 9. 「没声音」不等于链路断了
- **现象**：探针 440Hz RMS 0.32 正常，脚步却听不见。
- **根因**：不是链路，是**量级**。旧参数跑动峰值 RMS 只有 0.02 量级，且主体能量在 60–100Hz（手机喇叭发不出）。
- **修法**：频段上移到 300–2200Hz、增益 ×1.5、母线上加压缩器当限幅（−16dB / 8:1）。
- **测量教训**：用 CDP 50ms 轮询读 analyser 会**错过短脉冲**，读出 0.004 而实际 0.077。要在页面里用 `requestAnimationFrame` 连续采样再取最大值。

### 10. 跳跃滑步 = 用了跑跳循环 + 空中没有位移
- **根因**：`ALS_N_JumpLoop` 是**跑动起跳**的循环，脚前后行程 63–70cm；角色空中不位移 → 脚原地划。
- **修法**：起跳用 `JumpWalk_*`/`JumpRun_*`（按速度选、左右脚交替），下落换 `FallLoop`（脚行程仅 7cm），空中 ACC 降到 30% 保惯性。
- **判断工具**：`node w01_foot.cjs` 用 FK 算脚骨每帧世界坐标，行程大 = 一定会划。

### 11. 手机不出声，先查解锁路径再查音量
- **排查顺序**：① `__audioState().state` 是不是 `running` ② 不是就查解锁（iOS 静音拨片 / 微信 webview / webview 首个实例坏）③ 是 `running` 还没声，才怀疑音量和频段。
- **根本原因（v0.11.2）**：`AudioContext` 在**非手势**上下文里被创建了（`update()` 第一帧的兜底解锁）。iOS 上这种实例 `resume()` 返回成功但状态永远 `suspended`。**上下文只能在手势里 new**，`audioReady()` / 兜底一律只 resume 不新建。
- **确定性修复**：手势里真播 1 帧空 buffer、`navigator.audioSession.type='playback'`、`WeixinJSBridgeReady` + `visibilitychange` 重试、连续失败就重建 `AudioContext`。
- **别忘自证**：失败时才显示的提示条 + 页面角落的版本号，能区分"代码没修好"和"手机跑的是旧文件"。
- **兜底链路（v0.11.3）**：`OfflineAudioContext` 不需要手势、不受自动播放策略限制，可以把合成结果渲染成 WAV，交给 `<audio>` 播。有些 webview 只拦 WebAudio 的输出，这条能救。

### 13. 合成音效到不了「写实」——瞬态做不出来
- **现象**：噪声 + 滤波 + 包络怎么调都「太难听、和原版完全不像」，且有几十毫秒起振时间导致与动画不同步。
- **根因**：真实脚步的冲击瞬态是宽带颗粒，合成做不出来；噪声从静音爬到全电平的起振就是不同步的来源。
- **修法（v0.11.4）**：ALS 的 `.uasset` 里直接内嵌原始 WAV（RIFF 段），不需要引擎就能按 RIFF 边界切出来。96kHz → trim → 16kHz 单声道 16bit → 统一增益（保留走跑相对轻重）→ base64 共 111KB 内嵌。播放用 `AudioBuffer` 在动画事件帧直接 `start()`，同步问题消失。
- **教训**：RULES 第 6 条「能生成就不用素材」要留第二档——合成先试，明显不合格就转项目内素材，别死磕。

### 14. 「跳跃手臂举老高」先查原版再怀疑烘焙
- **实测**：`ALS_N_JumpRun_*` 反侧手最高 197cm，头顶才 164cm——**原版动画就是这样**，不是烘焙错。
- **观感差的真实原因**：切在手臂最高点再 0.18s 硬切进下落。先拉长混合到 0.30s；用户仍不满意 → 起跳统一改用 JumpWalk 片段（双臂前摆、最高到下巴）。v0.11.5 加快跑后恢复分流：>4.8 m/s 才用 JumpRun，普通走跑仍是 JumpWalk。

### 15. 原生步速填错 = 全程匀速滑步（问出来的 bug）
- **用户一句「快跑动作和 ALS 的对吗」暴露的**：动作资产是原版，但 `ANIM_NATIVE` 里填的是拍的估值（walk 1.7 / run 3.75 / sprint 6.5），ALS 源码基准是 150/350/600 cm/s。
- **原理**：速率 = 速度/原生步速 永远自洽，但脚的贴地速度 = 速率 × 真实原生步速，填错一个数就差固定百分比（sprint 8%、walk 12%），匀速滑步，很难目测发现。
- **教训**：从源码抄参数就全抄，别一半源码一半拍脑袋；真机手感校准前，先对齐资产来源方的基准值。

### 16. 同名局部变量覆盖（v0.11.8 踩的）
- 相机段 `var cp, sp`（cos/sin pitch）覆盖了朝向段的 `var sp`（速度），后面新加的冲刺 FOV 判定读到的速度其实是 sin(pitch)≈0.3。
- **教训**：同一个 update 函数几百行，加代码前先 grep 有没有同名 `var`；sin/cos 这种辅助变量用带前缀的名字（sP/cP）。

### 17. 相机效果只动位置不动 lookAt = 远景跳变（v0.11.9）
- 落地微沉第一版一帧内把 camera.position.y 拽下 0.25m，lookAt 不变 → 俯仰角突变 → 用户看到「远景方块跳一下」。相机位置的任何瞬变都会把整个画面内容瞬间平移。
- **规矩**：相机抖动类效果①幅度要小（厘米级）②位移用两帧以上平滑追目标量，不能一帧到位③位置和注视点同步动（画面整体点头），除非刻意要变俯仰。

### 18. 一次轻点 = 5 个手势事件，音频解锁不能每个都跑（v0.11.11）
- pointerdown / touchstart / pointerup / touchend / click 都绑了 audioUnlock → 一次轻点跳跃跑 5 遍，其中 wavUnlock 每次都 play→pause 启停媒体管线 → 手机上跳跃掉帧到十几。桌面帧间隔完全无差异（8.7ms/帧），说明是手势×音频的开销不是渲染。
- **修法**：WebAudio 已确认能响且 state=running 时手势直接早退；wavUnlock 用 _wavUnlocked 只做一次。
- **方法**：手机特有性能问题先在桌面量化（帧间隔 p95/max），桌面无差异 → 查手机特有的路径（手势、音频、媒体管线）。

### 19. 动画采样别跟物理步长跑（v0.11.12）
- 固定步长 1/120 意味着 60fps 手机每渲染帧跑 2 次 update；driveAnim 原本在 update 里 → 骨架采样/写骨翻倍。走路大部分时间不混合没暴露，跳跃全程混合（4 次切换）就掉帧。
- **修法**：driveAnim 移到 loop 按渲染帧调一次，60Hz 采样视觉无差，计算量减半。fireSteps 支持跨帧区间+回绕，事件不漏。
- **规矩**：纯表现层（动画采样、特效）不进固定物理循环；物理循环只留必然要 120Hz 的东西（移动、重力）。

### 20. 早退条件要覆盖所有正常状态（v0.11.13）
- v0.11.11 的手势早退只写了 "WebAudio 正常"，但这台手机的 WebAudio 一直被拦、走 `<audio>` 备用链路 → 早退永不成立，每次轻点 5 个手势事件仍跑完整解锁路径。
- **教训**：写 "已经在正常工作就早退" 时，把每一条能用工作的路径都列出来（WebAudio / `<audio>`），否则优化的正是另一条路径。

### 21. 姿态字典不要每次切动画清空（v0.11.13）
- `setAnim` 里 `delete` 两个姿态字典 → 下次采样重建 64 个 Quaternion；一跳 4 次切换 = 256 个临时对象，持续跳跃就持续 GC 尖峰（"卡顿"手感）。
- **修法**：字典永不清空，`driveAnim` 按 `AN[ANIM.cur].bones` 判断骨归属，残留骨不参与。内存对照：静止 10s +131KB、连跳 12 次 −947KB，无泄漏。

### 22. data URI 音频每次 play 会重新解析（v0.11.15）
- 手机端起跳帧 60~100ms 同步阻塞，长帧全落在 jumpWalk/jumpRun，唯一可疑项是 `el.play()`；音频元素用 `data:audio/wav;base64,...`，iOS / webview 每次播放可能重解 base64。
- **修法**：改 Blob URL（atob → Uint8Array → Blob → createObjectURL），失败回退 data URI。
- **教训**：长音频素材给 `<audio>` 用 Blob URL，data URI 只适合图片/字体这类解析一次就缓存的资源。

### 12. 落地滑步：脚钉住的动画 + 身体位移 = 必滑
- **根因**：落地片段里脚基本不动（行程 8–14cm），但身体还在以 4.5 m/s 前进，0.32s 就是 1.4m。
- **修法**：按落地时的水平速度分流——>1.8 m/s 干脆不播落地片段（跑步循环直接接上，只留压扁 + 音效）；≤1.8 m/s 才完整播。
- **真正的解法**是上下半身分层（腿走跑步循环、上身播落地压缩），ALS 就是这么做的，我们还没做。

### 26. 分轴截断的加速度 = 贴墙永久侧漂（v0.11.22）
- 加碰撞后，人正对墙站着不动，会以约 0.4 m/s 沿墙横向漂移，越漂越快。
- **根因不在碰撞**：移动代码把每帧速度增量分 x / z 各自截断到 `ACC·dt`。速度被墙清零后重新加速时，两个轴各走满 `ACC·dt`，合方向偏向 45°；这个偏差每帧被"清零 + 重新加速"复制一次，累积成侧向速度。
- **修法**：按向量长度截断（超长才等比缩放）。
- **教训**：碰撞调不通时先怀疑"喂给碰撞的速度本身不对"。碰撞只是把朝墙那一部分拿掉，喂进去的东西歪了，剩下那部分当然歪。

### 25. 网格的摩尔纹是"线宽随距离变细"造成的，不是网格本身（v0.11.21）
- 最早否掉网格是因为远处满屏摩尔纹。真因：固定世界宽度的线，距离一远就有几百条挤进一个像素。
- **解法**：`fwidth()` 把线宽钉在 1 像素（不会变密），再按"一个像素覆盖多少米"衰减——`smoothstep(0.12, 0.55, pxSize)` 一开，掠射角整段自动消失。
- 顺带：网格要取**世界坐标**（`modelMatrix × position`），因为地面是跟着角色平移的，取局部坐标网格会跟着滑，穿帮。
- **教训**："这个方案有 A 缺陷"不等于"这个效果不能做"，多数时候是**实现方式**有缺陷。

### 24. 换投影方式只能换相机，不能靠调参数（v0.11.20）
- "正交轴测"不是把透视相机抬高、拉远就能得到的：透视下远处的方块永远会缩小、平行线永远收敛。唯一正解是 `OrthographicCamera` + 换 `renderer.render` 的相机参数。
- **连带坑**：正交下全场景到相机几乎等距，`Fog` 会退化成均匀白纱，必须临时 `scene.fog = null`；正交的"机距"不影响画面大小，只影响裁剪，所以要摆得比最高的塔还远（90 m）。
  - **v0.15.0 补注：这条只对"全景正交"（机距 90m、整个场景都在框里）成立。** 跟随式等距（机距 31m、枢轴在角色肩上、画面纵向 28m）里，场景纵向跨度只有 20m 左右，雾量 5%~30% 仍有层次，白色主题实测没糊，所以**不用动雾**。同一句话换个摆法就不成立了——旧结论要连条件一起搬。
- **教训**：用户说"像某游戏的视角"时，先去想那是什么**投影方式**，而不是先调角度和距离。

### 23. 重写一段代码，先把被替换掉的旧段副作用列出来（v0.11.19）
- 加视角三档时整段重写了相机部分，把 `follow` 的平滑跟随、`camKickT/camKickV` 的衰减一起删了——相机永远盯着原点，角色跑十几米就丢了，页面却不报错（`follow` 只用不赋值，句法完全合法）。
- **发现方式**：测试脚本同时打印相机坐标与角色坐标，一比才发现差了 40 m。
- **教训**：替换一个代码块时，先列出旧块里"除了你要改的目标之外"还做了什么（跟随、衰减、状态复位……），逐项确认新块有没有承接。只盯着新目标写，删掉的往往是最不起眼的那几行。

### 27. 别用 `sed -i` 改 world01.html，它会顺手把整个文件的 CRLF 换成 LF（v0.11.25）

`sed -i 's/v0.11.23/v0.11.24/g'` 只改一行版本号，结果 git diff 显示 1729 行新增 / 1705 行删除——全文件换行符被 GNU sed 重写了一遍。功能没坏（HTML 对 LF 无所谓），但 diff 彻底没法看了。

**改 world01.html 只用 Edit 工具**（它保留原换行符）。真要批量替换，先确认 diff 行数合理再提交。

### 28. 算"推力"要用意图速度，不能用当前速度（v0.11.26）

给贴墙加摩擦，第一版写 `press = −(vel·n)`，跑出来数据几乎没变。原因是法向分量**上一帧就被清零了**，这一帧只剩重新加速出来的一点点（≈ a·dt），按它算摩擦力等于没有。

改成 `press = −(目标速度·n)`（`tx,tz`）才对：那才是"你有多想钻进墙里"。
**教训**：凡是"已经做过一次处理"的量，再用它当输入前先想一遍它还剩什么。被清零、被夹紧、被平滑过的变量，往往已经不是物理量本身。

### 29. 手势判定要先问"是不是另一种操作"（v0.11.30）

自由视角里"双指 = 缩放"，判定条件只写了 `ptrCount() >= 2`。结果"左手推摇杆 + 右手转视角"也满足两根手指，直接进捏合，摇杆和视角同时被作废——用户以为"自由视角不能转视角"。

**教训**：多点手势的判定条件不能只看数量，要看**意图**。这里两条就够：没有手指在推摇杆（`!touch.active`）、所有手指在同一半屏。手势之间有优先级（持续操作 > 瞬发手势），别让新的抢走正在进行的那个。

### 30. 同一个手势，三档相机的符号必须对齐（v0.11.31）

自由视角的俯仰写成了 `freePitch -= dy`，第三人称是 `camPitch += dy`。两者的量纲完全一样（都是"相机相对枢轴的仰角"），符号却相反——用户一进自由视角就觉得上下反了。

**教训**：同一个物理量的不同档位副本，加减号必须抽查一遍。写新档位时最好的做法是**把公式抄过来再改需要改的那一项**，不要凭手感重写。

### 31. 材质换回来再换过去，会闪一帧（v0.11.32）

自由视角遮挡改半透明后，射线回调里要"把出名单的还原、把新名单的变透明"。顺序写成先换新名单再还原旧的，同一个物体如果在两帧间来回进出，会有一帧拿到 `propMat` 又立刻被刷回去，屏幕上一闪。

**修法**：先 `for (occluded)` 还原（跳过 `keep` 里仍然在的），再 `for (keep)` 上 `ghostMat`。名单用数组 diff，不用 `Set` 也行——物体数只有个位数。

**顺带**：`ghostMat` 必须 `depthWrite = false`，否则半透明的塔会把后面的角色写进深度缓冲，看起来像被裁掉一块。

### 32. 批量改名会误伤"同名但不同义"的字符串（v0.11.33）

`index.html` → `world01.html` 用脚本全局替换，看着干净，实际踩了两处：`backups/index.html` 被先替换成 `backups/versions.html`、再被 `index.html → world01.html` 二次替换成 `backups/versions.world01.html`；`fs.writeFileSync(path.join(BK,'index.html'))` 这种"只是拼路径"的地方也被改成了 `world01.html`，索引页会写到错的文件名。

**教训**：改名别只做一次 `replace`，按**从长到短**的顺序替换（先 `backups/index.html`，再裸 `index.html`），改完 `grep` 一遍残留，再跑一次生成脚本看产物文件名对不对。

### 33. 遮罩换材质，"还原"必须还原成原材质（v0.11.34）

自由视角的遮挡遮罩早期一律 `occluded[i].material = propMat`。加了小屋之后，屋顶是 `roofMat`、树冠是 `leafMat`——被遮一次再走开，它们会变成墙的颜色，而且再也回不去。

**修法**：每个参与遮罩的 mesh 在创建时记 `userData.baseMat = m.material`，还原时用它。

**同一个坑的变体**：门窗是贴在墙面上的深色面片、不在 `blockers` 里，墙变半透明后它们还是实心的，远看像几块灰方片浮在空中。给宿主墙挂 `userData.trim` 列表，遮罩时同步 `visible = false`。

**教训**：只要做"临时替换某个属性、之后再恢复"，恢复用的值就必须是**记下来的**，不能是"我以为是默认的那个"。

### 35. 边缘命中 + 安全边距 = 永远判「站不住」（v0.11.40）

攀爬检测的命中点本来就在碰撞体边缘（沿射线第一个进盒的采样点）。落点检查写成 `insideCol(..., margin=0.10)`，从边缘往里第一二步都还在 10 cm 边距里，循环立刻 break，`sEnd - hitS = 0` → `tryClimb()` 永远返回 false，按跳跃只会普通起跳。

**修法**：先按 `margin=0` 找最深可站点，判完宽度后再回退 10 cm。**坑的通用形**：几何判定里，"命中条件"和"安全条件"要分开，别把安全边距塞进命中循环。

### 36. 直线插值位移一定会从盒子侧面穿过去（v0.11.41）

攀爬位移是"起点 → 顶面落点"一条 smoothstep 直线。起点在地面、落点在盒子顶上，这条斜线必然穿过棱柱侧面——用户一眼看出「攀爬穿模」。

**修法**：拆成「先垂直撑起到顶面之上（水平只走到外层表面外一个半径）→ 再水平推进到落点」。**通用形**：任何"绕过障碍的插值位移"，都要让**位移阶段**和**碰撞阶段**分开，别用一条斜线同时完成两者。

### 34. 逐个 new Mesh 会把 draw call 翻五倍（v0.11.36）

建房子时给每根栅栏柱、每条横板、每扇窗都 `new THREE.Mesh()`，还全开 `castShadow = true`。每个独立 Mesh 主画面提交一次、**2048² 阴影贴图再提交一次**；实测每帧 draw call 从 39（没房子）涨到 190，用户报「走路都掉帧」。无头浏览器帧时间看不出来（软件渲染约 105 fps），是 hook `WebGLRenderingContext.prototype.drawElements/drawArrays` 数出来的。

**修法**：`InstancedMesh(unitBox, mat)` + `Object3D` 摆矩阵，把几十个小方块合成一次提交；只有遮挡射线要按对象换材质 / 挂 `trim` 的保留独立；贴墙薄面片关投影。

**教训**：**掉帧先数 draw call，别先猜音频/物理**。用 `Page.addScriptToEvaluateOnNewDocument` hook 所有 draw 调用 + `requestAnimationFrame` 采样，不用改产品代码就能拿到每帧提交数，再拿旧版本快照 A/B 一下就知道是哪一版引入的。
