## 一、这是什么

一个**纯代码生成素材**的白色世界游戏原型。没有一张图片，所有形体由几何体和光照算出来。

一句话：**一片白色的天，一片白色的地，一个人。**

灵感来源是《Saltline》那种"素材全部由代码构建"的做法，以及"像上帝创世一样，从空白开始一点点把世界填上"的念头。

主要用**手机**玩，桌面同步支持。

## 四、已经拍过板的决定（不要擅自翻案）

| 决定 | 结论 | 理由 |
|---|---|---|
| 交付形态 | 单文件 HTML，Three.js 内联 | 手机传文件时依赖目录必丢，血泪教训 |
| 素材来源 | 只用几何体，不用图片 | 项目立项前提 |
| 素材优先级 | **能用代码生成的不用素材**（视觉、音效、动画都适用） | 用户 2026-11-13 定；单文件 + 离线可跑 + "世界由代码长出来"的命题 |
| 音效 | WebAudio 实时合成（噪声 + 滤波 + 包络），不内嵌音频文件 | 同上；ALS 有 wav 素材但按规则不用 |
| 相机 | 绕角色的球面轨道，手动转，不自动回正 | 自动跟随在手机上会晕 |
| 移动方向 | 相机相对 | 现代第三人称默认预期 |
| 地面纹理 | 不做网格 | 远处摩尔纹横条，破坏白世界的干净 |
| 参照物 | 散石 + 方块群 | 有体积有投影，不形成规律线条 |
| 世界的白 | 天纯白、地极浅灰、雾色比天暗一点点 | 硬做色差会变成"灰色山脊" |
| 角色风格 | 深色剪影，只有一个鼻凸 | 白色世界里唯一的视觉焦点 |

## 五、代码地图

`index.html` 约 1.38MB，四个 `<script>` 块：Three.js（654KB）+ 角色网格数据 `__CHAR`（417KB）+ 动画曲线 `__ANIMS`（284KB）+ 游戏本体（25KB）。

区块顺序固定，找东西按这个找：

| 区块 | 内容 |
|---|---|
| 启动自检 | `THREE` 未定义 / WebGL 不可用 / 渲染器初始化失败 / 3.5 秒没出第一帧 → 中文提示层 |
| 渲染器 | `WebGLRenderer`，PCFSoft 阴影，pixelRatio 上限 2 |
| 光影 | `HemisphereLight` 1.45 + `DirectionalLight` 1.84（跟随角色） |
| 地面 | `PlaneGeometry(300)` + `Fog(#F1F5F8, 20, 145)` |
| 道具 | 72 块大积木 / 240 颗实例化散石 / 11 座远处高塔，全部确定性伪随机 |
| 角色 | 单个 `SkinnedMesh` + 68 根 `THREE.Bone`（数据 `__RIG`），无切块 |
| 音效 | `audioInit`/`sfxStep`/`sfxJump`/`sfxLand`，WebAudio 合成，无音频文件；脚步事件来自 `__ANIMS[].steps` |
| 动画 | `ANIM` 状态机 + `samplePose`（帧间 slerp，绝对局部旋转）+ `driveAnim`（写回骨骼）+ 0.18s 跨动画混合 |
| 状态 | `P`（位置、速度、朝向、lean、落地冲击） |
| 相机 | `camYaw` / `camPitch` / `camDist` + `follow` 平滑跟随 |
| 输入 | 键盘 / 鼠标拖动 / 左半屏摇杆 / 右半屏拖动转视角 + 轻点跳 |
| 更新 | 固定步长 1/120，移动 → 跳跃 → 动画状态机 → 相机 |
| 绘制 | 摇杆画在独立 2D canvas 覆盖层 |

**角色骨架**：68 根骨骼就在 `SkinnedMesh` 的 `Skeleton` 里，局部变换来自绑定姿态（`__RIG.bones`），动画覆盖其中 25–32 根。层级：`root → pelvis → spine_01~03 → neck_01 → head`，`clavicle → upperarm → lowerarm → hand`，`thigh → calf → foot → ball`。

**动画工具链**（在 `tools/anim/`，重跑要 UE 工程副本 `D:/temp/als_export`）：

```
export_anims.py   # UE 命令行导出动画 FBX 到 D:/temp/als_anim_out（副本工程）
build_rig.cjs     # AnimMan.fbx → _rig.js（几何 + 蒙皮权重 + 骨骼绑定姿态）
bake_full.cjs     # 动画 FBX → _anims.js（每骨绝对局部旋转）
```

## 六、踩过的坑（按严重程度）

### 1. 手机打开纯白，桌面正常
- **现象**：一片白，没有任何报错提示。
- **根因**：`<script src="vendor/three.min.js">`，只把 html 传到手机，依赖目录没跟过去。
- **修法**：Three.js 整段内联。
- **教训**：给用户的页面必须**真的**只有一个文件。验证方式是"新建空目录只拷这一个 html 再跑"。

### 2. 内联之后还是纯白
- **根因**：`three.min.js` 首行是 `console.warn(...),`，靠逗号表达式让后面的立即执行函数处在表达式上下文。删掉首行后，`function(t,e){...}` 落到语句开头，被解析成**无名函数声明** → SyntaxError。
- **修法**：`*/` 后补一个 `!`。
- **教训**：校验要**每个 `<script>` 块单独** `node --check`，别只查最后一块。

### 3. 白色世界的光怎么调都不对
- **现象**：要么整片发灰，要么全过曝成纯白，天地无分界。
- **根因**：Three.js r155+ 是物理光照，`MeshStandardMaterial` 漫反射带 `1/π`，强度给 0.8 会发灰，要 3.0 量级地面才接近白。
- **修法**：hemi 1.45 / sun 1.84；地平线靠**雾色比天暗一点点**（`#F1F5F8` vs `#FFFFFF`）浮出来，不能靠地面比天暗硬做。

### 4. 只有角色脚下有影子，方块全无
- **根因**：改了 `shadow.camera.left/right/top/bottom` 但没调 `updateProjectionMatrix()`，仍是默认 ±5。
- **修法**：手动调用一次。

### 5. 角色侧面像一根柱子
- **根因**：胶囊拼接、无膝无肘、头陷进躯干里（头球底面低于躯干胶囊顶面 → 看着没脖子）。
- **修法**：躯干缩短（不是把头顶上去）、加颈、膝盖肘部分节 + 关节球、加鼻凸。
- **衍生坑**：背面视角两腿重叠成一条 → 髋间距加到 ±0.125；跳跃手臂向前抬像抱东西 → `rotation.x` 正值才是向后甩。

### 6. 转完视角按 W 还往老方向走
- **根因**：移动方向没改成相机相对。
- **修法**：`forward = (−sin yaw, −cos yaw)`、`right = (cos yaw, −sin yaw)`。

### 7. 动画接入后角色躺平（FBX 曲线四个连环坑）
> 补充（v0.9.1）：即便曲线全对，**刚性绑定**也会在关节处露缝。真蒙皮才是正解，别在切块方案上打补丁。
- **坑 1**：`Properties70` 的 `P` 节点格式是 `[名字, 类型, 标签, 标志, 值×3]`，值要从**末尾**取，从 `props[3]` 取会拿到标志位（字符串 → NaN）。
- **坑 2**：FBX 属性名带空格（`Lcl Rotation`），比对前要 `replace(/\s+/g,'')`。
- **坑 3**：`ALS_N_Pose.fbx` 这类资产**不写绑定姿态**，rest 必须从 `ALS_N_Walk_F.fbx` 统一取。
- **坑 4**：FBX `eEulerXYZ` = `Rz·Ry·Rx`（X 先施加）。写成 `Rx·Ry·Rz` 在 gimbal 附近（pelvis 的 Y≈−90°）会算出 40° 假旋转 → 整个人躺倒。
- **另一个必踩的公式坑**：局部旋转增量不能直接套。我们的骨骼组挂在「rest 世界朝向」里，增量要用**父骨 rest 世界旋转共轭**：
  `Q(bone) = W_rest(parent) · (R_anim_local · R_rest_local⁻¹) · W_rest(parent)⁻¹`，
  再转 Three 坐标 `q' = m ⊗ q ⊗ m⁻¹`（m = Rx(−90°)）。
- **验证手法**：把每个动画 pelvis/thigh 的增量角打出来，走路 pelvis 应在 10° 内、thigh 在 30° 上下。数字离谱就是上面某个坑。

### 8. 落地动画一帧就被覆盖
- **根因**：状态机每帧都调 `setAnim`，一次性动画被立刻换回 idle。
- **修法**：`if (!ANIM.oneShot) setAnim(...)`，让落地动画播完再交还状态机。

## 八、还没决定的事

3. 世界边界：无限延伸还是有限的白岛。
4. 要不要昼夜变化（会推翻现在的单一方向光布光）。
5. 角色要不要更多动作（跑、蹲、推、拾取）。
