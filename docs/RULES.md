# WORLD 01 · 章程与开发规则

> 本文件是项目的最高约束。任何改动（人改或 AI 改）都先读这里。
> 规则与代码冲突时，以本文件为准；本文件与用户当次指令冲突时，以用户为准，并在改动后回写本文件。

---

## 一、项目定位

- **类型**：单人、极简、白色世界的第三人称探索原型。
- **核心命题**：从一片空白开始，像造物一样一点点把世界填上。
- **美术铁律**：**不用任何图片素材**。所有视觉元素由几何体、光照、着色计算生成。这条不因为方便而破例。
- **交付形态**：单个 `.html` 文件，双击即开，离线可跑。

---

## 二、不可动的底线

| 编号 | 规则 | 原因 |
|---|---|---|
| R1 | `index.html` 必须保持**自包含单文件**（内含 Three.js），不得引用任何外部 JS / CSS / 图片 / 字体 | 已发生过一次事故：依赖目录没跟着文件走，手机打开纯白 |
| R2 | 不引入构建流程（webpack / vite / npm 依赖） | 要保持"双击就能开" |
| R3 | 不引入外部网络请求（CDN、字体、统计、接口） | 离线必须完整可玩 |
| R4 | 改动后必须在**孤立目录**里验证（只放这一个 html） | 桌面直接开原目录测不出依赖缺失 |
| R5 | 每次更新必须留下：一次 git 提交 + 一份 `backups/` 快照 + 一条 CHANGELOG | 版本可回退，改动可追溯 |

---

## 三、版本号规则

格式 `v主.次.修`（语义化版本的简化版）：

| 位 | 递增条件 | 例子 |
|---|---|---|
| 主 | 玩法范式改变 / 世界规则重写 / 存档不兼容 | 2D 横版 → 3D 世界 |
| 次 | 新增一项玩家可感知的能力或场景元素 | 加入视角旋转 |
| 修 | 只修 bug、调数值、改观感，不新增能力 | 修白屏、调跳跃高度 |

- 版本号**只出现在三个地方**：`docs/CHANGELOG.md` 的最新条目、git tag、`backups/` 文件名。
- 不在页面上显示版本号（保持画面纯净），但页面的 `window.__worldVersion` 要同步写入，方便线上排查。

---

## 四、每次更新的固定动作（七步，不可跳）

1. **读**：看 `docs/CHANGELOG.md` 最新一条 + 本次要动的那块代码，确认当前状态。
2. **备份**：`bash tools/snapshot.sh` 先做一次快照（哪怕改动很小）。
3. **改**：只动必要的地方。改大块结构前先想清楚回退方案。
4. **校验**：
   - `node --check` 抽取**每一个** `<script>` 块单独检查（历史上出过"库那块坏了、游戏那块是好的"的情况）。
   - 孤立目录截图：`新建空目录 → 只拷 index.html → headless 截图`。
   - 双端各看一眼：1280×720 横屏 + 390×844 竖屏。
5. **写**：更新 `docs/CHANGELOG.md`（新增一条，不删旧的）。
6. **提**：`git commit`，信息格式见下。
7. **标**：如果这次是一个可玩的里程碑版本，`git tag vX.Y.Z`。

---

## 五、提交信息格式

```
<类型>: <一句话说清做了什么>

<可选的补充：为什么这么做、放弃了什么方案>
```

类型只有五种：`feat` 新能力 / `fix` 修问题 / `tune` 调数值手感 / `docs` 文档 / `chore` 杂务。

例：

```
feat: 相机改为绕角色的轨道，支持转视角

原相机固定方位，转不了身。改成 yaw/pitch/dist 球面轨道，
移动方向同步改为相机相对，否则转完视角按 W 还往老方向走。
```

## 六、文档同步义务

改动触及什么，就必须同步更新对应文档，**不允许代码改了文档还停在旧版本**：

| 改了什么 | 必须更新 |
|---|---|
| 任何改动 | `docs/CHANGELOG.md` |
| 画面风格、光照、配色、形体语言 | `docs/DESIGN.md` 的「视觉语言」 |
| 相机、渲染、场景组织、坐标系 | `docs/DESIGN.md` 的「技术架构」 |
| 操作方式、按键、手势 | `docs/GAME.md` 的「操作」+ 页面内提示文案 |
| 数值（速度、跳跃、重力、尺寸） | `docs/GAME.md` 的「数值表」 |
| 新增/删除世界元素 | `docs/GAME.md` 的「世界元素」 |
| 规则本身变化 | 本文件 |

## 七、代码风格约定

- 纯 ES5 语法（`var` / `function`），不用箭头函数、`let`/`const`、模板字符串。理由：老旧手机浏览器兜底。
- 单文件内用 `/* ---- 区块名 ---- */` 分段，区块顺序固定：自检 → 渲染器 → 光影 → 地面 → 道具 → 角色 → 状态 → 相机 → 输入 → 更新 → 绘制 → 主循环。
- 所有可调数值集中在文件顶部或紧邻其使用处，**不要散落**。
- 参数命名宁可长一点要能读懂，不用 `a` / `b` / `t1` 这种。

---

## 八、明确不做的事

- 不为了"看起来更厉害"而增加系统。**能少一个元素就少一个**。
- 不加加载动画、不加开场 Logo、不加音效开关 UI。世界干净是设计的一部分。
- 不在没有验证的情况下说"做好了"。
- 不用生成式图片素材替代几何体。
- 不做多文件拆分、不做模块化重构（除非单文件真的撑不住了，那要作为一次「主版本」决策并记录理由）。

---

## 九、待决策清单

以下有分歧、尚未拍板，改动前先问用户：

1. 相机是否要「松手自动回正」（转完视角几秒后缓慢回到角色背后）。
2. 世界边界怎么处理：无限延伸，还是一个有限的白岛。
3. 是否要昼夜/太阳角度变化（会推翻当前单一方向光的布光）。
4. 角色是否需要更多动作（跑、蹲、推、拾取）。
