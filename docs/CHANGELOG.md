## v0.11.41 — 2026-11-13

**碰撞体积模式 · 修攀爬穿模 · 桌面鼠标指针锁定**

### 1. 碰撞体积模式（`C` 键 / 手机「碰撞」按钮）

用户要「看所有物体的实际碰撞」。按 `colliders` 里的同一套 2.5D 数据（中心 / 半宽 / 半深 / yaw / 顶面高度）把每个棱柱画成绿色线框，再加一个蓝色玩家胶囊（r = 0.36 / 高 1.86）。

- 所有盒子合并进**一个** `BufferGeometry` + `LineSegments`，一次 draw call（96 个碰撞体 × 12 条边 × 2 顶点 = 2304 顶点）。
- `depthTest: false` + `renderOrder 990`：被墙挡住的碰撞盒也能看见，方便核对"模型看到的"和"真正挡人的"差多少。
- 玩家胶囊每帧跟随 `P.pos`，可以直接看攀爬过程中胶囊有没有插进盒子。
- 入口：桌面 `C`、手机右上第四枚「碰撞」（点亮 = 开启）。调试钩子 `__world.setColViz()`。

### 2. 修攀爬穿模

v0.11.40 的位移是一条 `smoothstep` 直线：从起点直接插到障碍顶面。45° 的斜线会**穿过棱柱侧面**，看着就是人从方块里钻过去。

改成两段：

| 段 | 占比 | 轨迹 | 作用 |
|---|---|---|---|
| ① 撑起 | 前 52% | 起点 → 障碍外表面外一点（`hitS − PLAYER_R`）、顶面 +0.06 | 上升时身体始终在盒子外侧 |
| ② 翻上 | 后 48% | 该点 → 顶面落点 | 此时已高于顶面，水平推进不穿 |

自动化验证：攀爬全程 60 Hz 采样胶囊与目标盒子的水平间隙、判断「间隙 < 半径 且 低于顶面」为穿透 —— **穿透次数 0、最大深度 0**（修改前会从侧面穿进去）。

### 3. 桌面鼠标指针锁定

按用户要求改成 RPG 式：**点一下画面 → 指针被锁定隐藏 → 鼠标移动直接转视角**，`Esc` 退出。

- 锁定态用 `movementX / movementY` 调 `turnBy`，不需要按住左键。
- 保留未锁定时按住拖动的兜底路径（浏览器或 iframe 拒绝锁定时不至于完全不能转）。
- `pointerlockerror` 静默回退；`requestPointerLock()` 返回 Promise 时挂 `.catch()`，避免未处理的拒绝。
- 手机端完全不受影响（`pointerType === 'mouse'` 才进这条路径）。

| 实测 | 结果 |
|---|---|
| `C` 键 | 线框数 = 96 个碰撞体，2304 顶点；再按隐藏 |
| 手机「碰撞」按钮 | 点亮/熄灭与可视化同步；四枚按钮 14/56/98/140 竖排不重叠 |
| 攀爬穿透采样 | 0 次（阈值 2 mm） |
| 攀爬结果 | 空格与手机轻点都到 `y = 1.15`（= 顶面），结束回 idle |
| 锁定态移动 | `movementX 120` → yaw 0 → −0.744；解锁后同样移动 yaw 不变 |
| 未锁定拖动 | 兜底生效（yaw −0.744 → −1.364） |
| 回归 | 手势、45° 锁定、主题、`H`/`L`/`T`、遮挡遮罩、孤立目录零外部请求、120 fps 全过 |

## v0.11.40 — 2026-11-13

**攀爬：靠近 1m 左右障碍按跳跃 → 播 ALS Mantle 撑上去**

用户要求「把攀爬做一下」，追问后确认：素材去 ALS 项目里找、触发方式是靠近障碍按跳跃。在 UE 工程副本的 `Actions/` 下找到 `ALS_N_Mantle_1m_LH/RH`，数据上一版已导出内联，这版接玩法。

- **触发**：`doJump()` 先调 `tryClimb()`；命中就播攀爬、不进起跳缓冲。键盘空格和手机轻点都走 `doJump()`，所以两端都能触发，没加新按键。
- **判定**：沿 `P.face` 探 0.30–1.20 m，找高度 `0.45–1.25 m`、顶面 `hw/hd ≥ 0.30 m` 的碰撞体。低于 0.45 的自动迈台阶就够了；高于 1.25 爬不上；栅栏这类薄片（顶面站不住）排除。
- **位移**：Mantle 动画只有骨骼旋转、没有 root motion，位置由 `advanceClimb()` 用 smoothstep 从起点插值到障碍顶面（前 82% 时间完成），结束时钉在落点。
- **物理冻结**：`update()` 的整段物理（输入 / 加速度 / 碰撞 / 重力 / 起跳缓冲）包进 `if (climb) … else …`；攀爬期间 `vel=0`、`vy=0`、`onGround=true`，避免重力或墙把人拽回去。朝向、倾斜、动画状态机等公共部分照常跑。
- 一次性动画用现成的 `ANIM.oneShot` 机制，播放期间状态机不抢；`driveAnim` 只在 walk/run/sprint 触发脚步音，mantle 不会误播脚步。结束时补一声轻落地音。

**踩的坑**：落点检查一开始用了 10 cm 安全边距，但命中点本身就在盒子边缘，加边距后立刻判「站不住」，攀爬永远不触发。改成先找最深可站点、再回退 10 cm。

## v0.11.36 — 2026-11-13

**修掉帧：房子的小构件全部合并成 InstancedMesh，每帧 draw call 190 → 62**

用户报「走路都掉帧」，问是不是没带耳机、用外放导致的。**不是**：脚步音效每帧不做事，只在动画脚触地事件里播一声（走约 2–3 次/秒），WebAudio 走的是预解码的 `AudioBufferSourceNode`；万一被浏览器拦了，备用链路也只是复用池里已创建的 `<audio>` 元素，不新建节点。耳机/外放只影响输出设备，不影响渲染线程。

真正的原因用 WebGL draw call 计数查出来了：

| 版本 | 每帧 draw call |
|---|---|
| v0.11.33（没房子） | **39** |
| v0.11.34 / 35（房子） | **190** |
| v0.11.36（本版） | **62** |

v0.11.34 建房子时，栅栏柱、横板、门廊、烟囱、树干、门窗面片等约 95 个小方块全用 `new THREE.Mesh()` 单独建，而且全部 `castShadow = true`。每个独立 Mesh 主画面一次、**2048² 阴影贴图再一次**，等于平白多出 151 次提交；手机上阴影相机每帧跟着角色重画，走路时最明显。

改法（外观完全不变）：

- 只有**遮挡射线要按对象换材质、或要挂 `userData.trim`** 的网格保留独立：主屋墙、车库墙、两片屋顶、四块树冠、门窗面片。
- 栅栏（约 70 根柱 + 12 条横板）、门廊平台/雨棚/柱、烟囱、树干、灌木 → 全部走一个 `InstancedMesh(unitBox, propMat)`，**1 次 draw call（阴影再 1 次）**。
- 车库卷帘门的四条横槽合成另一个小 `InstancedMesh`，整体作为一个 `trim` 挂到车库墙上，遮罩时一起 `visible = false`。
- 门窗这类贴墙薄面片关掉 `castShadow`：背后就是墙，投影看不见，纯浪费。
- 碰撞体原本要造一个"只登记不渲染"的 Mesh，现在只传 `{position, rotation}` 字面量（`addCollider` 只读这两个字段）。

|---|---|
| 外观 | 正面/侧面/俯视截图与改动前一致，栅栏、门廊、窗、车库门、树都在 |
| 碰撞 | 撞主屋 z=−16.04 且站上门廊 y=0.3；撞栅栏 z=−8.54；车道进院到 z=−12.35 |

## v0.11.26 — 2026-11-13

**贴墙摩擦：正面撞墙站住，不再被"送"到方块边缘**

用户报：「撞到方块不松开前进，角色会朝方块边缘走，一直走到没有墙再往前走。」实测确认不是 bug——法向速度清零、切向原样保留，就是标准的贴墙滑。问题在于方块是随机旋转的，"撞正"几乎不发生，于是每次都被慢慢蹭走。

改法：贴墙时按 **压墙力度** 给切向速度加摩擦。

```
press = −(目标速度 · 墙法线)            你有多想往墙里钻
切向速度每秒衰减 WALL_FRIC × press      WALL_FRIC = 3.5
```

- `press` 必须取**目标速度**（`tx,tz`），不能取本帧的速度投影：法向分量上一帧就被清过，只剩一帧重新加速的那点量，按它算摩擦等于没有（第一版就栽在这，改完数据几乎没变）。
- 只在 `onGround` 时生效，空中蹭墙不减速。

实测（4×4 m 墙，按住前进 1.6 s + 再按 0.8 s 看还会不会继续挪）：

| 撞墙角度 | 1.6 s 横移 | 再按 0.8 s 又挪 |
|---|---|---|
| 0° | 0.00 m | 0.00 m |
| 5° | 0.17 m | 0.01 m |
| 10° | 0.35 m | 0.02 m |
| 20° | 0.76 m | 0.05 m |
| 30° | 1.31 m | 0.07 m（基本顶住） |
| 45° | 5.20 m | 2.54 m（照常滑） |
| 75° | 7.06 m | 3.48 m（≈ 满速 4.4 m/s） |

也就是：**30° 以内撞墙就是墙，45° 以上还是坡**。拐角仍会顺着力矩抹过去，暂时没动。

射线方向改成和正交相机一致（`camYaw` + `TOP_PITCH`），被扫到的物体换 `ghostMat`（0.26 不透明度）。第三人称下不换材质——否则被扫到的积木会凭空变透明。

### 5. 俯视跟随更紧
`follow` 的 lerp 在俯视里用 8（其余用 4.2）：战术视角下角色飘出画面中心会很别扭。

**三档视角：第三人称 / 上帝视角（遮挡遮罩）/ 第一人称**

### 1. 视角循环
手机右上角新增「视角」按钮，桌面按 `V`，三档循环：

| 档位 | 按钮文字 | 相机 | 说明 |
|---|---|---|---|
| 第三人称 | 视角 | 球面轨道 8.6 / 9.9 m，俯角可调 3°–57° | 原来的默认视角 |
| 上帝视角 | 俯瞰 | 俯角锁 66°，距离 15 m（横）/ 18 m（竖） | 拖动只转水平，俯仰固定 |
| 第一人称 | 第一 | 眼睛高度 1.62 m，随视线方向看 | 拖动上下抬头/低头，身体跟着视线转 |

两个 `blend` 量（`godBlend` / `fpBlend`）各自平滑，相机位置按 `fpBlend` 在"轨道位置"与"眼睛位置"之间插值——`fpBlend = 0` 时逐字等于原来的第三人称，所以老视角没有回归风险。

### 2. 上帝视角的遮挡遮罩
相机抬高后被积木/高塔挡住时，**不把相机拉近**（拉近就没俯瞰感了），而是把角色与相机之间的所有遮挡物换成半透明材质（`opacity = 0.26 × godBlend`，`depthWrite = false`），角色始终看得见。退出上帝视角时材质换回 `propMat`。

这个遮罩只在上帝视角里生效——一开始没加判断，第三人称下射线扫到的积木也会被换成透明，方块凭空消失。

### 3. 第一人称
- 身体跟随视线（`faceTarget = camYaw + π`），否则按前进会横着走（移动本身早就是相机相对的，这里只是让身体也转过来）。
- `fpBlend > 0.45` 时隐藏自身网格，避免看到头部内部；提前到 0.45 是因为 0.7 时相机已经在体内穿模。
- 上下看用独立的 `fpPitch`（±66°），不动 `camPitch`，切回第三人称时俯角还是原来那个。

### 4. 修自己造的回归：相机不跟人
重构相机段时把 `follow` 的平滑跟随（以及 `camKickT/camKickV` 的衰减）整段删掉了，结果相机永远盯着原点——角色跑出十几米就看不见人。测试脚本一比对相机坐标与角色坐标才暴露。

教训：**重写一段代码时先看被替换掉的旧段有哪些副作用，不能只看新段要达成什么。**

## v0.11.15 — 2026-11-13

**起跳长帧 60~100ms：data URI 每次 play 都在重新解析**

用户确认长帧全部落在 `jumpWalkL / jumpRunL`、60~100ms。起跳帧的同步开销只可能来自音频播放（`el.play()`），而备用链路的音频元素用的是 `data:audio/wav;base64,...` **data URI**——iOS / 部分 webview 每次播放都可能重新解析整段 base64，同步阻塞几十毫秒，数字完全对得上。

## v0.11.13 — 2026-11-13

**继续修持续跳跃掉帧（30 多帧 + 卡顿）**

v0.11.12 之后仍会"一直跳就掉到三十多、卡顿"。两个残留漏洞都指向"持续跳跃 = 持续累积"：

### 1. 备用音频链路没有早退
v0.11.11 的早退条件只认 WebAudio 正常。而**这台手机的 WebAudio 一直被拦，实际走的是 `<audio>` 备用链路**（`_wavOk`）——早退条件不成立，所以每次轻点的 5 个手势事件仍在跑完整解锁路径（resume、播空 buffer、安排 `setTimeout` 检查），一直跳就一直堆积。补上 `_wavOk` 早退。

### 2. 每次切动画都重建 64 个四元数
`setAnim` 里清空 `_poseCur` / `_posePrev` 两个字典，下一次采样再重建——一跳有 4 次动画切换（起跳→下落→落地→跑步），等于 256 个临时对象变垃圾。持续跳跃就是持续 GC 尖峰，这就是"卡顿"的手感来源。

改成字典永不清空、对象只创建一次；`driveAnim` 按当前动画声明的骨集合判断归属（残留骨不参与）。

**验证**：状态序列正常（jumpWalk → fall → landHeavy → idle）；内存对照——静止 10s +131KB、连跳 12 次 −947KB（GC 正常回收，无泄漏）；音频两链路、脚步事件（3s 9 步）全过。

## v0.11.12 — 2026-11-13

**动画采样降频：减轻跳跃混合期的手机掉帧（v0.11.11 后残余）**

v0.11.11 修掉了音频手势开销，掉帧从"十几帧"好转到"40 多"，但跳跃时仍掉。剩余瓶颈：**跳跃全程都在动画混合状态**（起跳→下落→落地→跑步四次切换），混合时每渲染帧要采 4 次全骨架姿态（68 骨 slerp ×2 套 ×2 次）——而物理循环 1/120 意味着 60fps 手机每渲染帧要跑 2 次 update，采样和写骨全部翻倍。走路大部分时间不混合所以没事，跳跃全程混合就暴露了。

修法：`driveAnim` 从物理循环（120Hz）移到渲染帧（60Hz）。骨骼动画的采样本身就是插值，60Hz 采样视觉完全无差，计算量减半。脚步事件 `fireSteps` 本来就支持跨帧区间和循环回绕，已验证 3 秒跑动 9 步无遗漏。

## v0.11.11 — 2026-11-13

**修：跳跃时掉帧严重（60 → 30 甚至十几帧）**

排查路径：桌面帧间隔统计显示跳跃与静止完全一致（8.7ms/帧）——JS 渲染逻辑不是瓶颈，掉帧是手机特有。

真凶：**一次轻点跳跃会触发 5 个手势事件**（pointerdown / touchstart / pointerup / touchend / click），每个事件都完整跑一遍 `audioUnlock`，其中 `wavUnlock()` 每次都做一次 `play → pause` 启停媒体管线，加上跳跃音效 + 落地音效本身，一次跳跃前后要启停媒体管线 7~8 次。手机上媒体管线启停是同步大开销，全砸在跳跃这一两秒里。

- WebAudio 已确认能响 + 状态正常时，**手势里直接早退**（音频操作归零）
- `wavUnlock` 改为只做一次（本来的用途就是"解锁一次"）
- 从后台切回 / 状态挂起时不受影响，解锁路径完整保留

## v0.11.4 — 2026-11-13

### 一、音效：合成 → 原版录音

用户反馈"和原版完全不像、太难听"。确实——噪声 + 滤波做不出真实混凝土脚步的瞬态和颗粒感，这是合成方法的先天短板。

按 `RULES.md` 第 6 条的第二档处理：从 ALS 项目的 `Audio/Footsteps` 里取出 **16 个原始录音**（`Concrete_Walk/Run/Step/Pivot`）。这些 `.uasset` 里直接内嵌了原始 WAV（96kHz 单声道），把 RIFF 段切出来即可。

- 走：`Concrete_Walk_01~05`（5 个变体）
- 跑：`Concrete_Run_01~04`（4 个变体）
- 起跳/落地：`Concrete_Step_01~03` + `Concrete_Pivot_02`（ALS 原版跳跃落地也是播脚步 Notify）

## v0.11.2 — 2026-11-13

**手机上提示「声音被挡住了」——找到真正的原因了**

`AudioContext` 是在**非用户手势**的上下文里创建的：`update()` 的兜底解锁在页面第一帧就把上下文建了出来。Chrome 允许事后 `resume()`，但 iOS Safari（以及多数 webview）对"不是在手势里创建的实例"经常永远起不来，`resume()` 返回成功、状态却一直是 `suspended`。

### 改了什么

- **上下文只允许在手势里创建**。`audioReady()` 和 `update()` 的兜底都不再新建实例，只对已存在的实例 `resume()`
- 如果检测到手里的实例是"非手势创建的"，第一次真手势时直接关掉重建
- 连续两轮手势仍不 `running` 也重建一次（有些 webview 的首个实例是坏的）
- 手势监听覆盖 `pointerdown / pointerup / mousedown / touchstart / touchend / click / keydown`，另加 `visibilitychange`（从后台切回来要重新 resume）和 `WeixinJSBridgeReady`
- 提示条会显示实际的上下文状态，例如「🔇 声音被挡住了（suspended）· 点这里再试」，方便判断卡在哪一层

### 验证

手势前 `__audioState().state === 'none'`（不再提前建上下文），模拟触摸后立刻变 `running`，跑动峰值 0.64。

### 曲线解析踩的四个坑（都已修）

1. **Properties70 的 P 节点**：格式是 `[名字, 类型, 标签, 标志, 值×3]`，值要取末尾 3 个数值；
2. **属性名带空格**：FBX 里是 `Lcl Rotation` 不是 `LclRotation`；
3. **rest 姿态只在部分文件里**：`ALS_N_Pose.fbx` 不写绑定姿态，rest 必须从 `ALS_N_Walk_F.fbx` 读；
4. **欧拉顺序**：FBX `eEulerXYZ` 对应 `Rz·Ry·Rx`（X 先施加），写成 `Rx·Ry·Rz` 会让 pelvis 扭 40°、角色躺倒。

### 关键公式

我们的骨架组挂在「rest 世界朝向」的组里，而 FBX 的局部旋转增量表达在父骨 rest 坐标系内，必须用父骨 rest 世界旋转共轭：

```
Q(bone) = W_rest(parent) · (R_anim_local · R_rest_local⁻¹) · W_rest(parent)⁻¹
```

再整体转到 Three 坐标系：`q' = m ⊗ q ⊗ m⁻¹`，`m` = Rx(−90°)。

- 切换混合 0.18s（四元数 slerp）

## v0.2.1 — 2026-11-13

**修复手机上打开纯白**

### 修正

- 根因：`index.html` 通过 `<script src="vendor/three.min.js">` 引用引擎，只把 html 传到手机时依赖目录没跟着走，`THREE` 未定义，脚本首行即中断，canvas 全白且无任何提示。
- Three.js 整段内联进 html，文件变为自包含单文件（约 690 KB）。
- 内联时删掉库首行 `console.warn(...)` 导致紧跟的立即执行函数落到语句开头、被解析为无名函数声明而报错，已改用 `!` 前缀修复。

### 新增

- 启动自检层：引擎未加载 / WebGL 未启用 / 渲染器初始化失败 / 3.5 秒未出第一帧，四种情况均在屏幕中央显示中文原因，不再白屏。

### 变更

- 验证方式改为「孤立目录测试」：新建空目录、只放一个 html、headless 截图。
