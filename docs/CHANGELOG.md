## v0.30.5 · 2026-11-18 · 虚空换成灰烬与雾；便利店音乐重写

> 「不要光点，搞点符合氛围的。音乐你直接复刻那首歌行吗，我又不发布我自己玩的作品而已」

### 1. 光点换成灰烬

原来的 160 个加法混合亮点，看起来像星空/萤火，和"虚空"不是一个东西。换成：

| 元素 | 做法 |
|---|---|
| **灰烬** | 140 片，在片元着色器里用噪声裁出不规则边缘、各自缓慢自转，尺寸随距离与种子拉开（0.45~2.35 倍）；缓慢**下坠** + 左右飘，边缘比中心亮一点，像被门里的光擦到一角 |
| **低空薄雾** | 一层 64×64 贴地薄雾，缓慢推移（`sin/sin` 两层），给"空"一点厚度，也给灰烬一个落处 |
| **远景剪影** | 五组巨大的暗色轮廓（15 个棱柱，色 `#020306`，比天幕更暗）铺在 18~30m 外。近处三扇门很小、远处那些很大，虚空才有尺度 |

关键取舍：灰烬用**普通混合**不是加法混合——加法会发亮，普通混合才是"被光擦到的碎屑"。默认 12m 取景下剪影在画面外，拉到 30m 以上才出现，等于给愿意看远的人一个回报。

### 2. 便利店音乐重写（仍是原创）

明确一句：**没有复刻《Country Roads》**。那首歌的词曲仍在版权保护期，私用也不改变"复制他人作品"这件事，所以按那个**语感**重写：

- 84 BPM、G 大调、I–V–vi–IV（G–D/F#–Em–C），低音**级进**下行 G→F#→E→C
- 拇指打拍：1、3 拍踩低音，第 3 拍换五度（乡村最常见的交替低音）
- 食指分解：八个八分音符（根-三-五-八往返），每小节后半拍补一个高音
- 每根弦带 **4ms 拨片噪声**（不是纯正弦），旋律加 **5.2Hz 揉弦**
- 11.43 秒一循环，峰值归一 0.85、RMS 0.210、无非法采样

**要真放那首歌**：`storeMusicRecording` 那个槽位已经留好——把你自己合法拿到的录音转成 data URI 填进去，游戏会优先播它，合成的那支自动退到后备。

## v0.30.4 · 2026-11-18 · 虚空加空间感；便利店有了乡村民谣

> 「纯黑太平了，来点空间扰动的感觉看看。便利店的音乐呢，乡村路」

### 1. 虚空不再是纯黑

- **天幕**：一个反面球壳（半径 320），三层正弦叠出的慢速扰动——大团 / 中团 / 细纹，外加一条漂移的带子。扰动作用在视线方向上（`d2 = normalize(d + n * 0.11)`），所以上下层次会被"弯"掉，不是一条直边。
- **亮度**：底部约 6/255、中部 11~15、顶部 19~22（8bit）。既有层次，又不至于变成灰雾。
- **尘点**：160 个点，缓慢上浮、左右微摆、近大远小，加法混合；顶点着色器里算，CPU 零开销。
- **消色带**：极暗的平滑渐变在 8bit 下会起同心条纹，加半级抖动打散。
- **旋钮**：`VOID_HAZE`（天幕总强度，1.0 为现值）；其余亮度仍在 `VOID_BG / VOID_HEMI / VOID_SUN` 里。
- **踩到的坑**：`ShaderMaterial` 构造时会 `UniformsUtils.clone()` 深拷 uniforms，`voidClock.value` 写了没用——表现为"背景在动但帧间零差异"。改成创建后把 `uniforms.uTime` 指回同一个对象，主循环只改 `voidClock`。实测 6 秒间隔两帧：纯背景区 100% 像素有变化、平均差 8~9/255。

### 2. 便利店音乐（原创乡村民谣）

- 没有引用《Country Roads》或任何现成曲子的旋律；按那个语感写了一支原创循环：**G–D–Em–C、92 BPM、每和弦四拍、10.43 秒**。
- 三层：拍点低音、八分音符钢弦分解（根-三-五-八）、一句稀疏的口哨感旋律（G 大调五声音阶）。
- 末音尾巴按取模写回开头，**循环接缝端点差 0.0001、斜率差 0.0004**（用假 AudioContext 在 Node 里量的）。
- 峰值归一 0.85、RMS 0.209、无非法采样；音量 0.20（花园 0.28 / 旧测试场 0.14）。
- `storeMusicRecording` 有值就优先用录音，为空才走合成——以后塞真录音不用改代码。

## v0.30.3 · 2026-11-18 · 原野改成真正的虚空

> 「原野黑一点，要虚空感」

**问题**：出生世界已经没有地面和布景了，但光照还是「空场」那套——环境光 ×1.9（当年为了照亮一整片地面）、太阳 ×1.05、背景 `#15171b` 还带点蓝灰。结果三门亮亮地立在灰底上，像摆在摄影棚里，不像悬在虚空。

**改法**（参数集中成四个常量，以后调只要改这一处）：
| 常量 | 值 | 说明 |
|---|---|---|
| `VOID_BG` | `0x05060a` | 背景几近纯黑，只留一丝冷蓝 |
| `VOID_HEMI` | `0.30` | 主题环境光倍数，原来 1.9 |
| `VOID_SUN` | `0.38` | 主题太阳光倍数，原来 1.05 |
| `VOID_FOG_NEAR/FAR` | `6 / 90` | 雾色＝背景色，远处直接融进黑 |

另外出生世界关掉太阳阴影（`sun.castShadow = !isVoid`）——没有地面就没有投影可落，省一趟阴影渲染。

**取舍**：试过 0.20（更黑）——石拱门会糊成一坨黑，角色几乎看不见；0.36（更亮）——角色清楚但门偏亮、虚空感变弱。**0.30 / 0.38** 是能同时保住「角色看得见」和「门浮在黑里」的位置。

**实测**：近景/远景各一张对照；其余三层亮度未变（改动只在 `isVoid` 分支）；碰撞 1075 未变、审计 0、零外部请求。

滚轮/捏合改的是目标值（`isoViewH`），实际机距（`isoDistCur`）还要被每帧 ~100ms 的指数缓动追——**双重平滑**：手指/滚轮停了画面还在后面"补"。修法：`isoZoom()` 与捏合处理器在改目标值的同时**直接把机距落到位**——手指在哪画面就在哪，零延迟；缓动只保留给进档/转屏这类系统性变化（避免切进等距时画面猛地一缩）。

### 1. 为什么必须是正交投影

透视相机的平行线**永远**会收敛：不管 FOV 调到 10° 还是 5°，屋顶的上沿和院子的地砖就是不可能对得齐。等距（isometric）在画法几何里是一件确定的事：

- 投影方式 = **正交**（平行投影），不是透视
- 仰角 = `atan(1/√2)` = **35.264°**
- 方位 = **45°** 的整数倍（经典四向：45 / 135 / 225 / 315）

三条都做到了才叫等距。缩窄 FOV 只能得到"看起来像"。

### 2. 怎么叠进去的（不动原有的三档）

不换掉原来那台相机——`camera`（`PerspectiveCamera`）继续负责第一 / 第三 / 自由，新增一台 `orthoCam`（`OrthographicCamera`）。两台每帧同位置、同朝向，`activeCam` 决定 renderer 用哪台。

关键在**接缝**：正交视锥半高取 `机距 × tan(FOV/2)`，于是两台相机在**枢轴平面**上等大。

- 切投影的那一刻不跳（枢轴处尺寸连续）
- "远处不变小"从第一帧就成立
- 进等距时俯角/机距是缓动的，缩放开合也是连续的

```
半高 = 机距 × tan(FOV/2)  →  正交画面在枢轴处的世界高度 = 透视画面在该平面的世界高度
```

实测：`halfH 11.9998 vs expectHalfH 12.0000`（差 0.0002，浮点误差）。这条不成立就说明投影和机位脱节了，所以专门放进测试断言。

### 3. 取景：用"纵向覆盖多少米"来定

一开始按"画面窄边覆盖多少米"算，竖屏窄边是宽，纵向直接撑到 34.6m——**人是画面里一个小点，上下全是空地**。改成以纵向高度为主变量：

| 握法 | 纵向覆盖 | 角色占屏高 | 备注 |
|---|---|---|---|
| 横屏 | 28m | ≈6.3% | 房子完整 |
| 竖屏 | 28m | ≈6.3% | 横向 12.9m，竖屏的固有代价 |

两种握法下角色看着一样大。滚轮 / 双指改的就是这个米数（`ISO_VIEW_H_MIN 6` ~ `MAX 90`）；正交下没有 FOV 可调，缩放只能这么来。

**28m 是量出来的**：`DESIGN 3.4` 里 v0.11.39 删掉正交的理由之一是"出生点的房子跑出画面上边"。这次专门拿这个理由当验收项：24m 时房子顶部仍被顶出去（等距会把前方的东西推到画面上方），30m 完整、28m 刚压住边。当初的否决是对的，所以这一项必须验，不能装看不见。

| 操作 | 等距下 |

### 5. 一处实测才发现的问题

进等距时机距从 `camDist`（8.6）起步，但自由视角实际在 23——镜头会**先一头钻进去再退出来**，0.5 秒的"抽一下"。改成从 `effDistNow`（上一帧算完的实机距）起步。过渡帧截图对比确认过：现在是从当前画面直接推远，没有往返。

## v0.13.3 — 2026-11-14

**运动系统补 ALS 的脚部 IK（Foot IK）。上一版结尾记的"坡屋顶两脚一悬空一陷入"，这版修掉了。**

### 从"骨盆补偿"改成"逐腿两骨 IK"

旧实现只有一层骨盆补偿：量到脚陷进地里就把骨盆整体抬一点。**修好一只脚必然压坏另一只**——斜坡上两脚支撑差实测 9.9cm，骨盆只有一个值，物理上无解。

现在对每条腿单独解两骨 IK：

```
骨盆 → 大腿(0.426m) → 小腿(0.402m) → 脚踝 → 前脚掌
目标：脚踝 = 该脚自己脚下的支撑高度 + 平地站立的踝高 0.100m（实测值）
```

解法是平面余弦定理，没有迭代求解器：① 整条腿绕髋转到「髋→目标」方向；② 再绕膝把「髋→踝」长度收到目标长度。膝盖往哪边拐由**身体正前方**决定（pole 向量），所以反关节在这里不可能发生。

### 分工：骨盆管"公共量"，腿管"差异"

这是这一版最关键的一条，也是踩过坑才明白的：

| 情况 | 谁修 | 为什么 |
|---|---|---|
| 平地站立，两脚一起浮 2~4cm | **骨盆下沉** | 腿已经接近伸直（膝角 168~171°），伸不了，往下没有余量。只能整体沉 |
| 斜坡，一脚高 10cm、一脚低 10cm | **逐腿 IK 抬 uphill 那只** | 骨盆补不了差异；而抬脚只会让腿变弯，永远有余量 |

所以 `updateFootContact()` 分两遍：先量每只脚的落差，取两者最小值交给骨盆（限幅 −0.16 ~ +0.08m），剩下的差额再逐腿 IK。**剩余量恒 ≥ 0，也就恒可解**，不会出现"腿被拉成橡皮"。

### 脚掌朝向独立控制

屈膝会把小腿和脚掌一起转过去（实测左腿 167°→122° 时鞋底翻了 45°，前脚掌插进屋顶 7.2cm）。所以位置解完后，**脚掌的世界朝向强行恢复成「动画原本的朝向 × 贴坡旋转」**，局部四元数由小腿的新朝向反解。脚的姿态从此与膝盖怎么弯无关。

贴坡量靠 `supportAt` 在踝点周围打两个差分取梯度，倾斜到地面法线；超过 31° 的梯度当台阶断崖处理（不贴）。走动时按速度衰减（`1 - v/1.3`），不然会像粘在坡上滑步。

### 实测

|---|---|---|

| 18.2° 坡屋顶 左脚 | 陷进坡面 0.001（脚踝）| **0.099（=踝高 0.100）** |
| 18.2° 坡屋顶 右脚 | 悬空 0.193 | **0.099** |
| 两脚落差 | 9.3cm | **0.0cm** |
| 坡上鞋底（前脚掌）穿模 | −7.2cm | **−1.1cm**（平地是 −0.4cm） |

| 脚掌贴坡角 | 0° | **18.2° × 2（正好等于坡度）** |

### 三个坑，都留了注释

1. **膝盖离连线不到 1mm 时，叉积归一化是噪声**。第一版用 `cross(髋→踝, 髋→膝)` 当屈膝平面法线，站立时腿几乎伸直，归一化后是随机方向——实测脚横着飞出去 21cm。改用身体正前方当 pole。
2. **单次解析解只剩 1.8cm 残差**。因为原动画的膝盖未必落在"垂直 + 正前"这个平面里。改成每帧解 3 轮，每轮重新量当前踝位、解剩余差额，收敛到毫米级。
3. **脚掌会跟着屈膝一起转**（见上）。这是"看起来贴上了但鞋尖还在墙里"的根因。

## v0.13.2 — 2026-11-14

**运动系统补 ALS 的原地转身（TurnInPlace）。**

### 接了：原地转身 90°

- 站定时目标朝向差出 **60° 以上**，不再是"用 lerp 把身体拧过去"（那是原地滑冰），而是播 ALS 原版的 `TurnIP_L90/R90`，脚真的会碾过去。转身时播放 pivot 步声。
- **转角来自动画，不是代码硬转**。这 90° 打在骨架最顶层的 `root` 骨上（骨盆本身不动，数据实测：root 从 0→90°，pelvis 恒为 0）。所以 `P.face` 在播放期间冻结，视觉上的转动全部由 root 骨提供。
- **结算**：播完/被打断时把 root 骨当前的 yaw 加进 `P.face`，同时把 root 骨同帧归零（`hardCut`，不做姿态混合）。不这么做的话，`P.face` 和 root 骨会各转一次，变成 180°；而留混合时间会让 90° 慢慢褪回 0，看起来像"转过又转回去"。
- **角度自适应**：素材只有 90°，但实际要转的可能只有 70°。转到"够用"就收（`TURN.want`），不会转完再倒回来像甩了一下。
- **视线稳定才转**：`faceTarget` 连续 0.12s 没变才允许触发。玩家甩鼠标看风景时，身体不会跟着原地转圈。
- **打断保护**：转身中途推方向键，会把"已经转过的角度"结算进 `P.face` 再切到移动动画，朝向不会跳。
- 转身期间脚踩 pivot 音（ALS 原版 `Concrete_Pivot`），冷却 0.42s。

### 一个必须记下来的根因

第一版转身**永远不触发**。原因是站定时朝向 lerp 是 12/s，视线停稳的那 0.12s 里它已经把角度吃掉了 76%，等转身条件成立时残差早就小于阈值。

这不是参数没调好，而是**两套机制在抢同一件事**：ALS 用 TurnInPlace 解决"站定转身"，我们却同时留着"lerp 自动转身"。修法是站定且视线未稳时冻结 lerp（`faceFreeze`），走路时不冻结（移动方向优先）。

### A. 手机性能

- **真凶是 fill rate，不是 JS**。原来手机上也开着 MSAA（`antialias: true`）、像素比按 3x 走（`devicePixelRatio` 3）、阴影 2048 + `PCFSoftShadowMap`，等于把每像素成本叠了好几倍。上一版用 CDP 在 4 倍 CPU 降频下测不出掉帧，进一步说明瓶颈在 GPU / 显存，不在主线程。
- 新增 `IS_MOBILE` 判定：先看 UA（Android / iPhone / iPad / 鸿蒙 / MIUI），iPadOS 13+ 伪装成 Mac 时退回「触点数 >1 + 粗指针 + 短边 ≤820」。之前的写法「有触摸 + 短边小」会把小窗口的桌面浏览器误判成手机。
- 手机上：**关 MSAA**、像素比封顶 **1.5**、阴影图 **1024** + **硬 PCF**。桌面维持 2 倍像素比 + MSAA + 2048 PCFSoft。
- **自适应分辨率**：按帧间隔统计（每 24 帧一次），平均慢于 43 FPS 就降 0.08（很慢则 0.16），稳定 56 FPS 以上攒够 4 次才升；下限 0.62，每次调整后锁 0.9 秒。开局 1.5 秒不动（那几帧在做着色器编译）。降过的档位记 12 秒不再回爬，避免两档之间来回闪。
- 开火时不再 `scene.updateMatrixWorld(true)`（整场景遍历）；靶子是静止的，用上一帧的矩阵就够。
- 回归：`D:/temp/w01_v130.mjs` 14 条断言（手机 / 桌面各跑一遍全 PASS）、`w01_adapt.mjs` 4 条（软渲染压力下自动降到 0.62 并稳定、0 次抖动）。

### B. 手枪

按成熟 FPS 的做法逐项补，不再是「三个盒子 + 一个锥形闪光」：

- **模型 18 个部件**：滑套（带两道顶部斜切）、抛壳口、4 条防滑纹、照门两片 + 准星、枪管端面 + 枪口孔、套筒座、导轨、分解杆、扳机护圈（前立柱 + 底横梁，是真的围出一个圈）、扳机、握把 + 4 条握把纹、弹匣体 + 底板。两把枪共用同一批 geometry（`GCACHE`）。
- **材质分两段**：滑套中灰钢、握把深色聚合物。原来的全黑在这个白色世界里会糊成一个剪影，看不出是枪。
- **后坐力改成欠阻尼弹簧**：开火灌一个初速度，先猛退、过冲一点再收住。枪身位移 / 俯仰 / 横摆三条曲线，第三人称和第一人称共用参数；相机同时给一下 `camKickT` 微沉。
- **滑套循环**：开火后滑套后座 28mm 再回位（85ms），换弹上匣后自动拉一次。这是手枪"有质感"的关键帧，之前完全没有。
- **散布**：基础 0.0032 + 移动 + 空中 + 连射累积，停火按指数衰减。射线方向在锥内按 `sqrt(random)` 取极坐标（均匀分布，不然子弹会往中心挤）。
- **准星重做**：`+` 字符换成四段短线 + 中心点，间距由当前散布驱动（3–29px），命中变金色、空仓变红。只改 `transform`，不触发重排。
- **特效池**（预建复用，不在开火瞬间 new）：抛壳（重力 + 落地反弹一次 + 静止）、曳光、弹孔贴片（法线按 2.5D 碰撞体三个面里最近的那个取）、枪口烟、枪口火光。
- **火光不能用叠加混合**：这个世界底色是白的，`AdditiveBlending` 在白底上等于没画——第一版就是这样，截图里完全看不见。改成普通混合的橙色，形状用「一片正对镜头的方片 + 一个前向锥体」，长条面片在透视下会拉成横贯半屏的丝带。
- **换弹四段**：抬枪 → 下沉 → 退匣（弹匣整体掉出握把 85mm）→ 上匣 → 回位，1.35s，72% 进度补弹，期间不能开枪。
- **空仓**：干击顿挫 + 准星变红 + HUD「空仓 · 按换弹」，不再是静默失败。
- 弹匣 8→12 发、备弹 72，开火间隔 0.22→0.14s。
- 修了一个老 bug：靶子自己也是碰撞体，射线先撞到它自己的碰撞盒，浮点误差让「打中靶子」退化成「打中场景」。现在按 `kind === 'target'` 排除，靶子交给 mesh 射线判。
- 新诊断：`__world.fx`（特效池）、`__world.mobile`、`__world.renderScale`、`__world.dprCap`。

**限制**：没有音效（`window.__SFX` 是空的，脚步那套也只是占位）；第三人称的枪挂在手骨上、朝向跟相机，角色垂手站立时枪口正对镜头，只看到端面——这是挂点和姿势的问题，不是模型问题，要真正好看得等「持枪待机姿势」这类动作素材。

## v0.11.36 — 2026-11-13

**修掉帧：房子的小构件全部合并成 InstancedMesh，每帧 draw call 190 → 62**

用户报「走路都掉帧」，问是不是没带耳机、用外放导致的。**不是**：脚步音效每帧不做事，只在动画脚触地事件里播一声（走约 2–3 次/秒），WebAudio 走的是预解码的 `AudioBufferSourceNode`；万一被浏览器拦了，备用链路也只是复用池里已创建的 `<audio>` 元素，不新建节点。耳机/外放只影响输出设备，不影响渲染线程。

真正的原因用 WebGL draw call 计数查出来了：

| 版本 | 每帧 draw call |
|---|---|
| v0.11.33（没房子） | **39** |
| v0.11.34 / 35（房子） | **190** |
| v0.11.36（本版） | **62** |

v0.11.34 建房子时，栅栏柱、横板、门廊、烟囱、树干、门窗面片等约 95 个小方块全用 `new THREE.Mesh()` 单独建，而且全部 `castShadow = true`。每个独立 Mesh 主画面一次、**2048² 阴影贴图再一次**，等于平白多出 151 次提交；手机上阴影相机每帧跟着角色重画，走路时最明显。

改法（外观完全不变）：

- 只有**遮挡射线要按对象换材质、或要挂 `userData.trim`** 的网格保留独立：主屋墙、车库墙、两片屋顶、四块树冠、门窗面片。
- 栅栏（约 70 根柱 + 12 条横板）、门廊平台/雨棚/柱、烟囱、树干、灌木 → 全部走一个 `InstancedMesh(unitBox, propMat)`，**1 次 draw call（阴影再 1 次）**。
- 车库卷帘门的四条横槽合成另一个小 `InstancedMesh`，整体作为一个 `trim` 挂到车库墙上，遮罩时一起 `visible = false`。
- 门窗这类贴墙薄面片关掉 `castShadow`：背后就是墙，投影看不见，纯浪费。
- 碰撞体原本要造一个"只登记不渲染"的 Mesh，现在只传 `{position, rotation}` 字面量（`addCollider` 只读这两个字段）。

|---|---|
| 外观 | 正面/侧面/俯视截图与改动前一致，栅栏、门廊、窗、车库门、树都在 |
| 碰撞 | 撞主屋 z=−16.04 且站上门廊 y=0.3；撞栅栏 z=−8.54；车道进院到 z=−12.35 |
| 遮罩 | 主屋 5 个 trim 全隐藏；车库 2 个 trim（含 InstancedMesh）全隐藏；走开材质与可见性全还原 |

## v0.11.26 — 2026-11-13

**贴墙摩擦：正面撞墙站住，不再被"送"到方块边缘**

用户报：「撞到方块不松开前进，角色会朝方块边缘走，一直走到没有墙再往前走。」实测确认不是 bug——法向速度清零、切向原样保留，就是标准的贴墙滑。问题在于方块是随机旋转的，"撞正"几乎不发生，于是每次都被慢慢蹭走。

改法：贴墙时按 **压墙力度** 给切向速度加摩擦。

```
press = −(目标速度 · 墙法线)            你有多想往墙里钻
切向速度每秒衰减 WALL_FRIC × press      WALL_FRIC = 3.5
```

- `press` 必须取**目标速度**（`tx,tz`），不能取本帧的速度投影：法向分量上一帧就被清过，只剩一帧重新加速的那点量，按它算摩擦等于没有（第一版就栽在这，改完数据几乎没变）。
- 只在 `onGround` 时生效，空中蹭墙不减速。

实测（4×4 m 墙，按住前进 1.6 s + 再按 0.8 s 看还会不会继续挪）：

| 撞墙角度 | 1.6 s 横移 | 再按 0.8 s 又挪 |
|---|---|---|
| 0° | 0.00 m | 0.00 m |
| 5° | 0.17 m | 0.01 m |
| 10° | 0.35 m | 0.02 m |
| 20° | 0.76 m | 0.05 m |
| 30° | 1.31 m | 0.07 m（基本顶住） |
| 45° | 5.20 m | 2.54 m（照常滑） |
| 75° | 7.06 m | 3.48 m（≈ 满速 4.4 m/s） |

也就是：**30° 以内撞墙就是墙，45° 以上还是坡**。拐角仍会顺着力矩抹过去，暂时没动。

两个 `blend` 量（`godBlend` / `fpBlend`）各自平滑，相机位置按 `fpBlend` 在"轨道位置"与"眼睛位置"之间插值——`fpBlend = 0` 时逐字等于原来的第三人称，所以老视角没有回归风险。

### 2. 上帝视角的遮挡遮罩
相机抬高后被积木/高塔挡住时，**不把相机拉近**（拉近就没俯瞰感了），而是把角色与相机之间的所有遮挡物换成半透明材质（`opacity = 0.26 × godBlend`，`depthWrite = false`），角色始终看得见。退出上帝视角时材质换回 `propMat`。

这个遮罩只在上帝视角里生效——一开始没加判断，第三人称下射线扫到的积木也会被换成透明，方块凭空消失。

### 3. 第一人称
- 身体跟随视线（`faceTarget = camYaw + π`），否则按前进会横着走（移动本身早就是相机相对的，这里只是让身体也转过来）。
- `fpBlend > 0.45` 时隐藏自身网格，避免看到头部内部；提前到 0.45 是因为 0.7 时相机已经在体内穿模。
- 上下看用独立的 `fpPitch`（±66°），不动 `camPitch`，切回第三人称时俯角还是原来那个。

### 4. 修自己造的回归：相机不跟人
重构相机段时把 `follow` 的平滑跟随（以及 `camKickT/camKickV` 的衰减）整段删掉了，结果相机永远盯着原点——角色跑出十几米就看不见人。测试脚本一比对相机坐标与角色坐标才暴露。

教训：**重写一段代码时先看被替换掉的旧段有哪些副作用，不能只看新段要达成什么。**

## v0.11.13 — 2026-11-13

**继续修持续跳跃掉帧（30 多帧 + 卡顿）**

v0.11.12 之后仍会"一直跳就掉到三十多、卡顿"。两个残留漏洞都指向"持续跳跃 = 持续累积"：

### 1. 备用音频链路没有早退
v0.11.11 的早退条件只认 WebAudio 正常。而**这台手机的 WebAudio 一直被拦，实际走的是 `<audio>` 备用链路**（`_wavOk`）——早退条件不成立，所以每次轻点的 5 个手势事件仍在跑完整解锁路径（resume、播空 buffer、安排 `setTimeout` 检查），一直跳就一直堆积。补上 `_wavOk` 早退。

### 2. 每次切动画都重建 64 个四元数
`setAnim` 里清空 `_poseCur` / `_posePrev` 两个字典，下一次采样再重建——一跳有 4 次动画切换（起跳→下落→落地→跑步），等于 256 个临时对象变垃圾。持续跳跃就是持续 GC 尖峰，这就是"卡顿"的手感来源。

改成字典永不清空、对象只创建一次；`driveAnim` 按当前动画声明的骨集合判断归属（残留骨不参与）。

**验证**：状态序列正常（jumpWalk → fall → landHeavy → idle）；内存对照——静止 10s +131KB、连跳 12 次 −947KB（GC 正常回收，无泄漏）；音频两链路、脚步事件（3s 9 步）全过。

## v0.11.12 — 2026-11-13

**动画采样降频：减轻跳跃混合期的手机掉帧（v0.11.11 后残余）**

v0.11.11 修掉了音频手势开销，掉帧从"十几帧"好转到"40 多"，但跳跃时仍掉。剩余瓶颈：**跳跃全程都在动画混合状态**（起跳→下落→落地→跑步四次切换），混合时每渲染帧要采 4 次全骨架姿态（68 骨 slerp ×2 套 ×2 次）——而物理循环 1/120 意味着 60fps 手机每渲染帧要跑 2 次 update，采样和写骨全部翻倍。走路大部分时间不混合所以没事，跳跃全程混合就暴露了。

- 从后台切回 / 状态挂起时不受影响，解锁路径完整保留

- 编码成 16bit PCM，`URL.createObjectURL` 交给 `<audio>` 元素播放
- 每种声音渲染 3 个变体轮换，避免机械重复
- WebAudio 一旦不是 `running`，所有发声自动走 `<audio>`；第一次真手势里会先静音播一次把元素解锁
- 渲染是纯代码合成，没有引入任何音频文件

两条链路互不影响：WebAudio 正常时用它（延迟低、可精确调度），被拦就自动切 `<audio>`。

### 二、跳跃那只手

查了动画数据：`JumpRun_LF/RF` 里反侧手确实会摆到 **197cm**（头顶 164cm，高出 33cm）。这是 ALS 原版就有的动作，不是烘焙错了——跑动起跳靠大幅摆臂带冲量。

问题在于我们把起跳片段切在手臂最高点（t≈0.32s，就是它举到顶的时候），然后用 0.18s 切到下落姿势，手臂像被拽下来。这版把"起跳 → 下落"的混合时间单独拉长到 **0.30s**，让它有个收回来的过程。

### 三、验证

`__forceWav()` 强制挂起 WebAudio 后：9 个 `<audio>` 元素 `readyState=4`，`play()` 返回成功；WebAudio 正常时跑动峰值 0.62。

## v0.11.2 — 2026-11-13

**手机上提示「声音被挡住了」——找到真正的原因了**

`AudioContext` 是在**非用户手势**的上下文里创建的：`update()` 的兜底解锁在页面第一帧就把上下文建了出来。Chrome 允许事后 `resume()`，但 iOS Safari（以及多数 webview）对"不是在手势里创建的实例"经常永远起不来，`resume()` 返回成功、状态却一直是 `suspended`。

### 改了什么

- **上下文只允许在手势里创建**。`audioReady()` 和 `update()` 的兜底都不再新建实例，只对已存在的实例 `resume()`
- 如果检测到手里的实例是"非手势创建的"，第一次真手势时直接关掉重建
- 连续两轮手势仍不 `running` 也重建一次（有些 webview 的首个实例是坏的）
- 手势监听覆盖 `pointerdown / pointerup / mousedown / touchstart / touchend / click / keydown`，另加 `visibilitychange`（从后台切回来要重新 resume）和 `WeixinJSBridgeReady`
- 提示条会显示实际的上下文状态，例如「🔇 声音被挡住了（suspended）· 点这里再试」，方便判断卡在哪一层

### 验证

手势前 `__audioState().state === 'none'`（不再提前建上下文），模拟触摸后立刻变 `running`，跑动峰值 0.64。

**手机上仍然没声音 / 落地仍然滑 —— 再修一轮**

| 落地情形 | 处理 |
|---|---|


### 曲线解析踩的四个坑（都已修）

1. **Properties70 的 P 节点**：格式是 `[名字, 类型, 标签, 标志, 值×3]`，值要取末尾 3 个数值；
2. **属性名带空格**：FBX 里是 `Lcl Rotation` 不是 `LclRotation`；
3. **rest 姿态只在部分文件里**：`ALS_N_Pose.fbx` 不写绑定姿态，rest 必须从 `ALS_N_Walk_F.fbx` 读；
4. **欧拉顺序**：FBX `eEulerXYZ` 对应 `Rz·Ry·Rx`（X 先施加），写成 `Rx·Ry·Rz` 会让 pelvis 扭 40°、角色躺倒。

### 关键公式

我们的骨架组挂在「rest 世界朝向」的组里，而 FBX 的局部旋转增量表达在父骨 rest 坐标系内，必须用父骨 rest 世界旋转共轭：

```
Q(bone) = W_rest(parent) · (R_anim_local · R_rest_local⁻¹) · W_rest(parent)⁻¹
```

再整体转到 Three 坐标系：`q' = m ⊗ q ⊗ m⁻¹`，`m` = Rx(−90°)。

### 运行时

- 状态机：idle / walk / run / jump / fall / land，落地是一次性动画（播完才回到状态机）
- 切换混合 0.18s（四元数 slerp）
- 播放速率 = 实际速度 / 动画原生步速（walk 1.7、run 3.75、sprint 6.5 m/s，先拍的估值，等体验后调）
